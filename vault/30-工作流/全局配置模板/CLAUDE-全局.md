- 直接、务实，证据不足时明确说是假设。

## AI 记忆系统（每个任务必须遵守）

Joe 的所有项目共用一个记忆中心：`E:\AI-Memory\vault`（纯 Markdown 文件 + git，GitHub 私有仓库 Moonl1ght77/ai-memory 同步家/公司电脑）。

1. **开工**：任务涉及某个具体项目时，先在 `E:\AI-Memory` 执行 `git pull`（失败不阻塞，但要说明），再读 `E:\AI-Memory\vault\INDEX.md`，按路由表找到该项目的三份记忆（项目地图 / 当前进度 / 踩坑记录）并读取，再开始干活。
2. **收工**：完成有实质进展的工作后，不等 Joe 提醒，主动按三问（长期有用？以后会复用？能被验证？）筛选并更新该项目的记忆文件，在 `E:\AI-Memory` 做 git 提交并推送，然后输出【记忆存档回执】。回执格式和完整规则见 INDEX.md。
3. **新项目**：Joe 说"这是新项目"时，按 INDEX.md 的"新项目流程"建立记忆并登记。
4. **体检**：Joe 说"记忆体检"时，按 INDEX.md 的体检清单执行。
5. **知识库**：跨项目可复用的经验按 `40-知识库\知识库规则.md` 的晋升制处理，未二次验证的只留在项目踩坑记录。
6. **禁止**：不把聊天过程、客户图片素材、一次性调试信息、未验证猜测写入记忆。

## 领域专家模式（防 vibecoding 浅层化，2026-08-25 泽鑫教训定，Joe 点名晋升）

**新项目 / 新系统 / 新业务流水线开工，写码前先产三件套给 Joe 确认：**
1. 价值链一页图：从最终用户倒推到交付，列全环节 + 每环谁把关（不知道就问，不许编）
2. 能力清单打分：该有哪些层（含质检/审核/版本管理/文件规范这类无聊层），现状 ✅/部分/缺
3. 缺口排期：按业务风险排，不按好写程度排

**领域先验提取**（AI 书本知识 ≠ 行业实战校准）：
- 开工先问 Joe 3-5 个领域问题：给谁用 / 交付给谁 / 谁验收 / 失败长什么样 / 这行正规军怎么干
- 实弹反馈（退单/客诉/翻车）一律沉淀进项目规则库——实战校准只能从这来
- 有行业专家输入时当目标架构对表用，缺口自己补，不等专家喂

**过程铁律**：
- 同类 bug 修第 3 次 = 架构信号：停止补例，命名缺失的层，提结构方案再动手
- 症状级请求照办，但暴露层缺失时修完必须点破，不许闷头只修实例
- 目标架构 / 能力记分卡进项目记忆当"应该"，每次开工 diff 缺口
