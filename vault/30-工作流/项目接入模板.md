# 项目接入模板

新项目接入记忆系统时，在项目文件夹根目录创建以下文件：CLAUDE.md、AGENTS.md（内容相同，分别给 Claude Code 和 Codex 自动读取），以及 CONTEXT.md（项目词典，见下）。

## CLAUDE.md 模板

```markdown
# CLAUDE.md —— 【项目名】

## 记忆（每次必做）
- 本项目记忆：`E:\AI-Memory\vault\20-项目记忆\【类目】\【项目名】\`
- 开工先读三份记忆：项目地图.md、当前进度.md、踩坑记录.md
- 本项目词典：根目录 `CONTEXT.md`，开工一并读，术语以它为准
- 收工按三问（长期有用/会复用/能验证）主动更新记忆，并输出【记忆存档回执】
- 完整规则见 `E:\AI-Memory\vault\INDEX.md`

## 项目要点
-（一句话定位）
-（关键禁区，如有）
```

## AGENTS.md 模板

内容与 CLAUDE.md 相同（如项目已有 AGENTS.md，只把"记忆"一节追加到文件末尾，不要覆盖已有规则）。

## CONTEXT.md —— 项目词典（2026-08-05 定）

**放项目文件夹根目录，不放 vault。** 词典必须跟着代码走：任何人、任何 AI、任何一台电脑打开这个项目，第一眼就该看到这里的词是什么意思，不该还要去翻记忆库。

### 分工（别搞混）

| 文件 | 位置 | 管什么 |
|---|---|---|
| `CONTEXT.md` | 项目根目录 | 这个项目里**每个词是什么意思** |
| `当前进度.md` | vault | **做到哪了**、下一步、阻塞点 |
| `踩坑记录.md` | vault | 什么方案**试过不行** |

### 规矩

- **懒建**：不预先创建空文件。第一次出现"这个词到底指什么"的分歧时才建，有一条写一条
- **只放词，不放实现**：CONTEXT.md 是词典，不是需求文档、不是设计稿、不是草稿纸。写"商品卡片指什么"，不写"商品卡片用什么组件实现"
- **随时更新**：术语当场敲定当场写进去，不要攒着批量补
- Joe 说了某个词，和 CONTEXT.md 里已有定义冲突时，**当场指出来问清楚**，不要自己猜

### 格式（照抄结构，不抄内容）

```markdown
# 【项目名】词典

## 术语

**商品卡片**
商店列表页里每个商品占的那一块（图 + 名 + 价）。详情页那个大的叫**商品主图区**，不是这个。
_避免使用_: 产品卡、item card

**分类**
后台设置的商品归类，一个商品只属于一个分类。
_避免使用_: 品类、类目

## 关系
- 一个**分类**下有多个**商品**
- 一个**商品**在列表页表现为一个**商品卡片**

## 曾经混淆过
- "分类"以前同时指后台分类和前台筛选标签 —— 已定：后台的叫**分类**，前台可多选的叫**筛选标签**
```

最后那节"曾经混淆过"最值钱：记住的不只是结论，还有为什么定成这样，防止过几个月又绕回去。
