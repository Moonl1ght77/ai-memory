## 二、AI 工作规则

### 开工（每次任务开始）
1. 先在 `E:\AI-Memory` 执行 `git pull`，同步另一台电脑的最新记忆（失败不阻塞干活，但要在回复里说明没同步成功）。
2. 判断任务属于哪个项目，读取该项目三份记忆；**项目根目录有 `CONTEXT.md`（项目词典）就一并读，术语以它为准**；涉及打法选择时顺带看一眼对应的 `40-知识库\<类目>.md`。**新项目/新系统开工另加读跨类目的 `40-知识库\AI协作打法.md`（领域专家模式）**。
3. 扫一眼 `30-工作流\已安装工具清单.md`：本次任务用得上里面的工具/命令时，主动提醒 Joe（他经常忘记装过什么），用不上就不提。**Joe 不懂英语、看不懂技能的英文描述**，提工具时一律报中文说明，对照 `30-工作流\中文命令速查表.md`。
4. 只补读当前任务需要的文件；不扫描无关项目、不读客户图片素材。
5. 开工前用一两句话说明：读了哪些记忆、本次任务边界。
6. **时效性优先于记忆（2026-09-07 Joe 定，Claude 与 Codex 都适用）**：训练数据有截止日期，当前真实日期在系统提示里，**两者之间的一切我一概不知道**。开工先算盲区跨度（当前日期 − 知识截止）。凡涉及**模型/产品发布与版本、价格额度、API 接口形状、库与框架版本、行业动态与竞品、任何带「最新/现在/目前/已经」的问法** —— 一律先搜再答，带来源和日期；搜不到就说搜不到，不许拿旧知识补位。要写出「据我所知」「我的知识截止」时，那是**必须去搜的触发器**，不是免责声明。

### 收工（每次有实质进展的任务结束）
不等 Joe 提醒，主动执行。**Joe 发出验收信号（"ok"/"可以"/"过了"等）即视为该任务收尾，回执立刻跟上，不等追问**（2026-07-19 Joe 定）：
1. 按三问筛选本次内容：**长期有用吗？以后会复用吗？能被验证吗？** 三个都是"是"才写入。
2. 更新对应项目的记忆文件；"当前进度.md"必须刷新"最后更新"日期。**顺手看一眼文件体积：当前进度或踩坑记录超过约 10KB 就按上面的归档规则搬历史归档**（这一步过去没有触发点，规则形同虚设，2026-08-09 体检定为收工必查项）。
3. 检查是否有经验满足知识库晋升条件（见 `40-知识库\知识库规则.md`，核心是"第二次被验证"），满足才晋升，否则只留在项目踩坑记录。
4. 在 `E:\AI-Memory` 执行 git 提交并 `git push`，提交信息写清楚更新了什么。
5. 输出【记忆存档回执】（固定格式见下）。
6. **写记忆文件只用 Write / Edit 工具，不经过解释反斜杠的层**（Python / JS 普通字符串、`echo -e`、`printf`、heredoc 拼 sed 都不行）：Windows 路径里的 `\n` `\t` `\0` `\03` `\202` 会被当转义符，路径断行、多出制表符、混进控制字符和乱码（英维尔 08-30、印花归档 09-07、agent全自动生图 09-15～16 三次实锤，公司机 09-16 一次修 6 个文件）。写完 grep 一遍行首路径尾巴、制表符、控制字符再提交。做法细节见 `40-知识库\AI协作打法.md`。
7. **代码分支收工时顺手推到远端（2026-09-18 Joe 定）**：任务分支哪怕没合、没审、没上线，也 `git push -u origin <分支>` 一次，私有仓推未合并分支不碰 main 也不碰线上。起因：织花云 `claude/library-thumbs-paging` 两轮 26 文件只在家用机硬盘上，人到公司机想接手，GitHub 没有、这台没有、家用机关着，只能等回家。回执里「未推」不再是可接受的收工状态，写清「已推 origin/<分支>」。
