## 二、AI 工作规则

### 开工（每次任务开始）
1. 先在 `E:\AI-Memory` 执行 `git pull`，同步另一台电脑的最新记忆（失败不阻塞干活，但要在回复里说明没同步成功）。
2. 判断任务属于哪个项目，读取该项目三份记忆；涉及打法选择时顺带看一眼对应的 `40-知识库\<类目>.md`。
3. 只补读当前任务需要的文件；不扫描无关项目、不读客户图片素材。
4. 开工前用一两句话说明：读了哪些记忆、本次任务边界。

### 收工（每次有实质进展的任务结束）
不等 Joe 提醒，主动执行：
1. 按三问筛选本次内容：**长期有用吗？以后会复用吗？能被验证吗？** 三个都是"是"才写入。
2. 更新对应项目的记忆文件；"当前进度.md"必须刷新"最后更新"日期。
3. 检查是否有经验满足知识库晋升条件（见 `40-知识库\知识库规则.md`，核心是"第二次被验证"），满足才晋升，否则只留在项目踩坑记录。
4. 在 `E:\AI-Memory` 执行 git 提交并 `git push`，提交信息写清楚更新了什么。
5. 输出【记忆存档回执】（固定格式见下）。

### 记忆存档回执（固定格式）
```
【记忆存档回执】
- 项目：XXX
- 更新文件：当前进度.md、踩坑记录.md
- 写入要点：① …… ② ……
- 知识库：无晋升（或：××晋升到 40-知识库\类目.md）
- 未写入：××（一次性内容，不符合三问）
- git 提交+推送：已完成（或失败原因）
```
如果本轮没有值得存的内容，输出【本轮无需存档】加一句原因。

### 新项目流程（Joe 说"这是新项目"时）
1. 问清：项目名、所属类目（微信小程序 / 独立站 / 电商作图 / 其他，可新增类目）、项目文件夹位置。
2. 项目还没有文件夹时，按 `30-工作流\电脑文件夹规则.md` 建：代码类 → `E:\Projects\项目名`；纯素材类客户单 → `E:\Studio-Assets\客户名\项目名`。
3. 复制 `30-工作流\三文件模板` 到 `20-项目记忆\<类目>\<项目名>\`，改名为 项目地图.md / 当前进度.md / 踩坑记录.md 并填写。
4. 在本文件路由表加一行。
5. 在项目文件夹里创建 CLAUDE.md 和 AGENTS.md，写法照抄 `30-工作流\项目接入模板.md`。

### 收拾电脑（Joe 说"帮我收拾电脑"时执行）
按 `30-工作流\电脑文件夹规则.md` 第四节执行：只读盘点桌面 / `E:\00-收件箱` / 下载文件夹 → 提出去向清单 → Joe 确认后才移动，删除只删确认项 → 输出收拾报告。

### 记忆体检（Joe 说"记忆体检"时执行）
1. 核对路由表和 `20-项目记忆` 实际文件夹是否一一对应。
2. 列出每个活跃项目"当前进度"的最后更新日期，超过 30 天的提醒 Joe 核实。
3. 抽查记忆内容：有没有写串项目、有没有堆聊天记录、有没有未验证的猜测没标注。
4. 检查 `E:\AI-Memory` 的 git log 是否正常记录，且已推送到 GitHub（本地和远程一致）。
5. 修剪知识库：按 `40-知识库\知识库规则.md` 逐条检查，出处失效/被取代/一年没用的条目报给 Joe 确认后删除。
6. 用一张表输出体检结果，先说结论。

### 路线图对表（Joe 说"路线图对表"时执行）
1. 读 `50-路线图\变现路线图.md` 和各活跃项目的"当前进度"。
2. 输出：当前阶段、该阶段勾选项完成情况、距离"进入下一阶段的信号"差什么、下一步最重要的三件事（具体到项目）。
3. 根据真实反馈提出路线图修订建议，Joe 确认后更新文档（对表结果本身不写入，只更新路线图勾选项）。

### 禁止写入记忆
- 完整聊天过程、一次性调试细节
- 客户图片和素材文件（记忆只记它们放在哪）
- 未验证的猜测（要写必须标注"假设"）
- 情绪化评价
