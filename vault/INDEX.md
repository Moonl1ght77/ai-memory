## 二、AI 工作规则

### 开工（每次任务开始）
1. 先在 `E:\AI-Memory` 执行 `git pull`，同步另一台电脑的最新记忆（失败不阻塞干活，但要在回复里说明没同步成功）。
2. 判断任务属于哪个项目，读取该项目三份记忆；项目根目录有 `CONTEXT.md`（项目词典）且本次涉及术语时读取相关条目，以其定义为准。涉及打法选择时读取对应的 `40-知识库\<类目>.md`；新项目、新系统或新业务流水线另读 `40-知识库\AI协作打法.md`（领域专家模式）。
3. 本次需要选择、核对或提醒工具时，读取 `30-工作流\已安装工具清单.md` 的相关段落，主动提醒 Joe 已装且用得上的工具。提工具用中文说明，必要时对照 `30-工作流\中文命令速查表.md`，不通读与任务无关的工具条目。
4. 只补读当前任务需要的文件；不扫描无关项目、不读客户图片素材。
5. 开工前用一两句话说明：读了哪些记忆、本次任务边界。
6. **核验事实**：模型/产品发布、价格额度、API、库与框架用法、行业动态及竞品等易变事实，先查当前可靠来源，注明必要来源与日期；查不到明确说明。关键数字、人物和结论用可靠来源或本地证据核验；区分事实、推测和观点。

### 收工（每次有实质进展的任务结束）
不等 Joe 提醒，主动执行。**Joe 发出验收信号（"ok"/"可以"/"过了"等）即视为该任务收尾，回执立刻跟上，不等追问**（2026-07-19 Joe 定）：
1. 按三问筛选本次内容：**长期有用吗？以后会复用吗？能被验证吗？** 三个都是"是"才写入。
2. 仅有通过三问的新事实或状态变化时，更新对应记忆及「最后更新」日期。只检查本次修改的文件：超过约 10KB 时逐条核对归档条件；有效规则和活跃风险保留，拿不准不搬。
3. 检查是否有经验满足知识库晋升条件（见 `40-知识库\知识库规则.md`，核心是"第二次被验证"），满足才晋升，否则只留在项目踩坑记录。
4. 有实际文件差异时，在 `E:\AI-Memory` 执行 git 提交并 `git push`，提交信息写清楚更新了什么。
5. 输出【记忆存档回执】（固定格式见下）。
6. 优先使用当前环境的直接文件编辑工具（如 Write / Edit、apply_patch）。Windows 路径不得经过会解释反斜杠的字符串层；确需脚本时用原始字符串等可靠方式，写后检查路径、制表符和控制字符再提交。已验证的故障及做法见 `40-知识库\AI协作打法.md`。
7. **代码分支收工时顺手推到远端（2026-09-18 Joe 定）**：任务分支哪怕没合、没审、没上线，也 `git push -u origin <分支>` 一次，私有仓推未合并分支不碰 main 也不碰线上。起因：织花云 `claude/library-thumbs-paging` 两轮 26 文件只在家用机硬盘上，人到公司机想接手，GitHub 没有、这台没有、家用机关着，只能等回家。回执里「未推」不再是可接受的收工状态，写清「已推 origin/<分支>」。

### 新项目流程（Joe 说"这是新项目"时）
1. 问清：项目名、所属类目（微信小程序 / 独立站 / 电商作图 / 其他，可新增类目）、项目文件夹位置。
2. 项目还没有文件夹时，按 `30-工作流\电脑文件夹规则.md` 建：代码类 → `E:\Projects\项目名`；纯素材类客户单 → `E:\Studio-Assets\客户名\项目名`。

4. 在本文件路由表加一行。
5. 在项目文件夹里创建 CLAUDE.md 和 AGENTS.md，写法照抄 `30-工作流\项目接入模板.md`。
6. `CONTEXT.md`（项目词典）**不预建**，第一次出现术语分歧时才在项目根目录建，格式见 `30-工作流\项目接入模板.md`。它归项目不归 vault，理由和规矩都写在那个模板里。
