# 耶稣陶瓷灯独立站 · 踩坑记录

## 已确认问题
- 2026-11-13：tympanus.net（Codrops 文章与 Hub）对 WebFetch 返回 403，需用内置浏览器 get_page_text 读取；seekhimfirst.com 产品页对抓取返回 429。

- 2026-11-15：**jsDelivr 的 `three.*.min.js` 会装出两份 TSL**（three 0.187）：npm 包里没有 min 文件，jsDelivr 现压的 `three.webgpu.min.js` 内部仍引用未压缩的 `./three.tsl.js`，importmap 再把 `three/tsl` 指到 `three.tsl.min.js` 就是两个模块实例，报 `No stack defined for assign operation` + 栈溢出。CDN 直引用包里原有的 `three.webgpu.js` / `three.tsl.js`；正式主题用 Vite 打包没这个问题。
- 2026-11-15：**浏览器解 PNG 只给 8 位**，16 位深度图直接当纹理会丢精度。运行时把 16 位拆成 R 高字节 + G 低字节的 8 位 PNG，JS 里 `getImageData` 还原成半浮点 `DataTexture`（`prototype/relight.js`）。Shopify CDN 会不会把这张 PNG 转有损 WebP 未核，进主题时要验。
- 2026-11-15：**B2 白底图只有荆棘冠两态同机位**（外框差 ≤ 3 px），圣心、升天的不亮/点亮是分别生成的，机位和大小不同，叠不上；拖动对比和点灯短片只能用荆棘冠。以后要成对的图（如 B1 商品卡），点亮版必须以不亮版定稿为底图只改光。
- 2026-11-15：Claude 内置浏览器面板不在前台时 rAF 被限到约 1 帧/秒，WebGL/WebGPU 画布截图是旧帧。调着色器用「渲染后同一任务里 `canvas.toDataURL()` 贴成 `<img>` 再截图」取确定性画面；帧率不能在这里测。
- 2026-11-15：首屏底图石像占满图高，`object-fit: cover` 在比 16:9 更宽的屏上会裁掉头脚；改成永远按高度适配、图外补黑（底图背景本来就是黑的）。

- 2026-11-20：Claude 内置浏览器面板隐藏时 rAF 完全不跑、`scrollTo` 不生效，滚动动效没法在面板里验。改用本机无头 Playwright：`uv run --with playwright`，`chromium.launch(executable_path=...ms-playwright/chromium-1248/chrome-win64/chrome.exe)`（pip 版 playwright 要的浏览器版本对不上，直接指现有的），桌面 + 手机视口按滚动进度逐段截图。
- 2026-11-20：`python -m http.server` 一下收 100 多个并发图片请求偶尔 `ERR_CONNECTION_REFUSED`，是本地开发服务器的问题，CDN 不会。
- 2026-11-20：黑底实拍帧叠在网页上，别用几何窗口渐隐（视频黑比页面底色暗，会露暗方框、切断光晕），也别混成某个底色；按模糊后亮度抠 alpha、RGB 反预乘（除数下限 0.1 防放大底噪）。WebP alpha_quality 要 100（无损）：70 会把光晕压出等高线，85 反而比 100 还大。
- 2026-11-20：**`shopify theme init` 现在拉的是积木式 Skeleton**（2026-10-01 起：纯 Liquid 模板、无 sections/JSON 模板，应用区块插不进，`{% partial %}` 未开功能的店会报 Unknown tag）。要 sections 版就 `git clone Shopify/skeleton-theme` 后取 `a4f32d3`（2026-02 最后一版 sections）。
- 2026-11-20：Liquid 里 `alt: x.alt | default: y` 写在 `image_tag` 参数里时，`default` 作用在整个标签输出上而不是 alt；先 `assign alt = ...` 再传。Liquid 也没有 `ternary` 过滤器。theme check 都查不出。
- 2026-11-21：**本机 `python -m http.server` 把 .webp 当 `application/octet-stream` 发**（Windows 注册表没 webp 类型）：Joe 电脑装了 IDM，它注入所有 chrome.exe（含 Playwright 的无头浏览器），每张图弹一个「下载文件信息」框，一次截图弹了几十个；带 `?v=` 查询串时 Chrome 还直接不解码。本地预览一律用 `tools/serve.py`（显式 MIME），跑大量图片的无头截图前先小样探一次。
- 2026-11-21：本机 npm 默认源是 npmmirror，装包常 ECONNRESET；临时加 `--registry=https://registry.npmjs.org` 能装（不改全局配置）。
- 2026-11-21：**liquidjs 的 `{% render %}` 片段只看得到 globals**，不传 `{ globals }` 时 `request`、`shop` 等在 snippet 里是空的（Shopify 里能看到），预览里 snippet 的判断全走错分支。`parseAndRender(src, scope, { globals: G })`。liquidjs 把 `t: title: x` 这类命名参数传成 `[name, value]` 数组。
- 2026-11-21：Git Bash 会把以 `/` 开头的参数改写成 Windows 路径（`/` → `D:/Git/`），给 Playwright 脚本传网址路径要加 `MSYS_NO_PATHCONV=1`。theme check：schema 名（含 locale 里的译文）最长 25 字符；snippet 里的 class 在别的文件定义会报 ValidScopedCSSClass，共用样式放 critical.css。
- 2026-11-21：liquidjs 里 `assign x = blank` 后 `x != blank` 为真（Shopify 里为假），判断用 `assign x = nil` + `if x`。CSS 自定义属性：子元素自己声明 `--p` 会盖住父元素上 JS 设的 `--p`，默认值要放在被 JS 设置的那个元素上。
- 2026-11-21：**`container-type: inline-size` 的元素在收缩包裹的位置宽度会塌成 0**（如 `justify-items: center` 的网格项）：商品卡 `.niche-card` 就是这样在手机送礼页被挤扁、快捷加购按钮飘到卡外。放卡的容器必须给定宽（`width: min(100%, 340px)`）。

- 2026-11-21：**`view-transition-name` 会让元素自成绘制层（像定位元素那样后画）**，叠放的两张图里先写的那张带了名字就会盖住后面那张；产品页点亮图因此一直不显示。叠图要显式 `position: relative; z-index`，叠在上面的按钮/浮层也要给 z-index。

- 2026-11-24 抠浅色背景前的白瓷（A7 转一圈）：BiRefNet 常丢瓷盘左缘（白盘压在淡紫转盘上），按色抠（背景 B-R≈-25、转盘 +30、瓷 0–12）丢灯罩背光一侧；两者取并集才全。灯罩和瓷盘是回转体，轮廓只随转盘偏心平移：抽十几张样本取多数得标准轮廓，偏心按一圈正弦拟合（残差 ≤2 px），每帧平移即可，不用逐帧跑模型（无显卡时每张约 16 秒）。
- 2026-11-24 两段转盘视频对角度：用整帧自相关精测一圈周期（A6 27.247 秒、A7 27.358 秒），只需一个锚点就能换算全程角度。

- 2026-11-26：**页面是近黑 #0B0A09，实拍和生图的「黑底」普遍比它亮**（摆放图 ≈8–19、石像底 ≈13–19），边缘渐隐只能把方框边变软，块还在。照片类按模糊亮度抠 alpha；整图（石像）压黑场到底色 p90 以下再 `mix-blend-mode: lighten`。`tools/fit-page-black.py`。
- 2026-11-26：给图片加载淡入时，CSS 动画的优先级高于所有普通 opacity 规则（含 `.lit` 叠层）：用 `from { opacity: 0 }`、不写 to、不加 fill，加载前 `paused` 压在首帧，load 后 running，结束移除类，叠层自己的 opacity 自然接回。只对 `loading=lazy` 且未完成的图做，否则首屏已半画出的图会闪一下。

- 2026-11-27：**Shopify CDN 会改写主题 assets 里的图片**：PNG 默认按 JPEG（无 Accept）或 WebP（浏览器）有损发出，`home-hero-depth.png` 里拆在 R/G 的 16 位深度被打乱，上线后首屏石像满是噪点（本地预览看不出）。加 `?format=png`（已有 `?v=` 就 `&format=png`）取回的像素与原图逐像素一致。WebP 也可能被重压：转盘帧等透明 webp 像素不变，`home-hero.webp` 被压到 75%（平均差 0.7、最大 16）。**凡是按数据读的图（深度图、查找表）都要带 format=png 并在 CDN 上逐像素核对**（11-15 那条「未核」已坐实）。
- 2026-11-27：Shopify 后台 Chrome 自动化：控件多在 shadow DOM，截图常超时；改值用原生 value setter + composed input/change 事件，正文用 `tinymce.activeEditor.setContent()`；上传框从外部塞文件会传两遍；批量内容先经临时 file input 读进 sessionStorage 再逐页填；元对象富文本字段自动化填不进（改用多行文本）；页面模板下拉只列在线主题的模板；菜单嵌套要用鼠标拖（键盘拖不动）。

## 失败方案
- **审不亮图只对不亮实拍会漏错**（2026-11-13 公司机）：荆棘冠右上方的浮雕在不亮 4K 实拍里像几根树枝，点亮后才看出是展翅的天使；Joe 出的不亮白底图把它画成了带叶子的树，第一轮只对照不亮帧，误判通过。规矩：审任何白底图（不亮或点亮），都要同时对照**不亮帧 + 点亮帧**，浅浮雕的内容以点亮帧为准。对照图存在项目仓 `assets\02-产品图\审图对照\`。
- **用照片做透光浮雕 3D 灯罩，两条路都过不了 Joe**（2026-11-13 公司机，Blender 5.2 后台脚本，项目仓 `tools/relief-from-lit.py`、`tools/lamp-texture-ring.py`，渲染在 `assets\05-3D\试验-点亮图反推浮雕\`）：① 点亮图当厚度图反推位移：外形和瓷盘能做像，但浮雕成斑点、脸糊——点亮图（尤其 AI 白底图）的亮暗混着光影和质感纹理，程序分不出哪些是厚度，换清楚的图也救不了；② 贴图法（点亮态直接贴图发光）：点亮清楚但像贴纸，不亮态无立体感。结论：没有 STL 就不做浮雕 3D，「转着看」用实拍视频切帧。图生 3D 工具（Hunyuan3D/Tripo/Meshy）未实测。
- **gpt-image 参考图编辑会重画浮雕**（2026-11-13 公司机，天亿马 `gpt-image-2.6-flare` `/images/edits`，quality high、1024×1024，每张约 50 秒）：拿视频帧作参考出点亮白底图，提示词明写「浮雕不得重画、移动」，三张仍把主像放大移到正中、改了脸和手、圣心从近盘沿挪到中部；元素齐全但构图不同，过不了「浮雕不得改」。结论：要求浮雕跟实物一致的图，不能让模型整图生成；同理织花云踩坑记录也记过这个接口无视 mask、整图重画。脚本在项目仓 `tools/gen-whitebg.mjs`，密钥从织花云 `.env` 以 `--env-file` 读，不落盘。

- **长响应在本端丢掉，钱照扣，别赖服务商**（2026-11-13 公司机，天亿马 gpt-image-2 + quality high + 两张参考图，单张约 ¥1.08）：5 次计费只拿到 2 张图。供应商逐条核过账单，5 行 token 数完全一致（2695–2706 入 / 7024 出），跟成功那两次一样，说明服务端每次都出了图、正常返回。丢在我们这端：客户端日志 2 次 `HTTP 200` 但 body 是空的 `{}`、1 次 `fetch failed`；成功的两次客户端耗时 236 s / 241 s，body 是约 1 MB 的 base64。即四分钟的长连接下载大 body，中途断了，状态行已经到手所以看着像 200。当时还并发跑 3 张、没存原始返回，断了查不出原因又重试，白烧两次。
  - 规避：付费前报令牌分组、画质、单张价；先跑 1 张；不并发；响应流式写盘（head / body 分开存），断了也留半截证据；Bash 工具默认 2 分钟超时，这种调用必须后台跑。
  - 教训：先查自己的传输日志再怀疑服务商。供应商原话「不存在说丢了还扣费」，核下来是对的。
- **天亿马 pool 分组 /models 列出 gpt-image-2，实际调用 503**（2026-11-13 公司机）：两枚 pool 令牌（织花云那枚、新建「生图」）都返回 `No available channel for model gpt-image-2 under group 🌏️ OpenAI Azure (distributor)`，即时返回、不出图。模型列表能看到不等于有渠道；先发 1 张探活再算成本。

- **侧身石像的手势在纯侧面看不出来**（2026-11-14 公司机，Joe 生图）：纯侧面做祝福手势，掌心朝向石像自己，画出来像挡脸或比「嘘」；写「托着衣褶」被画成手指捏袍子。双手合十也不是耶稣像的常见动作。规矩：手势要掌心朝观众的，身体至少转到四分之三侧身或接近正面；空着的手写明「不碰衣服」。最终用敞开双臂迎接（姿势另给一张参考图，提示词写明只参考姿势、不参考颜色材质）。

## 风险
- 首屏「石像捧灯」可能被部分信徒视为不敬，已在方案中列备选。

## 规避策略
- 读 Codrops 页面直接走浏览器，不用 WebFetch。
- 2026-11-22 主题 `<dialog>` 弹窗贴左上角：Skeleton 基础样式把元素 margin 清零，模态 dialog 的默认居中靠 UA 的 `margin: auto`，被清后就在 (0,0)。新写弹窗要显式 `position: fixed; inset: 0; margin: auto`。
- 2026-11-22 转着看的 122 帧（spin-000…121）不是闭合的一圈（源视频圣心→升天一段），交互上不能取模循环，否则末帧→首帧硬切；用往返映射或夹在两端。
- 2026-11-23 场景图换真灯：肉眼按网格量模型那盏灯的盘底，普遍偏高 20–40 px，真灯放上去下面露出模型瓷盘的「底座」；用亮度梯度自动找盘底在暖光桌面上也会跑偏（纪念那张挪低 67 px，露出模型灯顶）。可靠做法：在量出的位置附近用 BiRefNet（rembg birefnet-general）抠模型灯轮廓，按轮廓定宽度和盘底，再把轮廓 inpaint 掉。另：灯罩与瓷盘分两段对色时必须渐变过渡，硬切会出一条色带。
