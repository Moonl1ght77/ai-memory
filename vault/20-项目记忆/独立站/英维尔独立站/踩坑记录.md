## 风险
- （2026-08-21）`npm create astro@latest` 装出来是 Astro 7.2.4，实施计划文档里写的是"Astro 5"（版本漂移，latest 标签随时间变化）。**已验证**：计划给的 i18n 配置写法（`i18n: { defaultLocale, locales, routing: { prefixDefaultLocale } }`）在 7.2.4 下 `npm run build` 无报错，配置结构未改。后续阶段如遇到 Astro API 差异（组件语法、content collections 等），留意版本号，别默认按 v5 文档查。
- （2026-08-21）**agent 会话里的 Browser 预览面板不会真正合成帧**：`computer{action:"screenshot"}` 报 "the Browser pane is not displayed, so the page is not compositing frames"，即使 `tabs_select` 前置、`resize_window` 强制也一样。后果：GSAP ScrollTrigger 靠 `requestAnimationFrame` 驱动的动画会卡在初始帧（如 `gsap.from` 的 opacity:0 永远不推进），**不是代码问题**。验证方法：注入调试代码把 `gsap`/`ScrollTrigger` 挂到 `window`，用 `gsap.getTweensOf(el)` 读 tween 状态，手动调用 `gsap.ticker.tick()` 推进几次，看 opacity/transform 是否正常插值——插值正常就说明动画逻辑没问题，纯粹是这个环境下 rAF 没跑。后续阶段大量 GSAP 效果要验证时，直接用这个方法，别在截图上死磕。**补充（Task 2.1 二次验证）**：该环境浏览器面板 `innerWidth` 为 0，会让 `matchMedia('(max-width:768px)')` 误判为真、走进窄屏早退分支——验证桌面分支必须先补丁 matchMedia 再带 query 重载模块；scrub 动画可用 `animation.progress(0/0.5/1)` 手动推进读 DOM 验证插值。另：Astro 组件 `<script>` 会被去重打包（多实例只跑一份），写成一个脚本查全部 `[data-*]` 节点，别假设每实例各跑一份。
- （2026-08-21）**dev server 跨大量新增路由后 HMR 会噎住**：Astro dev 长跑期间子代理连续新增 pages，日志刷 `[router] Failed to update routes via HMR: TypeError: undefined is not a function`，页面路由不更新。解法：重启 dev server 即好，别去调 HMR。演示/验收前一律重启后再看。

- （2026-08-21）`scripts/import/parse.js`/`parse.test.js` 在 Shopify v1 阶段就写过一版（`rowToProductSetInput`，产出 GraphQL productSet 输入），v2 转向 Astro 静态站后阶段 3 任务直接**整个覆盖重写**成 `rowToProduct`（产出 products.json 字段）。这是预期行为，不是误删——v1 产物已随转向作废，git 历史里能找回（commit 65fca0b），没有需要迁移或兼容的地方。以后再遇到"这个文件之前写过"的情况，先看是不是转向前的旧方案遗留，别默认要保留兼容。

## 规避策略
- logo 白底转 PNG 不依赖 ImageMagick 时，可用 PowerShell + .NET `System.Drawing`（`Add-Type -AssemblyName System.Drawing` → `[System.Drawing.Image]::FromFile()` → `.Save(path, [System.Drawing.Imaging.ImageFormat]::Png)`）应急，但只是格式转换，不会抠透明背景，白底会原样保留。
