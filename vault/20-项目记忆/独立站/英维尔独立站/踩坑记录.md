# 英维尔独立站 · 踩坑记录

## 已确认问题
- （2026-08-21）本机（`E:\Projects\英维尔独立站（shopify平台）` 所在这台）未装 ImageMagick，`magick -version` 在 Bash 和 PowerShell 下都报命令不存在。抠图类任务先确认工具在不在，别假设装了。

## 失败方案

## 风险
- （2026-08-21）`npm create astro@latest` 装出来是 Astro 7.2.4，实施计划文档里写的是"Astro 5"（版本漂移，latest 标签随时间变化）。**已验证**：计划给的 i18n 配置写法（`i18n: { defaultLocale, locales, routing: { prefixDefaultLocale } }`）在 7.2.4 下 `npm run build` 无报错，配置结构未改。后续阶段如遇到 Astro API 差异（组件语法、content collections 等），留意版本号，别默认按 v5 文档查。
- （2026-08-21）**agent 会话里的 Browser 预览面板不会真正合成帧**：`computer{action:"screenshot"}` 报 "the Browser pane is not displayed, so the page is not compositing frames"，即使 `tabs_select` 前置、`resize_window` 强制也一样。后果：GSAP ScrollTrigger 靠 `requestAnimationFrame` 驱动的动画会卡在初始帧（如 `gsap.from` 的 opacity:0 永远不推进），**不是代码问题**。验证方法：注入调试代码把 `gsap`/`ScrollTrigger` 挂到 `window`，用 `gsap.getTweensOf(el)` 读 tween 状态，手动调用 `gsap.ticker.tick()` 推进几次，看 opacity/transform 是否正常插值——插值正常就说明动画逻辑没问题，纯粹是这个环境下 rAF 没跑。后续阶段大量 GSAP 效果要验证时，直接用这个方法，别在截图上死磕。

## 规避策略
- logo 白底转 PNG 不依赖 ImageMagick 时，可用 PowerShell + .NET `System.Drawing`（`Add-Type -AssemblyName System.Drawing` → `[System.Drawing.Image]::FromFile()` → `.Save(path, [System.Drawing.Imaging.ImageFormat]::Png)`）应急，但只是格式转换，不会抠透明背景，白底会原样保留。
