- （2026-08-21，Hero 流光丝带 3a6cc72）**canvas 单帧开销在这个 Browser pane 环境里量不准，别拿它当验收依据**。事实链：① 想量光栅化开销只有 `getImageData` 一条路（它强制把挂起的绘制指令真跑完），但它同时会把 canvas 从 GPU 后端降级成 CPU 后端、且每帧强制一次 GPU 同步 → 量出来是**软件光栅 + 全同步**的悲观值；② 不加 `clearRect` 连排 N 帧、最后只读一次，能避开"整屏 clearRect 让 Skia 把前面几帧当死指令丢掉"这个乐观陷阱，但仍是软件光栅数字；③ 判断这台环境是不是软件光栅：量一次全屏渐变 `fillRect` 的填充率，本环境 1280×720 要 2.7ms ≈ 293Mpx/s，GPU 光栅应该是它的几十倍。**结论**：这个环境能可信量到的只有"JS + 建路径"那半（本项目实测 0.5~0.7ms/帧，方法是 stub 掉 ctx 或 monkey-patch 掉光栅），光栅那半只能给上下界，"单帧 ≤4ms"这类红线在这里**无法验收**，要么上真机测，要么写清楚是估算。
