## 2026-09-10 凌晨 · 慢网下首屏一片空白 + 走走停停（commit d3be2dd，已推 + 部署线上）

Joe 在 **Windows Chrome/Edge** 上报「视频又不加载了」，追问后是两种现象都有：
**点进去一片空白** + **画面出来了定格不动**。CDP 限速实测（1.5Mbps / 0.8Mbps）两条全复现，
根因是两个，跟 09-06 那次的「码率」不是同一件事：

1. **空白 = 视频还没有帧就把视频墙淡入了**。宣发片 `preload="none"`，0.8Mbps 下点进去
   前 6 秒 `readyState` 一直是 0、`buffered` 是 0，而 `.ih-wall` 已经 opacity 1，
   墙底是白的 —— 用户看到的就是一片白。**`<video>` 从来没有 poster，没有任何静帧兜底**。
   → 抽片子第 0 帧做 poster（`brand-film-poster.webp`，1280×720 / 86KB），浏览器在
   readyState<2 时自动顶上、有帧后自己让位，零 JS。线上 0.8Mbps 实测：点击后 2.5 秒
   `readyState=0 buffered=0`，画面已是完整街景（修复前这里是纯白）。

2. **定格 = 09-06 那个卡顿看门狗的判据抓不住真实慢网**。它要「连续 3 拍每拍播不到 0.5s」，
   而慢网实际表现是走走停停（实测 0.91 / 0.26 / 0.51 / 0.36 / 0.30 / 0.68…），中间那些
   稍好的拍不断把 strikes 清零 —— **1.5Mbps 下 30 秒只播了 13.9 秒（46%）却一次都没降级**。
   → 判据换成窗口效率：`stalled(dts)` 看最近 4 拍（6 秒）累计播放量 / 应播量 < 0.7 就降级；
   loop 绕回那一拍按整拍算，单拍上限压在一拍时长防 seek 跳跃虚高。
   验证（线上 1.5Mbps）：**7.5 秒触发降级，13.5 秒起恢复实时播放**（每 1.5 秒推进 1.5 秒）。

3. **顺带补 Caddy 的 HTML 缓存头**。原先 HTML 响应**根本没有 Cache-Control**，浏览器按
   启发式缓存（约 (now − Last-Modified)/10）自行决定新鲜期 —— 09-06 视频换代改名之后，
   吃着旧 HTML 的访客会去请求已经不存在的旧文件名，首屏同样是一片空白。
   改成 `@html path / */ *.html` + `Cache-Control: no-cache`，只走 ETag 校验（实测 304 / 0 字节）。
   `/hero/*` 的 7 天缓存不动。线上 Caddyfile 备份 `/etc/caddy/Caddyfile.bak-20260910`。

**验证**：stalled() 单测 8 条（含 1.5Mbps 实测那串、loop 绕回、seek 跳跃、窗口滑动）、
前端测试 20 条全绿、线上冒烟 25 路由全过、HTML/zh/bn 三语缓存头全对、poster 200。

**剩余缺口（等 Joe 定）**：链路低于 **1.24Mbps**（-m 小码版的码率）时，降级到小码版后
仍然走走停停（0.8Mbps 实测 30 秒播 5.95 秒 = 20%），**没有更低码的版本可降，也没有第三层兜底**。
可选做法：降到小码版仍判定卡 → 直接 `pause()` 定在当前帧（干净定格 > 抽搐），
或再压一个 ~0.6Mbps 的极小码版。**没做，因为这是审美/权衡决定，不是技术判断。**

**架构层信号**：首屏大视频在关键路径上，弱网降级至今只有「大码 → 小码」一档 + 现在的 poster
兜底，缺一层「彻底放弃视频、退回静态首屏」的终极降级。09-06、09-10 两次都是这一层的漏。
