# 周展雄纹身膏独立站 · 踩坑记录

## 已确认问题
- **这套 Dawn 版本里，很多组件 CSS（`component-price.css`、`component-card.css`、`section-footer.css` 等）不是只在 `<head>` 加载一次，而是被各个 section/snippet 在正文（`<main>`/footer-group）里重复 `stylesheet_tag` 加载一遍。** 自定义样式表虽然物理上放在 `<head>`（紧跟 `base.css`），但只要选择器和 Dawn 原版同优先级，浏览器按"文档里出现的顺序"决胜负——正文里重复加载的那份永远比 head 里的自定义样式晚出现，会把自定义样式盖掉。2026-08-19 做 Task 4（`theme/assets/custom-dark.css`）时逐条 grep 核实出以下 4 处会被吃掉：`.price`（被 `component-price.css` 重新定义 `.price{color:...}`）、`.card--standard .card__inner` / `.card--standard`（被 `component-card.css` 同选择器重新定义 `border`）、`.footer`（被 `section-footer.css` 同选择器重新定义 `border-top`）、`h1/h2/.h1/.h2`（被礼品卡模板 `template-giftcard.css` 重新定义 `letter-spacing`，只影响礼品卡收件页这一个模板）。

## 风险
- 项目文件夹名含全角括号 `（shopify）`，部分工具链可能不认中文/全角路径（参考乐顺科纺：summer-compiler 不认中文路径）。真被工具卡住时再改英文名，先不动。

## 规避策略
- **Dawn 自定义样式被压制的第二种形态（2026-08-21 hero 占位插画隐藏失败）**：`base.css` 里 `.media > *:not(.zoom):not(...)` 这类带多个 `:not()` 的选择器特异性高达 (0,3,x)，单加 `body ` 前缀 (0,2,x) 赢不了。规避：把目标元素的全部真实类名堆上去（如 `body .banner__media.media.placeholder > svg.placeholder-svg` = (0,4,2)）。写完必须用浏览器 `getComputedStyle` 核实生效，theme check 和纯文本抓取都看不出样式没生效。
- 上面那条"正文重复加载组件 CSS 吃掉 head 自定义样式"的问题，不用 `!important`，改成给选择器前面加一层 `body ` 前缀提权即可稳赢（不改变命中的元素，只是把优先级从"同级比顺序"变成"我更精确直接赢"）。例：`.price{...}` → `body .price{...}`。以后往 `theme/assets/custom-dark.css` 加新规则时，先 grep 一下 `theme/assets/*.css` 有没有同选择器同优先级的定义、以及那份文件是不是被 section/snippet 在正文里重复加载，有就照这个办法加前缀，没有就不用加（比如 `.button--secondary`、`.announcement-bar__message` 只在 `base.css` 定义、`base.css` 全站只在 head 加载一次，不用加前缀）。
- `.footer` 还有个和优先级无关的隐患：`section-footer.css` 里 `.footer:not(.color-scheme-1){border-top:none}` 优先级比普通 `.footer` 高，页脚现在用 `scheme-1`（`footer-group.json` 确认）所以不触发；如果以后在主题编辑器里把页脚配色改成别的 scheme，页脚弱化边框会被这条规则吃掉，届时需要专门处理，不是加 `body ` 前缀能解决的。
