# 周展雄纹身膏独立站 · 踩坑记录

## 已确认问题
- **这套 Dawn 版本里，很多组件 CSS（`component-price.css`、`component-card.css`、`section-footer.css` 等）不是只在 `<head>` 加载一次，而是被各个 section/snippet 在正文（`<main>`/footer-group）里重复 `stylesheet_tag` 加载一遍。** 自定义样式表虽然物理上放在 `<head>`（紧跟 `base.css`），但只要选择器和 Dawn 原版同优先级，浏览器按"文档里出现的顺序"决胜负——正文里重复加载的那份永远比 head 里的自定义样式晚出现，会把自定义样式盖掉。2026-08-19 做 Task 4（`theme/assets/custom-dark.css`）时逐条 grep 核实出以下 4 处会被吃掉：`.price`（被 `component-price.css` 重新定义 `.price{color:...}`）、`.card--standard .card__inner` / `.card--standard`（被 `component-card.css` 同选择器重新定义 `border`）、`.footer`（被 `section-footer.css` 同选择器重新定义 `border-top`）、`h1/h2/.h1/.h2`（被礼品卡模板 `template-giftcard.css` 重新定义 `letter-spacing`，只影响礼品卡收件页这一个模板）。

## 规避策略
- **阿里云控制台（dnsnext）React 输入框不吃 form_input 程序化赋值**（2026-08-21 改 DNS 记录确认）：form_input 报"Set text value"但值被 React 弹回原值。规避：`triple_click` 选中输入框内容后用 `type` 键盘输入，稳定生效。改记录值前等弹层里旧值回填出来再动手，提交后有"解析变更确认"弹窗二次确认，内容会列出改动前后对比，核对无误再点确定。
- **Shopify 后台权限**：Settings 级页面（Domains/Payments/Plan）staff 账号（liltrick1015）无权限，必须店主账号 zhouwensen701@gmail.com。切换账号时 accounts.shopify.com 大概率弹 Cloudflare 人机验证，AI 不能代点，要 Joe 手过。
- **Shopify 主题发布后"前台看还是旧主题"排查顺序（2026-08-21 实战，耗一小时）**：先 `shopify theme list` 看角色（[live] 对不对）→ `shopify theme pull --only layout/theme.liquid` 验服务器文件内容 → **关键一步：`curl --noproxy "*"` 直连对比走代理的结果**。当天走代理（127.0.0.1:10808，LAX 出口）拿到的一直是旧主题页（旧主题槽位 t/1），直连立刻是新主题（t/3）——是代理出口命中的那台 Shopify 边缘服务器缓存没过期，不是发布失败。本机浏览器同走代理，所以 Joe 强刷也没用，换代理节点即解。别在这种情况下反复重发布。判别小技巧：响应头 `server-timing` 里 `theme;desc="<id>"` 是真正渲染的主题 id；CDN 路径 `/t/<n>/` 是主题槽位号，直接 curl `/cdn/shop/t/<n>/assets/某主题独有文件` 的 404/200 可判定槽位归属。
- **后台 Themes 页的 Publish 按钮在 iframe 里**，claude-in-chrome 的 a11y 树读不到、坐标点击无效。发布用 CLI：`shopify theme publish --theme <id> --force`（--force 跳过交互确认，非交互终端必加）。
- **Dawn 自定义样式被压制的第二种形态（2026-08-21 hero 占位插画隐藏失败）**：`base.css` 里 `.media > *:not(.zoom):not(...)` 这类带多个 `:not()` 的选择器特异性高达 (0,3,x)，单加 `body ` 前缀 (0,2,x) 赢不了。规避：把目标元素的全部真实类名堆上去（如 `body .banner__media.media.placeholder > svg.placeholder-svg` = (0,4,2)）。写完必须用浏览器 `getComputedStyle` 核实生效，theme check 和纯文本抓取都看不出样式没生效。
- 上面那条"正文重复加载组件 CSS 吃掉 head 自定义样式"的问题，不用 `!important`，改成给选择器前面加一层 `body ` 前缀提权即可稳赢（不改变命中的元素，只是把优先级从"同级比顺序"变成"我更精确直接赢"）。例：`.price{...}` → `body .price{...}`。以后往 `theme/assets/custom-dark.css` 加新规则时，先 grep 一下 `theme/assets/*.css` 有没有同选择器同优先级的定义、以及那份文件是不是被 section/snippet 在正文里重复加载，有就照这个办法加前缀，没有就不用加（比如 `.button--secondary`、`.announcement-bar__message` 只在 `base.css` 定义、`base.css` 全站只在 head 加载一次，不用加前缀）。
- `.footer` 还有个和优先级无关的隐患：`section-footer.css` 里 `.footer:not(.color-scheme-1){border-top:none}` 优先级比普通 `.footer` 高，页脚现在用 `scheme-1`（`footer-group.json` 确认）所以不触发；如果以后在主题编辑器里把页脚配色改成别的 scheme，页脚弱化边框会被这条规则吃掉，届时需要专门处理，不是加 `body ` 前缀能解决的。

- **`shopify theme push` 必须在主题根目录（`theme/`）跑，在仓库根目录跑会把线上主题清空（2026-08-31 公司机实测踩实，已恢复）**：在仓库根 `E:\Projects\周展雄纹身膏独立站（shopify）` 执行 `shopify theme push --theme 130588180526 --allow-live --force`，CLI 把仓库根当成主题根 —— 上传阶段没东西可传，**clean 阶段把 live 主题里 352 个文件全删了**，只剩 `layout/theme.liquid`、`templates/gift_card.liquid`、`config/settings_data.json`、`config/settings_schema.json` 四个 Shopify 拒绝删除的必需文件，线上主题当场变空壳（店铺当时还挂着密码墙，没波及顾客）。**判别信号**：输出里出现 `Failed to delete file "layout/theme.liquid"` 这类"必需文件删不掉"的报错 + 结尾 `pushed with errors` —— 看到这个就是目录跑错了，不是网络问题。**恢复**：`cd theme && shopify theme push --theme <id> --allow-live --force`，一次推回 352 个文件；推完用 `shopify theme pull --path <临时目录>` 数文件数复核。**规矩**：这个仓库的主题在 `theme/` 子目录，所有 shopify theme 命令一律先 `cd theme`。
- **旧的 `shopify theme dev` 进程会一直占着 9292 端口，而且会僵掉（2026-08-31 实测）**：08-28 起的 node 进程活到 08-31，端口占着但请求全返回 500 `Failed to Upload Theme Files`，新起的 dev 直接 `EADDRINUSE`。处理：`Get-NetTCPConnection -LocalPort 9292 -State Listen` 找 PID → `Stop-Process -Id <pid> -Force` → 重起。用完记得关，别留过夜。

- **`sed -i` 不能在 theme 目录里用（2026-09-06 实测踩实）**：`shopify theme dev` 在跑的时候，sed 建的同目录临时文件（`templates/sedXXXXXX`）会被 dev 的文件监听抓到并尝试上传，报 `Must have a liquid file extension`，**之后 dev server 就僵在错误态，所有请求返回 500，只能杀进程重起**（临时文件本身早已被 sed 删掉，看不出是谁干的）。改 theme 里的文件一律用 Edit 工具或 node 脚本原地写，别用 `sed -i`。
- **Shopify section 在 DOM 里的 id 不是模板 json 的 key**：实际是 `shopify-section-template--<主题id>__<key>`（如 `shopify-section-template--16538987921454__reviews`），主题 id 每份主题都不一样，复制主题 / 换主题就变。**CSS 想按 section 定位必须用后缀匹配 `[id$="__reviews"]`**，写 `#shopify-section-reviews` 永远不命中，而且不报错、静默失效。
- **Shopify `range` 类型的设置值必须落在 step 网格上，theme check 查不出来**：给 slideshow 的 `change_slides_speed`（min 3 / max 9 / step 2）写了 6，`theme check` 全绿，但 `theme dev` 上传时整个 `templates/index.json` 被拒，页面报 `Setting 'change_slides_speed' must be a step in the range`。手写模板 json 时，range 设置要先去 section 的 schema 里核对 min/max/step。
- **改 CSS 注释块时把 `*/` 落在中间，后面的规则会被静默吃掉**（2026-09-06 改 logo 时踩到，`filter: brightness(0)` 失效、logo 白底上看不见，theme check 和文本抓取都看不出来）。判别办法照旧：浏览器 `getComputedStyle` 核实关键属性，别靠肉眼看截图猜。
- **暗底改白底后，无图商品卡会「隐形」，看着像商品被删了（2026-09-06 商家/Joe 实际反馈）**：Dawn 对没有主图的商品渲染的是「无图卡」——DOM 里根本没有 `.card__media` 容器（链接 id 是 `StandardCardNoMediaLink-*`），只剩 `.card__inner` 里一行标题。暗底主题时卡片 #161616 在黑底上有层次，翻成白底后卡片和页面同为白色、边框又只有 #e5e3de，四个商品看上去就是一片空白。**判别**：先去后台确认商品数（含 Draft/Archived 筛选），别急着找"谁删了商品"。**修法**：`body .card--standard .card__inner:not(:has(.card__media)) { background:#f5f4f1 }` —— 只垫无图卡，商家上传主图后 `.card__media` 出现、规则自动失效，卡片恢复白底（白底主图配白卡正是要的效果）。教训：改全站配色后，要专门看一遍"占位/空状态"的表现，有内容的地方好看不代表空状态能看。
- **往 Shopify admin 传文件：能做，用「代理 input 转移」这招（2026-09-06 实测跑通，推翻当天早些时候记的"做不了"）**。（2026-09-21 补：这招只有产品页需要。Content → Files 页的 `input[type=file]` 在 light DOM，`find` 直接拿到 ref，`file_upload` 多文件一次传、不会传两份；博客封面走 Files 选图弹窗更省事，见当前进度 09-21 晚段。）症结是 Shopify 的 `input#file-input`（type=file）藏在 **shadow DOM** 里，claude-in-chrome 的 a11y 树不穿透 shadow root，所以 `find`/`read_page` 拿不到它的 ref，而 `file_upload` 的 `ref` 是必填。给它加 aria-label、挪位置、放大都没用——只要还在 shadow DOM 里就进不了树。**做法**：
  1. JS 在 light DOM 里建一个代理 input：`const p=document.createElement('input');p.type='file';p.id='claude-upload-proxy';p.setAttribute('aria-label','ClaudeUploadProxy');p.style.cssText='position:fixed;left:30px;top:400px;z-index:2147483647;width:300px;height:34px;';document.body.appendChild(p)`
  2. `find "ClaudeUploadProxy"` → 拿到 ref（light DOM 里的 file input **能**进 a11y 树）
  3. `file_upload` 把文件传进代理
  4. JS 用 DataTransfer 把 FileList 转移到真 input 并派发 change：`const dt=new DataTransfer();dt.items.add(proxy.files[0]);real.files=dt.files;real.dispatchEvent(new Event('change',{bubbles:true,composed:true}))`（`composed:true` 让事件穿透 shadow boundary）
  5. 删掉代理 input
  **已知副作用：一定会传两份。** 派发 `input`+`change` 会传两份，只派发 `change` 也传两份——组件对 `files` 赋值和 change 事件各响应一次。传完在 Media 区 hover 缩略图 → 点左上复选框 → 右侧出现 "Remove" → 点掉多余那张即可（媒体是即时保存的，Remove 只是从产品解绑，文件仍在 Content > Files）。
- **CDP 截图超时会把页面视口搞坏，后续所有坐标操作跟着废（2026-09-06 踩实）**：`Page.captureScreenshot timed out after 30000ms` 出现几次之后，页面 `innerWidth/innerHeight` 会从 1920×975 变成 **756×406**，表现是截图内容重复平铺、元素 `getBoundingClientRect()` 全归零、按钮点不中。**`resize_window` 修不好**（它改的是浏览器窗口，不是被 override 的视口）。**唯一有效的修法是 `tabs_close_mcp` 关掉标签页重开**，重开后 `innerWidth` 回到 1920。关标签前记得先把未保存的改动 Save 掉。
- **前一条"Shopify 新版 admin 下拉（`s-internal-single-picker`）程序化选不中"，根因很可能就是视口坏了**：视口恢复正常后，产品页的 Theme template 下拉**鼠标一点就展开**，选项（Default product / tktx）正常列出，点一下就选中了。所以遇到这类下拉先看 `innerWidth` 是不是还正常，别急着找绕法。
- **`shopify theme dev` 不能带 `--theme <live id>`（2026-09-21 公司机踩实）**：带了 live 主题 id，dev 会把本地文件直接同步上传到 live 主题，等于未验证的改动提前上线（当天密码墙开着没波及顾客）。正确做法是不带 --theme，让 CLI 自建 development theme 预览；线上只靠 `theme push` 更新。判别信号：dev 启动日志里 `preview_theme_id=130588180526` 就是 live id。
- **Dawn 商品卡两种风格别搞混（2026-09-21）**：`card_style = standard` 是「图片框（.card__inner 带配色/圆角/边框）+ 下方裸文字」，`card_style = card` 才是整张卡（.card--card 带 color-scheme class）包住图和文字。要「白卡包图带文字」的效果直接切 card 风格，不用 CSS 硬拼。card 风格下 `.card__content` padding = image_padding + 1rem。card_* 是全局设置，改了集合页 / 搜索页 / 推荐区一起变，白卡放白底会隐形，对应区块要同步换 scheme-2；main-search 区块没有 color_scheme 设置，只能 CSS 给 `.template-search` 垫底色。
- **移动端截图方案（2026-09-21）**：claude-in-chrome 的 `resize_window` 在 Chrome 最大化时不生效（innerWidth 仍 1920）；agent-browser 0.27.1 `set viewport` 卡 90 秒无输出（未深究）。能用的是借 `E:\Projects\sku-image-workbench\node_modules\playwright` + `channel: "msedge"`（本机 Playwright 内核不全），密码墙 cookie 用 curl POST `/password`（form_type=storefront_password&password=zzx2026）存 cookie jar 再 addCookies 导入；`waitUntil: networkidle` 被 Shopify 第三方脚本拖到超时，用 domcontentloaded + 等 4 秒。脚本模板在会话 scratchpad 的 mobile-shot.js，没入库。
- **验证 hover 样式别靠 Chrome MCP 的 hover**：Joe 切走标签页时 hover 状态不保持，`:hover` 匹配为 false。改为遍历 `document.styleSheets` 确认规则已在线上样式表里且特异性高于 Dawn 原规则。
- **Playwright 导入 curl 的 cookie jar（2026-09-22 家用机踩实）**：Windows 上 curl 写的 jar 是 CRLF，按 `\n` 切行会带 `\r` 进字段；`#HttpOnly_` 开头的行不是注释，`_shopify_essential`（密码墙会话就在它里面）正是这种行，按「# 开头就跳过」过滤掉就永远停在密码页。正确解析：`split(/\r?\n/)`、保留 `#HttpOnly_` 行并去掉前缀作 domain。家用机 Playwright 路径 `E:\Projects\Saas织花云\node_modules\playwright`（公司机是 sku-image-workbench），同样 `channel: "msedge"`。
- **`preview_theme_id` 绑在会话上，核线上前先换 jar（2026-09-22）**：带 `?preview_theme_id=<dev id>` 访问一次后，Shopify 把预览主题记进 `_shopify_essential` 对应的服务端会话，同一 jar 之后不带参数照样渲染 dev 主题（响应头 `server-timing: theme;desc="<id>"` 能看出来）。推 live 后要重新 POST `/password` 拿新 jar 再核，否则「线上已生效」是假的。curl 要 `-L -b jar -c jar` 跟 302。
- **Dawn `.rte` 列表 + 后台编辑器的 `<li><p>…</p></li>`（2026-09-22）**：Dawn 给 `.rte ul` 设了 `list-style-position: inside`，li 里再包块级 `<p>` 时圆点独占一行、文字掉到下一行。商家在后台富文本里粘贴出来的描述就是这种结构。修法一行：`.rte li > p { display: inline; }`（挂在需要的容器下，不要全站）。
- **related-products 推荐数量不保证（2026-09-22）**：Shopify 推荐接口回的件数可能少于 `products_to_show`（店里 7 个商品时只回 3 件），`columns_desktop` 设 4 会空一格。列数按实际能回的件数配，本店 3/3。
- **Shopify 动态源 `{{ product.description }}` 在 richtext 设置里可用（2026-09-22 实测）**：JSON 模板里直接写 `"row_content": "{{ product.description }}"`，collapsible-content 区块渲染出完整描述 HTML，不用写自定义 section。
- **全站级卡片 CSS 别写在 `.card__heading` / `.card__media` 这种 Dawn 通用类上（2026-09-21 博客上线才发现）**：Dawn 的商品卡、博客卡、集合卡共用 `.card*` 类，商品卡要的大写标题和 contain 图片一到博客卡就变成全大写截断 + 两边留灰。商品卡专属规则统一挂 `.product-card-wrapper` 前缀，博客卡是 `.article-card-wrapper`。
- **Shopify 新版 admin 表单元素大多在 shadow DOM，a11y ref 会失效、innerText 读不到**：可靠做法是 JS deep 遍历 shadowRoot 找元素直接操作（native setter + composed 事件 / tinymce API / click shadowRoot 里的 button）。页面在后台标签页时截图会 30s 超时、a11y 树残缺，但 JS 照常跑，整个发博客流程就是这么在后台标签页完成的。具体元素清单见当前进度 09-21 晚段。
