## 阻塞点

**唯一阻塞：没有一个公网能访问的 WordPress**（让云上 Worker 连进来）。当前 `WORDPRESS_API_URL` 是占位 `https://cms.invalid/...`。

两条复工路径：

**路径 A —— 免费隧道（推荐先走，零成本，当天能验完）**
`cloudflared` 已通过 `winget install Cloudflare.cloudflared` 装好。步骤：启动 LocalWP 的 `yanxinna-cms` 站点 → `cloudflared tunnel --url http://yanxinna-cms.local`（quick tunnel，无需账号）→ 把临时网址填进 `wrangler.jsonc` 的 `WORDPRESS_API_URL`（同时更新 WordPress 的 `YANXINNA_ALLOWED_ORIGINS`）→ 重新部署 Worker → 跑 `docs/wordpress/test-checklist.md`。
局限：关机/Local 停/隧道断即失效，只能验收不能长期上线，网址每次重启会变。

**路径 B —— 买主机（正式上线才需要）**
Joe 倾向阿里云。**必须选香港节点免备案**（国内节点绑域名对外服务要 ICP 备案，约 20 天）；买**轻量应用服务器 + WordPress 镜像**，别买空的 ECS。建议先用路径 A 验通再决定是否买。

**副作用待决策**：Pages 项目 `yanxinna-store` 对所有分支建预览部署，CMS 分支每次推送必失败（项目按静态导出配 `out`，CMS 分支已改 SSR 产物在 `.next`）。生产部署未受影响。要么限制预览分支构建，要么等切 Worker 时一并处理——**在此之前 CMS 分支提交先只本地留存**。

## 备忘（Joe 反复问过的概念）
- **主机 ≠ 域名**：主机是租的服务器空间（像租仓库），域名是网址（可后买，验收阶段用主机送的临时网址即可）。
- **「独立站的支付功能」（顾客付款，本站不做）和「买主机的付款」（交服务器租金）是两回事**，别混。

## 已知遗留（不是改代码能解决的）
1. 首页/商店/产品页构建后全是 ƒ Dynamic，每请求一次 Worker，与原 Pages 纯静态的成本/延迟模型不同 → 需 staging 压测后定预期。
2. `enforce_read_only` 只拦 `/yanxinna/v1/`；CPT `show_in_rest => true`，核心 `/wp/v2/*` 要在 WordPress 主机侧配。
3. `images.unoptimized: true` 使 `remotePatterns` 失效，WP 原图直出 → 上 Cloudflare Images 或在 WP 侧限上传尺寸。
4. Webhook `blocking => false` 挂 shutdown，失败无重试无日志，最坏靠 300 秒 revalidate 兜底。
5. 本地探针产品 `PROBE-001 / probe-bodysuit` 保留不删（语言回退活样本），**正式站不要导入**。
