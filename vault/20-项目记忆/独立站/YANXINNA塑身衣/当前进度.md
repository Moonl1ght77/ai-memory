莫斯科 0.141s 说明请求没有真的绕回本机 WordPress，走的是 KV 数据缓存——所以这组数字接近正式上线表现，隧道回源只影响缓存过期后的第一次请求。

**缓存分三层（实测）**：
1. HTML 页面**无 CDN 缓存**：响应头 `Cache-Control: private, no-cache, no-store`，无 `cf-cache-status`。根因是 `app/product/[slug]/page.tsx` 用 `cookies()` 读地区 cookie，Next 判定动态渲染，全站 ƒ Dynamic（对应遗留 #1）。每请求跑一次 Worker。
2. 数据层**有缓存**：`lib/wordpress/client.ts` 的 `next: { revalidate: 300, tags }` 落在 KV，Worker 渲染不回源 WordPress；内容变更由 webhook 立即打掉（实测 8 秒生效）。
3. 静态资源走 Cloudflare assets，正常缓存。

**HTTPS 实测（回答"客户会不会红屏不安全"）**：不会。`isSecureContext: true`、0 个 http 子资源、无混合内容告警、`ssl_verify_result=0`、check-host 23 个海外节点 HTTPS 全 200。真·红屏只有证书错误才出（过期/域名不匹配/没配 HTTPS）；混合内容不红屏，是掉锁+图片被拦。

**本机测速数据全部不可信**：公司机 `HTTP_PROXY=127.0.0.1:10808`，且 `workers.dev` 在大陆被 DNS 污染——本机解析到 `184.173.136.86`（`workers.dev` 解析到 `192.133.77.145`），都不是 Cloudflare 真实 IP（check-host 看到的是 `104.21.40.189` / `172.67.156.78`）。本机 curl 的 CF-RAY 落在 LAX、TTFB 1.2s，是绕代理的结果。**要覆盖中国客户就不能裸用 `workers.dev`，必须绑自定义域名。**

## 阻塞点

**长期阻塞仍在：没有一个公网能长期访问的 WordPress**。当前靠临时隧道，只能验收不能上线。

两条路径：

**路径 A —— 免费隧道（2026-07-30 已验证可行）**
`cloudflared` 已通过 `winget install Cloudflare.cloudflared` 装好。完整步骤：
1. 启动 LocalWP 的 `yanxinna-cms` 站点（Local GUI 里点 Start site；站点根 `C:\Users\Administrator\Local Sites\yanxinna-cms`）。
2. `cloudflared tunnel --url http://yanxinna-cms.local --http-host-header yanxinna-cms.local`
   —— **`--http-host-header` 不能省**，详见踩坑 #31。
3. 临时网址填三处：`wrangler.jsonc` 的 `WORDPRESS_API_URL`（要带 `/wp-json/yanxinna/v1`）、wp-config.php 的 `WP_HOME`/`WP_SITEURL`（踩坑 #32）、wp-config.php 的 `YANXINNA_ALLOWED_ORIGINS`（填 Worker 网址，不是隧道网址）。
4. `npm run deploy`（在 worktree 里跑），然后按 `docs/wordpress/test-checklist.md` 验收。
局限：关机/Local 停/隧道断即失效，网址每次重启会变，三处都要跟着改。

**路径 B —— 买主机（正式上线才需要）**
Joe 倾向阿里云。**必须选香港节点免备案**（国内节点绑域名对外服务要 ICP 备案，约 20 天）；买**轻量应用服务器 + WordPress 镜像**，别买空的 ECS。建议先用路径 A 验通再决定是否买。

### 上线前置：HTTPS / SSL（2026-07-30 Joe 问过，尚未执行，以下为待办不是已验证结论）

成本 0 元，**买主机时不要加购阿里云的收费 SSL 服务**。两个面分开办：

1. **前端站**：域名接入 Cloudflare 后 Universal SSL 自动签发、自动续期，免费，无需操作。现在的 Pages 和未来的 Workers 都一样；staging 用的 `*.workers.dev` 本身就是 HTTPS。
2. **WordPress 主机**：阿里云轻量装完镜像默认只有 HTTP，要自己配。做法 = 源站装 Let's Encrypt（certbot / 宝塔一键，90 天自动续期）+ CMS 子域接进 Cloudflare 开代理，**加密模式必须设 Full (strict)**。
   - **坑**：加密模式留成 Flexible 时浏览器有绿锁，但 Cloudflare 回源那段是明文 HTTP = 假加密。Full (strict) 要求源站真装了证书。

为什么是硬要求，不是可选：
- 后台登录密码明文传输。
- `YANXINNA_FRONTEND_URL` 必须 HTTPS + 标准端口，否则 `wp_http_validate_url()` 拒绝，webhook 静默跳过（见 `docs/wordpress/deployment.md` 第 24 行，唯一痕迹是 PHP 日志一行 `Cache refresh skipped: invalid frontend URL.`）。
- 媒体 URL 跟 siteurl 走；siteurl 是 http 时 HTTPS 页面里全是 HTTP 图片 = 混合内容被浏览器拦，整站断图。2026-07-30 验收没暴露这条，是因为 cloudflared 隧道自带 HTTPS。

**副作用待决策**：Pages 项目 `yanxinna-store` 对所有分支建预览部署，CMS 分支每次推送必失败（项目按静态导出配 `out`，CMS 分支已改 SSR 产物在 `.next`）。生产部署未受影响。要么限制预览分支构建，要么等切 Worker 时一并处理——**在此之前 CMS 分支提交先只本地留存**。

## 备忘（Joe 反复问过的概念）
- **主机 ≠ 域名**：主机是租的服务器空间（像租仓库），域名是网址（可后买，验收阶段用主机送的临时网址即可）。
- **「独立站的支付功能」（顾客付款，本站不做）和「买主机的付款」（交服务器租金）是两回事**，别混。
- **SSL 证书不用买**：前端 Cloudflare 免费自动给，WordPress 主机用免费 Let's Encrypt。详见上面「上线前置：HTTPS / SSL」。

## 已知遗留（不是改代码能解决的）
1. 首页/商店/产品页构建后全是 ƒ Dynamic，每请求一次 Worker，与原 Pages 纯静态的成本/延迟模型不同 → 需 staging 压测后定预期。
2. `enforce_read_only` 只拦 `/yanxinna/v1/`；CPT `show_in_rest => true`，核心 `/wp/v2/*` 要在 WordPress 主机侧配。
3. `images.unoptimized: true` 使 `remotePatterns` 失效，WP 原图直出 → 上 Cloudflare Images 或在 WP 侧限上传尺寸。
4. Webhook `blocking => false` 挂 shutdown，失败无重试无日志，最坏靠 300 秒 revalidate 兜底。
5. 本地探针产品 `PROBE-001 / probe-bodysuit` 保留不删（语言回退活样本），**正式站不要导入**。
6. 产品页 slug 不存在时是 soft 404（渲染 404 页面 + noindex，但 HTTP 状态 200）。根因是根级 `app/loading.tsx`，见踩坑 #34。
7. **验收结束要还原两处临时配置**：wp-config.php 里的 `WP_HOME`/`WP_SITEURL` 两行删掉（否则隧道一断本地站打不开）、`wrangler.jsonc` 的 `WORDPRESS_API_URL` 改回占位或真实主机。`wrangler.jsonc` 的隧道网址**故意没提交**（临时值，提交进分支是噪音）。
