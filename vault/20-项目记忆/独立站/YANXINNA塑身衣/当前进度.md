```
schtasks /Create /TN "YANXINNA-CMS-Backup" /SC WEEKLY /D SUN /ST 03:00 /TR "D:\Git\bin\bash.exe E:/Backups/yanxinna-cms/scheduled-backup.sh" /F
```
- ★ **注册计划任务必须管理员权限**：`Register-ScheduledTask` 和 `schtasks /Create` 在普通权限下都是 `Access is denied`，**关沙箱也一样**（是 Windows 本身的限制，不是工具的）。别再白试。
- ★ **`.vbs` 和 `.cmd` 都必须纯 ASCII**：cscript / cmd.exe 按 ANSI 读，中文注释会让整个文件失效。`.sh` 没这问题（bash 读 UTF-8）。
- ★ PowerShell 的 `Get-Content` 读 UTF-8 日志会显示乱码，**那是终端的问题不是文件的问题**，用 Git Bash 的 `tail` 看是正常的。别被它误导去"修"一个没坏的文件。
- ★ **别用 .cmd 做包装**：含中文注释的 `.cmd` 被 cmd.exe 按 ANSI 读会整个崩掉（`'手动跑也行' is not recognized as an internal or external command`）。同一家族的坑还有 PS 5.1 的 `Set-Content` 和踩坑 #39。改用 `.sh`（bash 读 UTF-8 没问题）。
- ★ **也别把 `&&` 和重定向塞进计划任务的参数里**，引号嵌套会炸。全收进 `.sh`。
- 本机 Git 装在 **`D:\Git`**，不是默认的 `C:\Program Files\Git`。

- ★ **快照数量上限 = 实例数 × 3（最多 15 个）**，满了要先删旧的。

## 备忘（Joe 反复问过的概念）
- **主机 ≠ 域名**：主机是租的服务器空间（像租仓库），域名是网址（可后买，验收阶段用主机送的临时网址即可）。
- **「独立站的支付功能」（顾客付款，本站不做）和「买主机的付款」（交服务器租金）是两回事**，别混。
- **SSL 证书不用买**：前端 Cloudflare 免费自动给，WordPress 主机用免费 Let's Encrypt。详见 `历史归档.md`「上线前置：HTTPS / SSL」段。
- **Cloudflare 不是测试工具，是生产平台**。Joe 多次以为「Cloudflare 只是拿来测试/给商家看的」。事实：老生产站 `yanxinna-store.pages.dev` 就跑在 Cloudflare Pages 上已好几个月；`...-cms-staging.workers.dev` 叫 staging 只是**我们起的名字**，不是平台限制，改个名部署上去就是正式站。免费额度 10 万请求/天，本站远远用不到。且不构成锁定 —— 代码在自己的 GitHub，换 Vercel 或自建只改部署配置。
- **前端不能「放进 WordPress」**。这套是 Headless：WordPress 只是个带后台的数据库（存产品 + 给商家加产品），页面由 Next.js 渲染。要把前端放进 WordPress = 把整套 React 站重写成 PHP 主题，推倒重来，且速度还是要靠 CDN。**WordPress 是商家的进货口，Next.js 是客户的门面**，两个东西不是一个东西的两半。
- **域名只是指路牌，指哪都行**。同一个域名的不同子域可指向完全不同的地方（主域指 Cloudflare、`cms.` 指阿里云）。买了主机不等于所有东西都得放主机上。**速度只取决于代码在哪台机器上执行**，与域名指谁、买没买主机无关。
- **老生产站为什么还有购物车和价格**：它从 `feat/homepage-effects` 分支构建，那分支上 `app/cart/`、`app/checkout/`、`app/api/stripe/`、`paypal-provider.tsx` 等 12 个文件原封未动。删干净的是 CMS 分支，从没合并没部署。要给商家看新版就发 staging Worker 网址，不是 `pages.dev`。

## 已知遗留（不是改代码能解决的）
1. 首页/商店/产品页构建后全是 ƒ Dynamic，每请求一次 Worker，与原 Pages 纯静态的成本/延迟模型不同 → 需 staging 压测后定预期。
