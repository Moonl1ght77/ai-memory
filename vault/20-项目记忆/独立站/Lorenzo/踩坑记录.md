## 待二次验证的做法：参考驱动的可交互原型（下个项目再验证一次有效就做成 skill）
- 流程手册：https://claude.ai/artifact/WgakGccdyEoWYr55Y44Pxg ；口令「参考原型」见日常口令。
- 来源：2026-11-02 家用机，Lorenzo 原型 v2 一天内做到 Joe 满意（https://claude.ai/artifact/AtdH7anEY3hnYch6d1tLam）。
- 流程：同步现状 → brief 对照已定事项列冲突、Joe 逐条拍板 → 收参考（参考站 / 配色图 / 字体图 / 效果图，各一张即可）→ 读参考站源码（脚本 + 样式）提取真实色值、字体、动效时长与缓动、结构 → 出一页视觉样板（色卡、字体对照、关键组件、动效演示）→ Joe 确认 → 做整站单文件网页 → 本地服务 + 脚本实测桌面 1440 / 手机 390 → Critic 打分 → 过了再给 Joe → Joe 给现象 + 参考图反馈 → 迭代，每轮决定写记忆。
- Joe 11-02 定的规则：
  1. 不管开头怎么说，默认先出样板、等 Joe 确认再做整站。
  2. brief 和 Builder / Critic / Loop 提示词由 Joe 在 Claude chat 生成后给链接；缺参考站 / 配色图 / 字体图时，Claude 自己上网找 3–5 个候选、读代码出对比页给 Joe 挑，选定后深读再做。只学手法，不碰对方 Logo、图片、文案。
  3. 要 Critic 打分（brief 第 10 节，≥ 85 且无 P0 / P1），过了再给 Joe 看。待定：Critic 用独立子代理（不带 Builder 上下文）以免自评偏宽。
  4. 交付先统一用 claude.ai 私有网页（单文件 HTML，同一网址迭代）。
  5. 动效手感 Claude 验不了，Joe 每轮回一句手感反馈。
- 这次的关键动作（写进 skill）：参考站动效靠读代码不靠截图（`scripts-*.js`、样式表、筛选脚本）；单文件页本地预览要另包 head（charset + viewport）；浏览器面板在后台时动画暂停、截图停首帧，用脚本查状态；转场 / 菜单 / 计数等动画回调都加超时兜底。
- 和现有技能的分工待定：全局规则 14 默认界面设计 oil-ui-pro、前端 oil-frontend、同任务一个主流程；这套流程管"参考 → 原型"，做 skill 时写清与两者的分工。
