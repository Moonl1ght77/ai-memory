# agent全自动生图 · 踩坑记录

## 已确认问题
- **同色系刺绣对颜色/品类检测完全隐形**（2026-07-09 Joe实测款2确认）：款2是黑+暗酒红双色，花是同色线绣同色布（酒红绣酒红），无颜色对比→颜色检测看不出花，早先被误归"文字/纯色款"。教训：**"刺绣款vs纯色款"这类品类判断纯代码做不了（同色刺绣是盲区），必须人眼或看细节图**。工具只做可靠的颜色清单，品类交给人。**【2026-07-09补·生成侧】同色刺绣不仅是识别盲区，也是生成低风险区**：无彩色小元素可丢，通用生成即可接受（款2黑色款Joe实测无问题）→该类款不必上V11定制。对照navy三花（多色小图案）必须定制枚举令才救得回蓝花。→ 由此得"定制取舍原则"：通用能出的+救不动的都不定制，只定制"能救且值得救"的中间款（详见当前进度）。
- **深色配色归并要防"黑吞暗色"**（2026-07-09 实测）：黑(20,20,22)与暗酒红(50,33,40)RGB仅差37，被COLORWAY_DIST=42误并成一个黑。修：加"一中性一有色不归并"守卫，且用**相对饱和度(色度/最亮通道)**而非绝对色度判有色——深色低饱和即黑、浅色需更高饱和才算有色（感知均匀），否则带冷调的浅白会被误拆。season_inventory.py group_colorways/compatible。
- **纯像素品类分类对金属五金/彩色滚边会误判**（2026-07-09 season_inventory实测确认）：品牌彩色小花logo用"色相簇数≥3+尺寸闸1-8%图宽"识别，实测16款~90%准，但款12抽绳裤的银色金属抽绳头（多色反光、尺寸落在闸内）被误判成刺绣款。修法不是继续调阈值（过拟合风险），而是**品类只作"建议"+自动裁候选图供人1秒复核**（真源优先+人工检查点原则）。教训：**纯代码分类有不可消除的边缘case时，正确设计是暴露证据给人确认，不是让代码假装authoritative**。另：细节特写图的吊牌/水洗标会误触发多色，logo检测只在全身图里做。
- **整季白底图可纯代码分拣**（2026-07-09验证）：每款文件夹含正面/背面/细节/五金多角度白底图；"全身平铺vs细节特写"用白边占比判（全身图四周留白≈1.0，特写填满画面），16款零错。season_inventory.py 把"翻225张图挑输入"变一条命令。
- **场景参考是弱锚（影棚素背景）时，8张成品场景各自发明**（V9.2首跑实锤：G1画成白墙水泥地真实房间、G5画成影棚素背景，同一次运行）：无特征背景图锚不住场景，且当时C的风格支柱写死"真实场所/反影棚"与影棚场景冲突。修复（V9.2.1）：A3输出"场景类型+一句可逐字复用的场景句"，C按场景类型双模式切换且8组提示词verbatim复用同一场景句。教训：**风格条款禁止写死单一模式；跨图场景一致性=参考图+逐字同句双锁**。
- **未提供参考且无条款的可见部位（鞋）会每张自由发明**（V9.2首跑实锤：8张鞋款不一）。修复：C鞋类规则=有指定锁指定、无指定则选一个中性描述8组逐字重复；QA跨图一致性加"同一双鞋"。教训：**跨图一致性条款必须枚举所有可见部位，没参考的部位用"选定中性描述+逐字复用"模式兜底**。
- **需求卡文字与输入图矛盾时模型各画各的**（V9.2首跑实锤：REQ2身材写"健身强壮肌肉"但IN1是清瘦模特的头像三视图且无全身→8张身材漂移）。教训：**身材锚必须是全身模特图；需求卡文字只能强化图片事实，不能对抗图片**；输入图规范已写进DOC1（模特图须带体型、图4图5勿同图）。
- **小元素保真受输出像素预算硬限制**（V9.2两轮实测：全身图刺绣无一张对，提示词强化无效）：1K输出的全身构图里 2.5cm 刺绣只分到约20px，物理上画不对。修复路径=给像素而不是给措辞：①半身构图变体（胸区像素×3）②IN3 喂白底原片裁剪的真源细节图（make_detail_crop.py，无AI零幻觉）。教训：**保真问题先算像素账，再谈提示词**（元素在输出图中<40px 时属于物理不可画对区间）。★半身版效果待QA验证。
- **变体禁止复制规则引擎文件**：裂变半身版时把 C/QA 的构图硬编码全部移到 A3 分镜表（数据层），C/QA 变成分镜无关的单份引擎——否则护栏双份，下次修复只改一份，另一变体必回归。
- **verify_canvas.py 的项目id是位置参数**（2026-07-10实测）：`--project <id>` 会被 OPT_WITH_VALUE 当选项值吞掉导致 IndexError，正确用法 `verify_canvas.py [--spec xxx] [--variant x] <projectId>`。另：agent.json 在应用关闭后仍残留（端口拒连≠文件不在），apply 前先确认 LumaXFlow.exe 在跑（`Start-Process` 后约12秒网关才可 ping 通）。
- uv 管理的 Python 装包需 `--break-system-packages`（PEP 668 externally-managed）。
- **用户拖图进画布会产生无连线的游离图片卡**（44卡 vs 蓝图37卡）：不影响运行（无连线不参与拓扑），核验脚本需容错无title卡。
- **多图输入的 LLM 质检节点不能按序号认图**（V9.1 首轮实测确认，已修复）：QA 一次收12张图，收图顺序与连线顺序不一致（8张图并发生成完成顺序随机/大模型多图计数错位），导致6个构图"硬失败"全是误报——QA 对内容的描述是准的，序号全错位。实锤证据：逐一调出8张 G 卡成品复核，张张符合自己的 Set。修复：QA 提示词改为"按内容认图"两步法（先按视觉特征区分参考图/成品图，再按构图特征匹配 Set 1-8），Set 缺失/重复本身即构图失败。教训：**凡是一次喂多张图给 LLM 判断的节点，一律内容认图，禁止序号认图**。
- **content-only 的单卡热更新是安全的**：apply 只发一张卡（ref+type+data.content）就能精准更新该卡提示词，不触碰连线顺序、不覆盖用户已编辑的其他卡。结构不变时优先用单卡 apply，不要全量重发。
- **白底平铺图无法传达弹力服装的上身松紧**（V9.0 实测确认）：Joe 在需求卡写"紧身贴身显肌肉"但出图宽松——因为版型归 A1 商品DNA管而 A1 只看平铺图且未连需求卡②。修复：版型上身要求做成硬指令字段，全链路 REQ2→A1→C→QA 贯通。教训：**凡是"图看不出来"的商品属性（松紧/弹力/垂感上身效果），必须给用户显式硬指令字段，不能指望模型从平铺图推断**。
- **用户心智：输入图=所见即所得**（V9.0 实测确认）：Joe 把"穿搭风格参考（mood图）"理解为"放搭配单品的地方"。教训：面向商家的工作流，输入图语义要做成"你给什么就穿什么"，AI 自主选品/配饰是负资产（他们有固定搭配），删掉反而更稳更省钱。
- **apply 更新已有项目有连线顺序陷阱**：apply 不隐式删除连线，删卡重连会让新连线追加到队尾，导致参考图槽位错位。结构性改动（删卡/改槽位）一律 apply 成新项目，不要原地升级。
- **素材A存在"连线槽位与提示词图号声明错位"**：TEXT8 连线序为图6/图3/图2，提示词却声明 Image1=商品/Image2=细节/Image3=风格；IMAGE4 同类错位。GPT-5.5 靠语义自愈所以"能跑"，但这是随机劣化源。V9.0 用构建器程序化保证连线序=前缀声明序。
- **素材A的生图卡从未真正挂姿势图**：所有 IMAGE 卡只有5张参考图，但提示词前缀声明了6张（Input Image 6 只存在于文字里）。V9.0 的 G1 真挂第6张姿势图，Set1用六图前缀、Set2-8用五图前缀。
- **平台引擎禁环**：QA→生图的级联反馈不能连成环（run 直接报错），必须做成向下的返修支线（R→RG）+ 单卡重跑。
- **构建脚本禁止写死机器路径**（2026-07-08 家机实锤，已修复）：build_lxf.py 的占位图源写死公司机 Temp 目录，家机重建直接失败。修复：占位图入库 `blueprints\assets\`，MEDIA_SRC 改相对蓝图路径。教训：**蓝图必须自包含，工具层只允许平台安装路径一个绝对路径且须是文件头配置常量**（已写入通用框架铁律12）。
- `.lxf` 是 Zip 包（PK头：canvas.json + manifest.json + media/images/）——文本 grep 搜不到卡内容，核验/取内容必须解包；`data` 字段是 JSON 字符串（不是对象）；导出格式与 apply 格式不同（导出：width/height/data字符串；apply：w/h/data对象且白名单 content/model/provider/size/resolution/quality，**不含 imageUrl**——apply 搭的图输入卡需手动放图）。
- Windows 控制台 GBK：py 脚本打印中文乱码，用 `py -X utf8` + `sys.stdout.reconfigure(encoding='utf-8')`。
- Git Bash 的 `/tmp` 与 Windows Python 路径不互通，临时文件用 scratchpad 绝对路径。

## 失败方案
- 无（本轮一次通过；curl 首次静默失败原因是把 node -e 内嵌在同一命令里取 port 失败，改为直接写死 agent.json 里的值即通）。

## 风险
- `run` 消耗余额：G1-G8 同层并发8张 high 质量图，瞬时消耗大；先跑组②检查提示词再跑组③。
- apply 的 data 出现白名单外字段会**整体拒绝**（不是静默丢弃）。
- 加密封装卡（`{"encrypted":true}`）不可读写，遇到只能连线使用。

## 规避策略
- 任何结构/提示词改动走 blueprints → 重跑 build/apply，保持蓝图为唯一真源。
- 新连线前先查 `E:\LumaX Flow\data\agent\docs\prompting.md` 槽位规则；生图卡入边数不得超过模型参考图槽位上限。
- 接口调用前先 GET /ping 与 /manifest 确认登录态与能力。
