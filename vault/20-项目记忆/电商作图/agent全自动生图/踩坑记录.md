# agent全自动生图 · 踩坑记录

## 已确认问题
- **白底平铺图无法传达弹力服装的上身松紧**（V9.0 实测确认）：Joe 在需求卡写"紧身贴身显肌肉"但出图宽松——因为版型归 A1 商品DNA管而 A1 只看平铺图且未连需求卡②。修复：版型上身要求做成硬指令字段，全链路 REQ2→A1→C→QA 贯通。教训：**凡是"图看不出来"的商品属性（松紧/弹力/垂感上身效果），必须给用户显式硬指令字段，不能指望模型从平铺图推断**。
- **用户心智：输入图=所见即所得**（V9.0 实测确认）：Joe 把"穿搭风格参考（mood图）"理解为"放搭配单品的地方"。教训：面向商家的工作流，输入图语义要做成"你给什么就穿什么"，AI 自主选品/配饰是负资产（他们有固定搭配），删掉反而更稳更省钱。
- **apply 更新已有项目有连线顺序陷阱**：apply 不隐式删除连线，删卡重连会让新连线追加到队尾，导致参考图槽位错位。结构性改动（删卡/改槽位）一律 apply 成新项目，不要原地升级。
- **素材A存在"连线槽位与提示词图号声明错位"**：TEXT8 连线序为图6/图3/图2，提示词却声明 Image1=商品/Image2=细节/Image3=风格；IMAGE4 同类错位。GPT-5.5 靠语义自愈所以"能跑"，但这是随机劣化源。V9.0 用构建器程序化保证连线序=前缀声明序。
- **素材A的生图卡从未真正挂姿势图**：所有 IMAGE 卡只有5张参考图，但提示词前缀声明了6张（Input Image 6 只存在于文字里）。V9.0 的 G1 真挂第6张姿势图，Set1用六图前缀、Set2-8用五图前缀。
- **平台引擎禁环**：QA→生图的级联反馈不能连成环（run 直接报错），必须做成向下的返修支线（R→RG）+ 单卡重跑。
- `.lxf` 的 `data` 字段是 JSON 字符串（不是对象）；导出格式与 apply 格式不同（导出：width/height/data字符串；apply：w/h/data对象且白名单 content/model/provider/size/resolution/quality，**不含 imageUrl**——apply 搭的图输入卡需手动放图）。
- Windows 控制台 GBK：py 脚本打印中文乱码，用 `py -X utf8` + `sys.stdout.reconfigure(encoding='utf-8')`。
- Git Bash 的 `/tmp` 与 Windows Python 路径不互通，临时文件用 scratchpad 绝对路径。

## 失败方案
- 无（本轮一次通过；curl 首次静默失败原因是把 node -e 内嵌在同一命令里取 port 失败，改为直接写死 agent.json 里的值即通）。

## 风险
- `run` 消耗余额：G1-G8 同层并发8张 high 质量图，瞬时消耗大；先跑组②检查提示词再跑组③。
- apply 的 data 出现白名单外字段会**整体拒绝**（不是静默丢弃）。
- 加密封装卡（`{"encrypted":true}`）不可读写，遇到只能连线使用。

## 规避策略
- 任何结构/提示词改动走 blueprints → 重跑 build/apply，保持蓝图为唯一真源。
- 新连线前先查 `E:\LumaX Flow\data\agent\docs\prompting.md` 槽位规则；生图卡入边数不得超过模型参考图槽位上限。
- 接口调用前先 GET /ping 与 /manifest 确认登录态与能力。
