## 文档层面的坑（2026-08-30 研究员盘点确认）

**三份大文档互相矛盾，没有 source of truth**
`reverse-unisevenai-report` / `工作台架构-unisevenai-report` / `workbench-blueprint` 三份重叠 60–70%，同一套设计写了三遍，细节对不上：

| 冲突点 | 版本 A | 版本 B |
|---|---|---|
| 数据库表数 | 14 张（含 `runs`） | 9 张（用 `task_groups`） |
| 状态机命名 | `created→uploaded→…→delivered` | `queued→normalizing→…→succeeded` |
| PSD 图层名 | `00_METADATA` / `01_REPEAT_GUIDES` | `00_README_METADATA` / `01_GUIDES_AND_REPEAT_BOUNDS` |
| dev 候选数 | 一次生成 32 保留 8–12 | 4–32 个输出 8–12 |
| seam 权重 | `0.45/0.30/0.15/0.10` 定值 | `w1/w2/w3` 未定 |

引用前必须先确认用哪一份，否则会把两套设计混着实现。

**三个 schema 被引用但不存在**
`TraceAnalysis schema v1`、`ImitateCandidate schema v1`、`DevCandidate schema v1` 三个名字在蓝图里反复出现，`config\` 下**只有** `pattern-ir.schema.json` 一个真实文件。

**`evolution-policy.json` 只有类型声明没有实例值**
印花模板那份是纯 JSON Schema，`baseline_version`、`max_questions_per_round` 全是类型不是取值。（总控项目那份是有实例值的，两者别搞混。）

**所有质量阈值都是空的**
`SEAM_THRESHOLD`、色差阈值、最小线宽、最大放大倍率、preserved region 差异阈值，全写成「配置化」「项目阈值」，无一个具体数值。

**`tiff` 这个名字大概率不产 TIFF**
目标平台前端把 `task_type=tiff` 的文案写成「生成高清/无缝/分层 PSD 文件」。文档明确说字段名不足以证明实际文件的 MIME 或扩展名。自有平台若照抄这个命名，会继承同一处语义混乱。

**四方连续预览是浏览器 CSS，不是服务端算法**
目标平台用 `background-repeat:repeat` + `background-size:33.3333%` 做预览。把它当成服务端无缝算法的证据是错的，文档自己也把这条列为「不应照搬」。

**`unit` 和 `single_file` 的关系文档自相矛盾**
产物链把它们串成一条线（`unit → seamless → single_file`），6.5 节的对照表又把二者写成互斥的两种输出。独幅到底走不走最小单元，没定。

**`/training-lite` 是异物**
印花模板里的 `/training-lite` 命令和 `training-lite-contract.json` 来自教学 PDF（默认任务是「麦田农业无人机 16:9 预览」），与印花业务无关。

## 活库渲染的坑（2026-08-30 实测，两个都是「印出来才知道」的类型）

**画布尺寸必须是平铺周期的整数倍**
按固定尺寸出图，切在半个周期上就不是无缝的。48 张里废了 24 张。渲染器本身没错，是调用方式错。

**多层叠加时，整体周期 = 各层周期的最小公倍数**
格纹的斜纹质感层自己有周期 4，跟 sett 周期未必整除。sett 周期是奇数（179/235/219）时斜纹对不上，接缝就露。
第一版自检没抓到，因为测试用的 sett 周期 152 恰好是 4 的倍数 —— **自检用例要故意取互质的值**，否则挡不住这类错。
修法：`tile_period = lcm(sett周期, twill周期)`，画布按它取整数倍。

**`seam_ratio` 不适合活库，会误报**
它拿接缝差异比内部平均差异。大片纯色的直纹格纹内部平均差异趋零，分母太小，比值炸掉，把真无缝的图判成不合格（实测 3 张误判，roll 误差全是精确 0）。
活库的周期是**构造**出来的，用精确判据：`np.roll(img, period)` 后逐像素相同。不需要估。
`seam_ratio` 留给路径 A（从实拍图反推周期），那时候不知道周期才需要估。

**斜格纹不是把直格纹转 45 度转出来的**
转 45 度会破坏周期性（周期变成 p×√2，无理数）。正确做法是让颜色取决于 `(x+y) mod p` 和 `(x−y) mod p` —— x 或 y 平移 p 时两个坐标都同余不变，所以照样以 p 为周期，精确无缝。

## apimart MJ 实弹两坑（2026-09-01，首单即中，均已修）

- **任务状态包在 `data` 里不在顶层**：`GET /v1/tasks/{id}` 返回 `{code, data:{status,...}}`，在顶层找 status 永远"超时"——实际 101 秒就完成。轮询必须先解 `data` 层。
- **`result.images[].url` 是列表**：一个 url 字段装 4 个地址。飞书踩坑记录早写过，防御代码还是写歪了（walk 只认字符串 url）——抄坑记录要抄到测试里，不是抄到注释里。
- 实测单价 $0.045/单（4张1024），50 单预算 ≈ $2.25，成本可忽略。缝检通过率 40/40（对比飞书历史 11/12），--tile 直出质量稳。

## 形态门禁两坑（2026-09-02 P1.5 实测）

- **Otsu 二值化在浅色/水彩系误杀**：粉底、薄荷底、水彩晕染的斑边缘软，二值化把晕染连成一坨，"融合斑"飙到 50。黑白系准、浅色系不准 = 指标随配色对比度漂。修法：门禁只拦极端（fused>20/ratio>0.3），2~20 打「疑似」交人判，商家判词回来再收。**任何图像启发式指标上线前先按配色分组看分布，别用一个阈值打全谱。**
- **拼版编号必须按全量候选固定**：只画通过项会让编号随门禁结果漂移，商家报的 #10 在下一版变成另一张。规矩：编号 = 全量文件排序序号，被拦的照画（压暗+红标），永不重排。第一版就因此把校准记录写错了两张，已改。

## 校准第一轮学到的（2026-09-02）

- **单张 vs 平铺是两种判断**：商家看单张把边缘裁切的斑读成"拼接问题"，平铺版同一张直接选中。给商家看 AI 件一律发平铺版，单张会制造假问题。
- **机器门禁的误杀要靠商家判词纠**：被拦的 #7 和三张黄标被选中——启发式指标在校准数据回来前只能"标"不能"拦"。规矩：新门禁上线先跑一轮只标模式，拿到人判再决定拦不拦。
- 探谱矩阵 v1 的 tag（b00~b09）与 v2 矩阵不兼容，`reroll()` 对旧 tag 会 KeyError；旧候选只保留不重 roll。
- **apimart MJ 三种失败姿势各一次**（2026-09-02 v2 批 20 单）：① 轮询 300s 超时但任务实际完成——不重发，拿 task_id 再 poll 收割（0 成本）；② 上游 `task_failed "执行报错"` cost=0——预算计数要退回，不然账对不上；③ 任务长时间不出（>20 分钟）——留 task_id 下次收割，别急着重发。**预算计数按提交计，退款按上游 cost 核对。**

## "密集恐惧感"怎么量化（2026-09-02，10 张人判验证）

- **数斑数不行**：商家选中的 #2 有 610 个斑，被判太密的 #14 才 72 个 —— 密感不是数量。
- **对的指标 = 高频能量占比 × 对比度**（FFT 半径 >24/256 的能量比 × 灰度标准差 × 10）：选中 7 张全在 0.27–0.48，被判密的 3 张 1.34–3.47，中间空一段，阈值 1.0 一刀切。已进 `quality.density_score`，拦 ≥1.0，疑似 ≥0.7。
- 教训：**人说的形容词先找 2–3 个候选指标在已有人判上比分离度，别拿第一个想到的就上线**。Otsu 那版差点当门禁用了。
- 提示词层面 MJ 对 "airy / breathing room / not dense" 这类软词基本无视（v2 三种斑型实测斑数均值 238/200/107，都密）。密度靠门禁筛，不靠提示词求。
- **判官不止一个，判词必须带 judge 字段**（2026-09-02）：Joe 看最疏 20 张说"还是密"，商家看同一张说"味道对了 19/20 过"。同一批图两种结论。校准记录若不区分判官，会把两种口味搅成一锅粥。规矩：付费方的判词是该客户的真值；内部人的判词单独成档，做"保守筛"参考。

## 引擎服务化踩的（2026-09-02）

- **mcp 2.x 改名**：`from mcp.server.fastmcp import FastMCP` 没了，改 `from mcp.server.mcpserver import MCPServer`；装的时候没锁版本就中招。要么 `pip install "mcp<2"`，要么用新名。
- **JSON 数字进来是 float**：`repeat_mm=12` 在自检里是 int，走 HTTP 变 `12.0`，SVG 写成 `width="12.0mm"`。mm/px 这类尺寸一律 `:g` 格式化。自检和契约测试各过一遍才抓到——**纯函数自检不等于接口测试**。
- **pytoshop 两个隐藏依赖**：`six`、`packbits`（RLE 压缩用）；不装 `packbits` 就用 `Compression.raw`。
- `reproduce()` 只认参数化款，抽样抽到 AI 件就 KeyError；AI 件复现 = 与源候选逐像素一致。**凡是"按品类分流"的函数，测试抽样必须覆盖每个品类。**
- **活库的"新建任务"不是出一张，是出一批**（2026-09-02 Joe 纠正原型）：正确手感 = 点提交 → 当页下方 12 款候选网格秒出 → 看中点「就要这个」入库 → 不满意「换一批」（换种子，零成本）。别做成"提交→跳任务页→一张"的表单流，那是生成路线的思维。
- **往测试文件里写 `\x00` 字面量要小心**（2026-09-03）：heredoc 里的 `"\x00"` 被 Python 替换成真 NUL 字节写进 .py，报 `source code cannot contain null bytes`；`re.sub` 的替换串里 `\x` 又被当转义炸。修法：替换用 lambda 返回 bytes。凡是写含转义序列的源码，用 Edit 工具或 lambda，别用字符串替换链。

## pytoshop 写 PSD 三坑（2026-09-03 Photopea 实开抓出，psd-tools 读回验证）

1. **默认给每层塞零尺寸黑蒙版**：`LayerRecord.mask` 默认 `LayerMask()`（rect 0 + default_color=False）→ Photoshop/Photopea 按全遮处理，画布一片透明。改 `default_color/disabled` 不管用（psd-tools 仍遮）。正解：`rec._mask = 空对象`（`length()=0`、`write` 只写 4 字节 0），规范里长度 0 = 无蒙版。setter 只认 LayerMask，要写私有 `_mask`。
2. **合并预览图写全零**：不带图层的看图软件、PS 缩略图靠 `image_data`，pytoshop 不填。要自己 `psd.image_data = ImageData(channels=(3,H,W) uint8)`。
3. **图层列表顺序是"第一个 = 最上层"**：按底在前攒的列表要 `reversed()`，否则底色盖住一切、psd-tools `composite(force)` 与合并图差一大截（28 均差就是这个）。
- 附：`psd-tools.composite()` 默认读合并图，`force=True` 才真按图层合成；两者都测才算验过。
- 附：图层名读回带 `\x00` 尾是 psd-tools 显示，Photopea 里干净，无需处理。
- **导出到目标像素别缩放位图，按目标尺寸重算**（2026-09-03）：512 画布 LANCZOS 缩到 1181 会让接缝有亚像素软化。正解 `scale_sett` 把带宽按比例缩成整数像素、总和精确 = 画布，再渲染 —— 周期精确等于画布。**且画布取 4 的倍数**（斜纹周期 4 整除），否则 roll 测试不为 0；物理误差 ≤0.17mm@300DPI，印刷无感，manifest 记 `repeat_mm_actual`。
- **pytoshop RLE 报 `NameError: packbits`**（2026-09-03）：它 `from . import packbits` 引的是自带 C 扩展，pip 装时没编译成功，静默失败；PyPI 的 `packbits` 包接口兼容，手动 `pytoshop.codecs.packbits = packbits` 挂上即可。效果：685mm 幅面 4 层 PSD 1236MB→381MB（比对标 517MB 两层还小）。代价：纯 Python packbits 慢，685mm 要 130s —— ponytail 记着，量大再换 C 实现或换写库。

## potracer 描摹三坑（2026-09-03，一张已知圆实测坐实）

- **极性反的**：`potrace.Bitmap(mask)` 描的是 **False（0）区域**。传 True=斑会描出整幅背景 + 把斑当孔（出现一条覆盖整个画布的大轮廓就是这个）。传 `~mask`。
- **坐标已是图像坐标**（y 向下），不要按 C 版 potrace "原点左下" 去翻，翻了反而错。用已知圆心的合成图验一次就清楚。
- `_Point` 不可解包，取 `.x/.y`。
- 描回验证用 **奇偶 XOR 填充**（每条轮廓单独栅格化后异或），不依赖轮廓方向，与 SVG `fill-rule="evenodd"` 一致。
- **水彩类 AI 图先中值滤波再量化**：碎点让路径数爆炸（6174）且 potrace 一平滑就全"错"；滤 5 后 1570 条、色差 3.9/255。还原度指标用色差不用索引 IoU（三个近米色互换 IoU 惨但人眼无感）。
