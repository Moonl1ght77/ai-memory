## 文档层面的坑（2026-08-30 研究员盘点确认）

**三份大文档互相矛盾，没有 source of truth**
`reverse-unisevenai-report` / `工作台架构-unisevenai-report` / `workbench-blueprint` 三份重叠 60–70%，同一套设计写了三遍，细节对不上：

| 数据库表数 | 14 张（含 `runs`） | 9 张（用 `task_groups`） |
| 状态机命名 | `created→uploaded→…→delivered` | `queued→normalizing→…→succeeded` |
| PSD 图层名 | `00_METADATA` / `01_REPEAT_GUIDES` | `00_README_METADATA` / `01_GUIDES_AND_REPEAT_BOUNDS` |
| dev 候选数 | 一次生成 32 保留 8–12 | 4–32 个输出 8–12 |
| seam 权重 | `0.45/0.30/0.15/0.10` 定值 | `w1/w2/w3` 未定 |

引用前必须先确认用哪一份，否则会把两套设计混着实现。

**三个 schema 被引用但不存在**
`TraceAnalysis schema v1`、`ImitateCandidate schema v1`、`DevCandidate schema v1` 三个名字在蓝图里反复出现，`config\` 下**只有** `pattern-ir.schema.json` 一个真实文件。

**`evolution-policy.json` 只有类型声明没有实例值**
印花模板那份是纯 JSON Schema，`baseline_version`、`max_questions_per_round` 全是类型不是取值。（总控项目那份是有实例值的，两者别搞混。）

**所有质量阈值都是空的**
`SEAM_THRESHOLD`、色差阈值、最小线宽、最大放大倍率、preserved region 差异阈值，全写成「配置化」「项目阈值」，无一个具体数值。

**`tiff` 这个名字大概率不产 TIFF**
目标平台前端把 `task_type=tiff` 的文案写成「生成高清/无缝/分层 PSD 文件」。文档明确说字段名不足以证明实际文件的 MIME 或扩展名。自有平台若照抄这个命名，会继承同一处语义混乱。

**四方连续预览是浏览器 CSS，不是服务端算法**
目标平台用 `background-repeat:repeat` + `background-size:33.3333%` 做预览。把它当成服务端无缝算法的证据是错的，文档自己也把这条列为「不应照搬」。

**`unit` 和 `single_file` 的关系文档自相矛盾**
产物链把它们串成一条线（`unit → seamless → single_file`），6.5 节的对照表又把二者写成互斥的两种输出。独幅到底走不走最小单元，没定。

**`/training-lite` 是异物**
印花模板里的 `/training-lite` 命令和 `training-lite-contract.json` 来自教学 PDF（默认任务是「麦田农业无人机 16:9 预览」），与印花业务无关。

## 活库渲染的坑（2026-08-30 实测，两个都是「印出来才知道」的类型）

**画布尺寸必须是平铺周期的整数倍**
按固定尺寸出图，切在半个周期上就不是无缝的。48 张里废了 24 张。渲染器本身没错，是调用方式错。

**多层叠加时，整体周期 = 各层周期的最小公倍数**
格纹的斜纹质感层自己有周期 4，跟 sett 周期未必整除。sett 周期是奇数（179/235/219）时斜纹对不上，接缝就露。
第一版自检没抓到，因为测试用的 sett 周期 152 恰好是 4 的倍数 —— **自检用例要故意取互质的值**，否则挡不住这类错。
修法：`tile_period = lcm(sett周期, twill周期)`，画布按它取整数倍。

**`seam_ratio` 不适合活库，会误报**
它拿接缝差异比内部平均差异。大片纯色的直纹格纹内部平均差异趋零，分母太小，比值炸掉，把真无缝的图判成不合格（实测 3 张误判，roll 误差全是精确 0）。
活库的周期是**构造**出来的，用精确判据：`np.roll(img, period)` 后逐像素相同。不需要估。
`seam_ratio` 留给路径 A（从实拍图反推周期），那时候不知道周期才需要估。

**斜格纹不是把直格纹转 45 度转出来的**
转 45 度会破坏周期性（周期变成 p×√2，无理数）。正确做法是让颜色取决于 `(x+y) mod p` 和 `(x−y) mod p` —— x 或 y 平移 p 时两个坐标都同余不变，所以照样以 p 为周期，精确无缝。

## 形态门禁两坑（2026-09-02 P1.5 实测）

- **Otsu 二值化在浅色/水彩系误杀**：粉底、薄荷底、水彩晕染的斑边缘软，二值化把晕染连成一坨，"融合斑"飙到 50。黑白系准、浅色系不准 = 指标随配色对比度漂。修法：门禁只拦极端（fused>20/ratio>0.3），2~20 打「疑似」交人判，商家判词回来再收。**任何图像启发式指标上线前先按配色分组看分布，别用一个阈值打全谱。**
- **拼版编号必须按全量候选固定**：只画通过项会让编号随门禁结果漂移，商家报的 #10 在下一版变成另一张。规矩：编号 = 全量文件排序序号，被拦的照画（压暗+红标），永不重排。第一版就因此把校准记录写错了两张，已改。

## 校准第一轮学到的（2026-09-02）

- **单张 vs 平铺是两种判断**：商家看单张把边缘裁切的斑读成"拼接问题"，平铺版同一张直接选中。给商家看 AI 件一律发平铺版，单张会制造假问题。
- **机器门禁的误杀要靠商家判词纠**：被拦的 #7 和三张黄标被选中——启发式指标在校准数据回来前只能"标"不能"拦"。规矩：新门禁上线先跑一轮只标模式，拿到人判再决定拦不拦。
- 探谱矩阵 v1 的 tag（b00~b09）与 v2 矩阵不兼容，`reroll()` 对旧 tag 会 KeyError；旧候选只保留不重 roll。
- **apimart MJ 三种失败姿势各一次**（2026-09-02 v2 批 20 单）：① 轮询 300s 超时但任务实际完成——不重发，拿 task_id 再 poll 收割（0 成本）；② 上游 `task_failed "执行报错"` cost=0——预算计数要退回，不然账对不上；③ 任务长时间不出（>20 分钟）——留 task_id 下次收割，别急着重发。**预算计数按提交计，退款按上游 cost 核对。**

## "密集恐惧感"怎么量化（2026-09-02，10 张人判验证）

- **数斑数不行**：商家选中的 #2 有 610 个斑，被判太密的 #14 才 72 个 —— 密感不是数量。
- **对的指标 = 高频能量占比 × 对比度**（FFT 半径 >24/256 的能量比 × 灰度标准差 × 10）：选中 7 张全在 0.27–0.48，被判密的 3 张 1.34–3.47，中间空一段，阈值 1.0 一刀切。已进 `quality.density_score`，拦 ≥1.0，疑似 ≥0.7。
- 教训：**人说的形容词先找 2–3 个候选指标在已有人判上比分离度，别拿第一个想到的就上线**。Otsu 那版差点当门禁用了。
- 提示词层面 MJ 对 "airy / breathing room / not dense" 这类软词基本无视（v2 三种斑型实测斑数均值 238/200/107，都密）。密度靠门禁筛，不靠提示词求。
- **判官不止一个，判词必须带 judge 字段**（2026-09-02）：Joe 看最疏 20 张说"还是密"，商家看同一张说"味道对了 19/20 过"。同一批图两种结论。校准记录若不区分判官，会把两种口味搅成一锅粥。规矩：付费方的判词是该客户的真值；内部人的判词单独成档，做"保守筛"参考。

## 引擎服务化踩的（2026-09-02）

- **mcp 2.x 改名**：`from mcp.server.fastmcp import FastMCP` 没了，改 `from mcp.server.mcpserver import MCPServer`；装的时候没锁版本就中招。要么 `pip install "mcp<2"`，要么用新名。
- **JSON 数字进来是 float**：`repeat_mm=12` 在自检里是 int，走 HTTP 变 `12.0`，SVG 写成 `width="12.0mm"`。mm/px 这类尺寸一律 `:g` 格式化。自检和契约测试各过一遍才抓到——**纯函数自检不等于接口测试**。
- **pytoshop 两个隐藏依赖**：`six`、`packbits`（RLE 压缩用）；不装 `packbits` 就用 `Compression.raw`。
- `reproduce()` 只认参数化款，抽样抽到 AI 件就 KeyError；AI 件复现 = 与源候选逐像素一致。**凡是"按品类分流"的函数，测试抽样必须覆盖每个品类。**
- **活库的"新建任务"不是出一张，是出一批**（2026-09-02 Joe 纠正原型）：正确手感 = 点提交 → 当页下方 12 款候选网格秒出 → 看中点「就要这个」入库 → 不满意「换一批」（换种子，零成本）。别做成"提交→跳任务页→一张"的表单流，那是生成路线的思维。
- **往测试文件里写 `\x00` 字面量要小心**（2026-09-03）：heredoc 里的 `"\x00"` 被 Python 替换成真 NUL 字节写进 .py，报 `source code cannot contain null bytes`；`re.sub` 的替换串里 `\x` 又被当转义炸。修法：替换用 lambda 返回 bytes。凡是写含转义序列的源码，用 Edit 工具或 lambda，别用字符串替换链。

## pytoshop 写 PSD 三坑（2026-09-03 Photopea 实开抓出，psd-tools 读回验证）

1. **默认给每层塞零尺寸黑蒙版**：`LayerRecord.mask` 默认 `LayerMask()`（rect 0 + default_color=False）→ Photoshop/Photopea 按全遮处理，画布一片透明。改 `default_color/disabled` 不管用（psd-tools 仍遮）。正解：`rec._mask = 空对象`（`length()=0`、`write` 只写 4 字节 0），规范里长度 0 = 无蒙版。setter 只认 LayerMask，要写私有 `_mask`。
2. **合并预览图写全零**：不带图层的看图软件、PS 缩略图靠 `image_data`，pytoshop 不填。要自己 `psd.image_data = ImageData(channels=(3,H,W) uint8)`。
3. **图层列表顺序是"第一个 = 最上层"**：按底在前攒的列表要 `reversed()`，否则底色盖住一切、psd-tools `composite(force)` 与合并图差一大截（28 均差就是这个）。
- 附：`psd-tools.composite()` 默认读合并图，`force=True` 才真按图层合成；两者都测才算验过。
- 附：图层名读回带 `\x00` 尾是 psd-tools 显示，Photopea 里干净，无需处理。
- **导出到目标像素别缩放位图，按目标尺寸重算**（2026-09-03）：512 画布 LANCZOS 缩到 1181 会让接缝有亚像素软化。正解 `scale_sett` 把带宽按比例缩成整数像素、总和精确 = 画布，再渲染 —— 周期精确等于画布。**且画布取 4 的倍数**（斜纹周期 4 整除），否则 roll 测试不为 0；物理误差 ≤0.17mm@300DPI，印刷无感，manifest 记 `repeat_mm_actual`。
- **pytoshop RLE 报 `NameError: packbits`**（2026-09-03）：它 `from . import packbits` 引的是自带 C 扩展，pip 装时没编译成功，静默失败；PyPI 的 `packbits` 包接口兼容，手动 `pytoshop.codecs.packbits = packbits` 挂上即可。效果：685mm 幅面 4 层 PSD 1236MB→381MB（比对标 517MB 两层还小）。代价：纯 Python packbits 慢，685mm 要 130s —— ponytail 记着，量大再换 C 实现或换写库。

## potracer 描摹三坑（2026-09-03，一张已知圆实测坐实）

- **极性反的**：`potrace.Bitmap(mask)` 描的是 **False（0）区域**。传 True=斑会描出整幅背景 + 把斑当孔（出现一条覆盖整个画布的大轮廓就是这个）。传 `~mask`。
- **坐标已是图像坐标**（y 向下），不要按 C 版 potrace "原点左下" 去翻，翻了反而错。用已知圆心的合成图验一次就清楚。
- `_Point` 不可解包，取 `.x/.y`。
- 描回验证用 **奇偶 XOR 填充**（每条轮廓单独栅格化后异或），不依赖轮廓方向，与 SVG `fill-rule="evenodd"` 一致。
- **水彩类 AI 图先中值滤波再量化**：碎点让路径数爆炸（6174）且 potrace 一平滑就全"错"；滤 5 后 1570 条、色差 3.9/255。还原度指标用色差不用索引 IoU（三个近米色互换 IoU 惨但人眼无感）。
- **撒布排布用环面距离**（2026-09-03）：拒绝采样判"太近"时 dx 取 `min(|a-b|, size-|a-b|)`，否则跨边处两斑绕回来会撞在一起。
- **元素描摹用洋红占位透明区**：RGBA 元素矢量化时把透明填成 `#ff00ff` 再量化，最后剔掉洋红色路径和底矩形，剩下的就是元素本体的 path。
- **heredoc 里写 `\x00` 第二次中招**：记了还踩。规矩升级：测试代码里凡要 `rstrip("\x00")`，改用 `.rstrip(chr(0))`，从根上不写转义序列。
- **撒布元素必须以"一朵斑"为单位，不能按连通域切笔触**（2026-09-03）：莲座斑 = 几段笔触围一圈 + 浅芯。按连通域切出来的是单个 C 形，随机旋转一撒就是污渍。抠法：深色 mask 闭运算把笔触连成团，团内非环即芯。
- **Otsu 阈值取 bin 上沿**：`edges[argmax]` 是下沿，`<= t` 会把整档漏掉（合成图 dark 直接为 0）。用 `edges[argmax+1]`。
- **元素旋转要限幅**：有朝向的元素（莲座、花头）±20°；0-360° 只适合无方向的点。
- **密感门禁不判"像不像"**：它只量疏密。元素源错了它拦不住，元素表必须人眼过一遍再量产。


## 描摹链 v2 / vtracer 坑（2026-09-03，均实测坐实）

- **vtracer 彩色模式会自己重算区域均色**：喂 8 色图出 251 种 fill，且 stacked 下层色被上层像素污染 → 精确色对不上、白缝检测全废。正解：**逐色二值描 + 秩掩码堆叠**（第 j 层 mask = 面积排名 ≥ j 的所有色），每条 path 颜色由我们赋，白缝按构造为 0。底色不描，整幅矩形。
- **vtracer 二值模式描"暗"像素**：mask=True 要写成 0（黑），False 写 255；输出路径带 `transform="translate(x,y)"`，坐标是像素坐标，与 PIL 约定一致（偏移实测 0 最优，不要 ±0.5）。
- **PIL `ImageDraw.polygon` 把边界像素填进去**：每个区域右/下各胖 1px，像素级精确的路径（`mode=none`）也被判 5.5% 坏像素 → 描回验证必须 4× 超采样后取像素中心。修前 v1 的 IoU/坏像素数字都偏高。
- **按通道中值滤波在三色交界造混色**：合成花在瓣/心/底交界出第 4 色（46 px）。元素级：占比 <3% 的色并入最近色；全图级靠 ΔE 合并 + 多数票。
- **描摹分辨率 <1024 时门禁必挂**：0.3mm 在 256px/100mm 只有 0.77px，边界误差吃掉 8%；门禁数值只对 ≥1024px 有意义（契约测试用 256 只验字段不验通过）。
- **vtracer spline 与 polygon 还原度相同**（1024 豹纹 2.6% vs 2.7%），polygon 文件小 4 倍（795KB vs 3.4MB）；量大或 PDF 太肥时切 `mode="polygon"`。

## 三档排版与元素表（2026-09-03）

- **排版档位用"占回位比例"不用"倍数"**：MJ 元素表大小不一，倍数一放主元素就 450px 撞成一团；`size=0.21` 这类比例与元素原始像素无关。
- **多档共用点集要带半径**：只按本档 min_dist 判距离，小元素会钻进大元素圈里；点集存 (x, y, r)，判 dist < r_new + r_old。单档时与旧判据逐字节一致（24 款复现验证）。
- **疏排版必须分格（stratified）**：n=9 纯随机会半边空；切 ≈n 格每格一个 + 格内抖动，参考图那种铺满感就出来。
- **色调图判点斑看芯占比**：单色元素常带一两个像素的"芯"残渣，按 n_colors≥2 判会把实心点当莲座送去做主元素；芯占比 <12% 一律点斑并清芯（与 rosette.CORE_MIN_RATIO 同值）。

## Java 后端本机起不来：Tomcat「Unable to establish loopback connection」（2026-09-05，实测坐实）

- 症状：`./mvnw spring-boot:run` 报 `Unable to start embedded Tomcat` → `PipeImpl ... Unable to establish loopback connection` → `UnixDomainSockets.connect0: Invalid argument: connect`。`./mvnw test`（MockMvc）全绿，所以只在真起服务时炸。EngineClient 里「JDK HttpClient 建不起 loopback 管道」是同一根因。
- 根因：JDK 21 在 Windows 上 `Selector.open()` 用 AF_UNIX 回环管道，socket 文件落在 `%TEMP%`（`C:\Users\...\AppData\Local\Temp`，短名长名都一样）时 connect 报 EINVAL；落在 `E:\` 或项目目录（含中文路径）就正常。单文件 `java SelTest.java` 三地对照验过。`-Djava.net.preferIPv4Stack=true` 无效。
- 修法：`server/pom.xml` 的 spring-boot-maven-plugin 加 `<jvmArguments>-Djdk.net.unixdomain.tmpdir=${project.build.directory}</jvmArguments>`，`./mvnw spring-boot:run` 直接能起（6 秒）。手工 `java -jar` 起时也要带这个参数；Linux/容器不受影响。

## 描摹参数实测：0.15mm 是免费午餐，「先放大再描摹」是负收益（2026-09-06，FLO-000023 五组对照）

| 配置 | 色数 | 路径数 | 色差 | 坏像素 | 白缝 | 耗时 | 门禁 |
|---|---|---|---|---|---|---|---|
| 12色/0.30mm/1024（原默认） | 11 | 4609 | 1.72 | 1.8% | 0 | 6s | PASS |
| 20色/0.30mm/1024 | 18 | 7204 | **1.94** | 2.1% | 0 | 8s | FAIL 色数超 |
| **12色/0.15mm/1024** | 11 | **6349** | **1.54** | **1.5%** | 0 | 6s | **PASS** |
| 12色/0.30mm/**2048** | 12 | **3976** | 1.89 | 2.3% | 0 | 15s | PASS |
| 20色/0.12mm/2048 | 19 | 15781 | 1.53 | 1.6% | 0 | 35s | FAIL 色数超 |

- **`min_feature_mm` 0.3→0.15 三个指标全向好、耗时不变、仍过门禁**，已写进 `profiles/print/_from_sample.json` 的 `vector_gates`

  `speckle = mf * W / unit_mm`，**W 翻倍则像素阈值跟着翻倍**，丢掉更多小特征；Lanczos 本来也不增细节

## 对标 PSD 是虚胖的（2026-09-06 定量实测，方法可复用）

对标网站 `output-01a04cb4….psd`：8096×8096 / 517MB / RGB 8-bit / **图层只有 2 层**（Background + Foreground，都是整幅像素）。

定量检验（方法：高频能量 = 拉普拉斯绝对值均值；缩到 1/f 再 Lanczos 放大回原尺寸算 PSNR，PSNR 越高说明该尺度以上是冗余的）：

| 指标 | 对标 8096px | 我们 945px |
|---|---|---|
| 高频能量 | 3.962 | **18.077**（4.6 倍） |
| 缩 1/2 再放大 PSNR | **38.2 dB** | 27.1 dB |
| 缩 1/4 | 31.8 dB | 21.7 dB |

→ 对标的**真实有效分辨率只有约 2000–4000px，其余是插值填出来的**；我们的 945px 每个像素都扛真实信息。
**差距不在画质，在画布物理尺寸**（685mm vs 80mm）。而四方连续图案**平铺是零损失**的：
`export_bundle(sheet_mm=720)` 实测出 8505×8505 / PSD 421MB / 256 秒，比对标还大且细节密度高 4.6 倍。

## 助手不许拿「最像的」顶上去（2026-09-07 Joe 实测抓出，决策 131）

Joe 输入「我要斑点狗印花」，助手回「按豹纹给你找…已经替你选上：豹纹」，铺出 71 款豹纹。
**斑点狗是黑白不规则圆斑，豹纹是带环带芯的玫瑰斑。**

根因不是模型笨，是**提示词只给了两个出口**：匹配上 / 信息不够去追问。
「说得很清楚但库里根本没这个品类」没有出口 → 模型被逼从 6 个品类里挑最像的。
`_relax()` 再补一刀：查不到就丢掉 keyword，只剩品类，71 款全倒出来 ——
**放宽机制在品类猜对时是救场，猜错时是放大器。**

修法是给第三个出口 `no_match`，且命中时**不查库不放宽、模型自己填的品类也要清掉**
（顶上去的那个才是要防的）。

**通用教训**：任何「把自然语言映射到固定枚举」的地方，都必须留「都不匹配」这个出口。
只给「匹配」和「问一句」两条路，模型一定会在第三种情况下硬凑 —— 而且它凑得越自信，
用户越容易信。**枚举白名单防的是编造，防不了顶包。**

顺带：前端 `lookup()` 拿到全空条件会照样查库 = 无筛选 = 把全库倒出来。
**「参数为空」和「参数是通配」在查询接口里长得一样，这是同一类 bug 的另一半。**

## 恒成立的门禁 = 从没报过警的门禁（2026-09-07，决策 126）

撒布件缝检写的是 `run_gates(img, period=size)` —— img 是**一个回位**、period 是**它的宽**，
`np.roll` 滚一整圈是恒等变换，**这条判据永远通过**。躺了很久没被发现，
因为撒布是构造保证无缝的，从来没有件被它拦过。

**空门禁的典型症状就是「从没报过警」。** 定期问一句：这道闸拦下过东西吗？
一次都没有的，要么是真没问题，要么是它根本没在工作 —— 后者要用「造一个必然失败的输入」去验。

## Git Bash 里 curl 带中文 JSON 会按 GBK 发出去（2026-09-09，家用机）

`curl -d '{"note":"中文"}'` 从 Git Bash 发，Java 回 400 `Invalid UTF-8 start byte 0xb5` —— 不是服务的错，是 shell 把命令行里的中文按本机代码页编了。
修法：JSON 先用 Python 写成 UTF-8 文件，`curl --data-binary @file -H 'Content-Type: application/json; charset=utf-8'`。读回来也要 `PYTHONUTF8=1 py -3` 解，不然管道里最后一个字显示成代理对乱码（存的是对的）。
规矩：Windows 上凡是联调发中文体，一律走文件不走命令行；看到「Invalid UTF-8 start byte 0xb5 / 0xc4」先怀疑 shell 编码再怀疑服务。

## Bash 工具的 heredoc 会把双反斜杠折成单反斜杠（2026-09-09，第三次栽同一坑）

heredoc 里写 Python 源码，`\\u` 这种双反斜杠到 Python 手里只剩一个，成了转义序列：09-09 写踩坑文本时一个代理对字面量让 `write` 抛 UnicodeEncodeError，而 `open('w')` 已先把 **踩坑记录.md 截成 0 字节**，靠记忆库 git checkout 才救回。与「heredoc 里写 x00 字面量」两次是同一根因。
规矩升级：① 改记忆 / 文档这类大文件，脚本先用 Write 工具落成 .py 文件再 `py -3 file.py`，不经 shell；② 凡要写「反斜杠 + 字母」的字面量，一律用文字描述代替；③ 危险写法 `open(p,'w')` 改成先写临时文件再 `os.replace`，写失败原件不动。
- 09-09 同一天再踩第四次：文本里有 Windows 路径，`C:` 后面「反斜杠 + U」被 Python 当成 Unicode 转义直接 SyntaxError。含 Windows 路径的文本一律 Write 工具落文件，不走 heredoc。

## `run_all` 会把 contracts 样例的 `createdAt` 刷脏（2026-09-09）

`tests/run_all.py` 的模块自检跑 `engine/contracts.py`，它重写 `docs/contracts/examples/*.export-manifest.json`，只有 `createdAt` 变，工作区就脏了。跑完验收 `git status` 见这一个文件改动 = 正常，`git checkout --` 掉即可；别把它混进别的提交。

## openpyxl `read_only` 打开的 xlsx 不 `close()` 会一直占着文件（2026-09-09，公司机）
- 现象：`terms_import.py --selftest` 在 `TemporaryDirectory` 清理时 `PermissionError: [WinError 32] 另一个程序正在使用此文件`。
- 根因：`load_workbook(read_only=True)` 懒读 zip，句柄一直开着，直到 `wb.close()` 或进程退出；Windows 删不掉被占的文件（Linux 不报，服务器上不会暴露）。
- 规矩：read_only 读完立刻 `wb.close()`。写模式（`Workbook()` + `save`）不受影响。
