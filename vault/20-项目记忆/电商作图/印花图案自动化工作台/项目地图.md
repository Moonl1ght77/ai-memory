# 印花图案自动化工作台 · 项目地图

## 项目定位

印花图案生成/处理的自动化工作台。三种模式：描稿 trace、仿稿 imitate、开发 dev。产物链：最小单元 unit → 四方连续 tiff / 独幅 single_file，两条分支各带一份分层 PSD。

## 技术栈（自有平台，文档已写死）

## 目标平台 unisevenai.com（黑盒观察对象，非自有资产）

前端 Vue 3 + Pinia + Element Plus；对象存储阿里云 OSS；`mode` 只接受 `trace|imitate|dev`；`task_type` ∈ `tiff|single_file`；`file_list` 分 `original/nano/tiff/single_file`。四方连续预览是浏览器 CSS 平铺（`background-repeat:repeat`），**不是服务端无缝算法**，别照抄。

## 长期原则

- 客户印花素材不进记忆库，只记路径
- 下游改动必须走总控任务卡 + 交接卡，不直接开工
- 模型 Runtime、数据库、对象存储、任务队列、印厂参数**五项全部只有选型没有配置**，别假设已有
- 印厂参数是全局阻塞点：四种输出、`/trace` 的 HOLD 条件、`/dev` 的可生产性过滤、8 项验收测试里的 color 与 PSD 两项，全依赖它
- 引用架构事实必须带 `文件路径:行号`

## 与泽鑫飞书作图项目高度重叠（2026-08-30 收工检查发现）

**开工必读** `20-项目记忆\AI应用\泽鑫飞书作图项目\`（尤其踩坑记录）。那个项目**已经在生产环境用 apimart 做印花图案生成**，跑通的东西本项目不要重造：

| 已跑通的 | 在泽鑫项目里 |
|---|---|
| apimart 模型 | 文字 `gpt-5.6-luna`、生图 `gpt-image-2`、**Midjourney** |
| **MJ 无缝直出** | `POST /v1/midjourney/generations`，prompt 里写 `--tile`，轮询 `GET /v1/tasks/{id}`。一单回 4 张 1024 独立单图 |
| MJ 实测质量 | `--tile` 12 张缝检 11 过；对比 `gpt-image` 效果图 4/4 缝检全炸 |
| **接缝检测器** | 已有并实测靠谱（真缝抓得出、MJ 件不误报） |
| 转矢量三件套 | 已有。"要印走转矢量" |
| DPI 实测 | MJ 原图 1024px 约 260DPI，**不到交厂标准** |
