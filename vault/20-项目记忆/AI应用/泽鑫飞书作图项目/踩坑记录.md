# 泽鑫飞书作图项目 · 踩坑记录

## 已确认问题
- 服务器只有 HTTP（80），WebFetch 类工具会强制升 HTTPS 导致连不上；抓页面用 `curl http://43.132.168.36/...`（2026-08-13 验证）
- nginx 对 `/operator/*` 的 POST 返回 404（GET 正常）——控制台网页里所有"新建/保存"操作应该都是坏的，绕法：服务器上直打 `127.0.0.1:8787`。已列入待同事修（2026-08-13 登记能力时发现）
- apimart 对 gpt-5.6 系列聊天模型**无视 stream:false 强制 SSE 流式返回**，标准 JSON 解析直接炸。修法：检测 `data:` 开头就按 SSE 拼接（zexin_print_agent.py chat() 已带兜底，2026-08-13 实测）
- apimart 高峰期**瞬时 401/500 抽风**（后端过载报"Too many connections"，连鉴权都乱拒），几分钟后自愈。症状：之前好好的密钥突然 401，同刻探针再测又 200。平台侧重试是7秒内连打3发（无退避），全撞抽风窗必全灭。已修：zexin_print_agent 对 401/429/5xx 做 5s/10s 退避重试两次（2026-08-13 实测）
- **飞书消息被劫走：同事本机实例和服务器连同一个飞书应用**（websocket 双连接，消息随机分发）。症状：飞书里 `/调用 print_design` 秒回"没有找到能力"，但服务器日志该时刻毫无动静、数据库里能力好好在。诊断法：对时——飞书消息时间 vs `docker logs` 有无活动。解法：同事关本机实例，本地调试要用独立测试飞书应用（2026-08-13 实锤）

- 飞书机器人下载消息图片需单独权限 `im:message:readonly`（错误码 99991672），开通后必须**创建新版本并发布**才生效。诊断法：docker logs 里搜 download_media（2026-08-13 实锤，开通当晚参考图链路即通）

- **半步接工艺坑（2026-08-14 实锤）**：商家的循环单元是"半步接"（相邻横向单元纵向错开半格32cm），不是四方平接。两个连环雷：① 按平接做的无缝图在半步接排列下竖缝对不上；② AI 生成的"无缝"肌理底同样是平接拓扑，垫底后照样现竖缝——底纹必须按晶格（v1=(W,H/2)）程序化生成。解法都在 zexin_bigtile.py `--half-drop`，出货前看 grid3x3 排列预览验缝。**接单先问清循环方式**，别默认平接。
- 首条真实客户反馈（2026-08-14，微信群）：商家嫌矢量成品"太密集"。根因在效果图阶段的图案密度，不是矢量化环节。已修：密度词汇独立于花位焊入提示词（疏/密/满印），默认密度改"适度留白不拥挤"。重跑话术：`/印花 刚才那个方向重出，稀疏一点留白多`
