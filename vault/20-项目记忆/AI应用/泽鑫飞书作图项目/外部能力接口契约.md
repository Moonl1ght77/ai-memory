# 外部能力接口契约（契约1）

> 来源：服务器源码 `src/omni_agent_hub/capability_dispatcher.py` 实读，2026-08-13 确认。
> 用途：写"印花设计"等外部子agent服务时照此实现。改了后端此文件才需要更新本契约。

## 平台 → 子agent（请求）

POST 到控制台登记的 `endpoint_url`，JSON body：

```json
{
  "task_id": "任务ID",
  "tenant_id": "商家ID",
  "agent_id": "agent ID",
  "capability_id": "能力标识",
  "input": { "text": "用户在飞书发的文字" },
  "context": {
    "channel": "feishu",
    "sender_id": "发送人ID",
    "conversation_id": "会话ID",
    "trigger_type": "触发类型",
    "source_id": "来源ID"
  }
}
```

请求头：`X-OmniAgent-Capability: <能力标识>`；登记时填了凭据引用（secret_ref）则带 `Authorization: Bearer <api_key>`，还可配自定义头（存 `secrets/channel_secrets.json`）。

## 子agent → 平台（响应）

同步返回 JSON（可裸返回，也可包在 `data` 字段里）：

```json
{
  "status": "completed",
  "text": "回复到飞书的文字（也认 result_text 字段）",
  "artifacts": [
    {
      "name": "文件名.png",
      "mime_type": "image/png",
      "kind": "image",
      "content_base64": "图片的base64编码"
    }
  ]
}
```

规则（平台侧硬校验）：
- `status` 省略默认 completed；`failed`/`error` 视为失败（错误信息读 `error` 字段）
- **禁止异步**：返回 accepted / queued / processing 直接算失败
- `artifacts` 最多处理 10 个；`content_base64` 必填且必须是合法 base64；`name` 缺省 result.bin、`mime_type` 缺省 application/octet-stream、`kind` 缺省 other
- `text` 和 `artifacts` 至少给一个，否则报"没有返回 text 或成果文件"
- 只有 `artifacts` 没 `text` 时，飞书里自动回"任务已完成，共生成 N 个成果文件。"

## 三个设计约束（动工前必须处理）

1. **120秒超时**（复用 OPENAI_TIMEOUT_SECONDS=120）+ 必须同步返回。生图实测 90～253 秒，合体能力内部调生图有撞线风险。方案三选一：快模型 / 单独放宽超时 / 同事加异步支持。
2. **参考图传不进来**：`input` 只有 `text`，没有图片字段。绕法：图床链接贴文字里 / 同事给契约加 images 字段 / 首版不用参考图。
3. **产物命名权在子agent手里**：`name` 字段咱自己定——"泽鑫-日期-款号-序号"命名规范可直接在合体能力里实现，守则 A-6 的过渡人工步骤届时自动作废。
