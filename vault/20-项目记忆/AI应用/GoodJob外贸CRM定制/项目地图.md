## 技术栈与架构真相

- 后端 Express+TS（server.ts 1.5 万行、mysql-store.ts 1.35 万行，203 文件平铺）；**MySQL 201 表（1.5.17 后；1.4.8 时 199 表；1.3.1 时 132 表）**；344 API；93 测试文件
- 1.4.8 起 npm workspaces 从 2 个变 5 个：backend / frontend / integration-worker / integration-sdk / goodjob-runner（+ whatsapp-plugin 独立 prefix）
- 前端**不是 React**：918KB index.html + 1.38MB prototype-api.ts 手搓 SPA（package.json 里 React 是假依赖）
- WhatsApp 插件独立服务（:3100 API + :5193 前端，Baileys 7.0.0-rc13 + PGlite），插件联系人"建到 CRM"是**断头路**（沙箱表，CRM 不读，打通≈2-4 天桥接）
- 登录：admin@goodjob.com / super@goodjob.com（密码见使用说明.txt，纯演示账号）

## 本地补丁清单（相对上游的改动，升级时要保留）

1. `backend/src/server.ts`：originAllowed 放行 `*.trycloudflare.com`（非生产）；loginLimiter 支持 `LOGIN_RATE_LIMIT` 环境变量
2. `backend/src/ai-http-security.ts`：`AI_HTTP_PROXY` 环境变量走代理（本地演示用）
3. `backend/src/provider-http-client.ts`：`PROVIDER_HTTP_PROXY` 同上（数据源通道）
4. `backend/src/ai-model-runtime.ts`：请求体显式 `stream: false`（apimart 默认流式导致解析失败）
5. `backend/src/prospect-qualification-workflow.ts`：修 campaignId / channelId 自相矛盾校验（原作者 bug，ICP 和门禁闸门出厂焊死）
6. `frontend/vite.config.ts`：`allowedHosts: true`（隧道访问）
7. 环境变量全在 `scripts\run-backend.cmd`（含代理、限流、密钥占位值）
8. `deploy-ubuntu.sh`：上游 1.5.17 起已从公开仓删除，本仓整份是我们的（6 坑修复 + PLATFORM_MFA_ENCRYPTION_KEY + GOODJOB_UPLOADS_DIR），合并上游时 modify/delete 冲突一律 `git add` 保留本地版

## 长期原则

- 路线：**一家一版**（fork 后按商家改），不做平台化
- 演示环境密钥全是占位值，不放真实客户数据、不长期开公网
- 本机 AI/数据源依赖代理（127.0.0.1:10808）开着；正式部署放香港服务器或换国内直连源
- WhatsApp 生产要么商家知情接受 Baileys 封号风险，要么 Meta 官方 API（付费）
- 交付商家前必做：删仓库明文账号说明、改种子密码、重新生成全套密钥
