# GoodJob 外贸 CRM 定制 · 踩坑记录

> 最后更新：2026-08-19（新增 22-28，香港服务器部署实操九轮全验证）

## 环境搭建

1. **schema 导入报 `Invalid default value for 'intent'`**：表定义有中文默认值 `DEFAULT '中'`，Windows 下 mysql 客户端必须加 `--default-character-set=utf8mb4`
2. **`spawn npm ENOENT`**：仓库的 run-with-profile.mjs 用 `spawn("npm")`，Windows 找不到 npm.cmd（作者 Linux 开发）。绕法：手动 source env 后直跑 workspace 命令；Linux 部署无此问题
3. **provision 脚本硬编码 root@3306 无密码**：本机 MySQL 有密码就废。解法（零污染）：用已装 mysqld 起第二实例——`mysqld --initialize-insecure --datadir=<新目录>` + `--port=3307`
4. **schema.mysql.sql 落后代码**：只有 91 表，必须再跑 `db:migrate` 补到 132 表，缺一不可
5. **bat 脚本双坑**：cmd 读 UTF-8 当 GBK 会吃字节（`netstat` 变 `etstat`）；LF 换行 if 块解析崩。**bat 必须 GBK + CRLF**（PowerShell `[IO.File]::WriteAllText($f,$c,[Text.Encoding]::GetEncoding(936))` + CRLF 归一）
6. **mysqld 不认 `%~dp0..\` 相对 datadir**：bat 里先 `pushd "%~dp0.."` + `set ROOT=%CD%` 转绝对路径

## 网络（本机 = 代理环境，一切外连问题先想代理）

7. **curl 测通 ≠ 后端能通**：本机全局代理（127.0.0.1:10808）让 curl 沾光，后端安全客户端裸连必超时。已加 `AI_HTTP_PROXY` / `PROVIDER_HTTP_PROXY` 补丁。**教训：诊断网络问题先 `env | grep -i proxy`**
8. **trycloudflare 域名大陆访问不稳**：老板打不开演示链接。备选：微信屏幕共享（100%通）> cpolar（要注册）> 香港云服务器（正路）。另（2026-08-17）：**cloudflared 本身也要挂代理**——裸连注册 API 报 `failed to request quick Tunnel: context deadline exceeded`；修法=HTTPS_PROXY 环境变量+`--protocol http2`（QUIC 走不了 HTTP 代理），已修进 tunnel.ps1（顺带修了正则误抓 api.trycloudflare.com 的 bug）。昨天能裸连成功纯属直连碰巧通，别指望复现
9. **登录限流误伤**：15 分钟 10 次失败按 IP 计，隧道下全员同 IP 共享额度；手机输入法自动大写密码首字母是高频 401 来源。已加 `LOGIN_RATE_LIMIT` 环境变量放宽
10. **apimart 默认流式返回**：不管请求怎么写都吐 SSE，系统只认一次性 JSON。请求体显式 `stream: false` 修复。另：报错"数据源适配器执行异常"是万能包装，真错误要看 provider_request_logs 表或复现

## 原作者 bug（改前先查这里）

11. **zod 自杀式校验**：`z.string().min(1).optional().default("")` —— 可不填但默认空串又要求至少 1 字符，前端不发该字段就必炸"参数格式错误"。已修 campaignId（ICP 闸门）和 channelId（门禁闸门）两处；**遇到"参数格式错误"先怀疑这个模式**，用 curl 重放拿 issues 数组定位
12. **数据源 Key 保存失败会静默留旧值**：卡片"已保存（留空不修改）"≠存对了。测试连接报"返回结构不兼容"（= 上游 4xx）先点「清除」重粘。Companies House 首配就栽这
13. **AI 配官网张冠李戴**：AI 搜索给 Baird Group 配了 baird-group.com（美国医疗公司），真官网是 baird-group.co.uk。**官网低频验证的"页面标题"必看**，标题和业务对不上就是错的；AI 出的官网和邮箱发信前必须过验证

## 业务功能坑（2026-08-16 摸排实测）

14. **prospect 来源线索跨账号转客户失败**：搜客清单转来的线索（来源 prospect_conversion）点"转为客户"会回查候选记录，候选挂在别的账号名下就报"候选客户不存在或无权访问"。**必须用当初建候选的账号转**（Baird 是 admin 建的，super 转就炸；换 website-inquiry 来源线索秒过验证了归因）
15. **AI 配置按账号隔离**：apimart Key 配在 admin 名下，super/Mia 打开 AI 配置全是"未启用 0 配置"。后果：无 Key 账号的 AI Agent **静默降级"规则模式"**（不报错，治理面板 calls=0 可确认没调 LLM），且规则模式完成标准错配会报"未满足完成标准"。**演示必用 admin**；商家部署要么每人配 Key 要么定制全局共享
16. **CSV 导入三连坑**：① 无 BOM 的 UTF-8 CSV 中文表头识别失败（xlsx 库按 1252 读，报"未识别到有效客户"；加 ﻿ BOM 就好）② 跨归属人查重失效——同名客户（别人名下）再导直接重复建档 ③ 日期列被转成 Excel 序列号显示（46254.33…）。另：界面"字段映射/去重预览"向导是展示图，实际一键直导
17. **成交≠归档，提成不同步**：商机确认成交后，提成对账"同步待核成交"仍报"本月暂无可同步的新归档成交"。必须：商机页关闭商机区→点成交行→抽屉→"归档成交"，之后提成才自动拉入（来源标"归档商机"）
18. **写接口有 CSRF**：登录态裸 fetch POST 会 403"安全校验失败，请刷新页面后重试"。调试/清数据走 UI 或直接 DB（3307 root 无密码，库名 `goodjob_crm_dev`，注意不是 goodjob）

21. **改 AI 配置后必须重启后端**（2026-08-17 实测定论）：改模型/重存 Key 后旧后端进程不自动重载，跑搜客任务报"数据源适配器执行异常 PROVIDER_INTERNAL_ERROR"，特征是 provider_request_logs 里 `http_status=0, duration_ms=0`（请求没发出就在进程内炸）。Key 本身、代理、apimart、gpt-5 全通（解密 Key 手工 curl 验证过）。**规矩：动过 AI 配置/数据源 Key → 停止系统.bat → 启动系统.bat → 再跑任务**。附：解密 ai_model_configs.api_key 的方法——AES-256-GCM，密钥=sha256("goodjob-ai-model-api-key-v1|"+PROVIDER_CREDENTIAL_KEY)，AAD=["ai-model-api-key",行id,provider,owner_id,team_id].join("|")，密文格式 ai-v1.iv.tag.payload（base64url）

## 香港服务器部署（2026-08-19 实测，九轮才通，修好的脚本在服务器 ~/goodjob-src/deploy-ubuntu.sh）

22. **Windows 检出的 .sh 带 CRLF，Linux 上必炸**：`set: pipefail: invalid option name`（\r 不可见）。上传后先 `sed -i "s/\r$//" *.sh`
23. **NodeSource apt 源 GPG 钥匙失效**（NO_PUBKEY 2F59B5F99B1BE0B4）：别修源，直接 nodejs.org 官方二进制包解到 /usr/local。**必须补软链** `ln -sf /usr/local/bin/node /usr/bin/node`——deploy 脚本的 systemd 单元写死 /usr/bin/node
24. **2核2G 编译必 OOM（退出码 137）**，加 2G swap 也救不了：本机编译（backend tsc + frontend vite 共 15 秒），dist 随源码上传，脚本改成产物齐全就跳过构建
25. **deploy-ubuntu.sh 落后代码四处**（原作者脚本没跟上自己的新要求）：① 迁移和运行时都要 `APP_DATABASE_PROFILE=production`，脚本没传 ② 数据库用户权限漏 REFERENCES（建外键必炸）和 DROP，且 grant 给 '127.0.0.1' 但 MySQL 实际按 'localhost' 匹配，两个 host 都要建 ③ 生产模式强制校验 PROSPECT_RUN_IDEMPOTENCY_SECRET 等 5 个密钥，脚本的 .env 模板没写，服务起一次死一次（crashloop 还会把 2核机器 CPU 拖满连 SSH 都挤死）④ 无域名时 CORS_ORIGINS 空，纯 IP 访问 Origin 校验 403"不允许的请求来源"，模板里兜底写死 http://IP
26. **deploy 脚本每次运行整体重写 shared/.env**：事后 append 的变量下一轮就被冲掉，改必须改脚本的 heredoc 模板，不能打补丁在 .env 上
27. **代理会间歇性掐 22 端口**（HTTP 同主机正常、SSH banner 超时就是这毛病）：服务器 sshd 已加 443 双端口（/etc/ssh/sshd_config.d/port443.conf），ssh 配置里 goodjob-hk443 备用；另阿里云控制台"远程连接"网页终端是保底通道
28. **服务器重启会清 /tmp**：上传的部署材料放 /home/admin 别放 /tmp；卡"停止中"等变"已停止"再开机，超 5 分钟用强制停止

## git / GitHub（2026-08-17 入库实操）

19. **浅克隆推新远程必炸**：app 当初是 `--depth=1` 克隆，推到新建空仓报 `remote unpack failed: index-pack failed / did not receive expected object`（每次缺同一个对象=缺历史，不是网络抖动；调 postBuffer/HTTP1.1 都没用）。解法：`git fetch upstream --unshallow` 补全历史再推，秒过。**推老克隆前先 `git rev-parse --is-shallow-repository`**
20. **本机没装 gh CLI 也能建 GitHub 仓库**：`git credential fill` 从凭据管理器拿 token（scope 含 repo），直接 `POST api.github.com/user/repos`。注意：JSON body 带中文在 Git Bash 里 `-d '...'` 传参会报 "Problems parsing JSON"，要么落文件 `-d @file` 要么 description 用英文

## 有用的正面经验

- 浏览器验证登录要带 Origin 头才能复现真实行为（curl 不带 Origin 会测出假阳性）
- Companies House 查注册号：find-and-update.company-information.service.gov.uk 搜名字，认 active 的经营主体（Holdings 是壳）；登记机关代码填 `RA000585`
- Hunter 找采购人：`hunter.io/search/<域名>`，看 Management/Operations 组里带 Buying/Merchandiser/Procurement 的职位；Sales 组是他们卖货的人，别选
- 邮箱格式规律（如 `名.姓@域名`）记下来，同司找第二人不花额度
- 手搓 SPA（非 React）自动化实测技巧：浏览器 ref 点击常失效，`querySelector` + `dispatchEvent(new Event("input",{bubbles:true}))` 填表单最稳；modal 用 `[class*=modal]` 过滤 `offsetParent!==null`；只读接口可用页面内 fetch 带 credentials 快速验证（写接口被 CSRF 拦，见坑 18）
- 权限模型实测：业务动作（释放公池/转候选线索）按**归属人**限制，super/admin 也不能替业务员操作；管理权限≠业务权限。旧记录"发货跟踪等 4 模块 admin 不可见"有误——是侧栏分组折叠导致的误判，admin 全可见
