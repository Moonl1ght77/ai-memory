# 通用AI翻译助手 · 项目地图

## 项目定位
Clean-Room BYOK 通用翻译助手，两条交付线共用一个翻译内核：
1. **Chrome 通用翻译扩展**（销售在 WhatsApp Web / Messenger / LinkedIn / 普通网页用）：划词/粘贴翻译、回译核对、术语表、输入框辅助、标签页实时字幕。每人用自己的 API Key。
2. **独立站 Web Widget + WordPress 薄插件**（网站访客用）：站点后端代理 API，前端零 Key。

从零开发，**禁止**读取/复刻现有 WhatsApp 插件源代码、禁止依赖外贸魔方、禁止占用 C000 任务（2026-08-25 需求文档定）。

## 技术栈
- pnpm 11 workspace monorepo（Node 24 LTS；pnpm 11 用 `corepack prepare pnpm@11.24.0 --activate` 激活）
- 扩展：Chrome MV3 + WXT 0.21 + React 19 + TypeScript strict；sidepanel + background + offscreen 三上下文
- 语音链：tabCapture → offscreen → AudioWorklet → 16kHz PCM16 → Deepgram WebSocket 流式
- 文本 Provider：DeepSeek / OpenAI-Compatible（域名白名单制）
- Widget：Vite lib 单文件 IIFE；WP 插件：单文件 PHP（设置页+短代码+REST 代理+限流限域）
- 测试：Vitest 75 单测 + Playwright 9 E2E（扩展真实加载冒烟）；封控静态扫描 `pnpm policy-scan`

## 长期原则（安全边界，永久有效）
- **16 个封控硬门永久 false**（packages/policy-guard，Object.freeze）：不自动发送、不模拟 Enter、不群发、不抓联系人/聊天史、不读 Cookie/Session、不后台捕获音频、不静默重连、无远程代码执行、无内容遥测。任何新功能不得绕过。
- 一切读取/插入/捕获必须用户点击触发；异常一律失败关闭不重试。
- API Key 默认 storage.session，永不 storage.sync，不进日志/DOM；扩展**没有 content script**（一切注入走用户触发的 executeScript），这是设计不是遗漏。
- 无 required host 权限、无 `<all_urls>`；平台与 API 域名全部 optional 按需申请。
- LinkedIn 锁最保守模式（仅选择→翻译→复制），UI 无开关。
- 新增 API 供应商必须先进 `provider-adapters/src/whitelist.ts` 白名单（代码变更），不开放任意 URL。
- 分发前必须：`pnpm test` + `pnpm e2e` + `pnpm policy-scan`（0 未豁免命中）全绿。
