## 已确认问题

### pnpm 11 装了但 PATH 里还是 10（2026-08-26）
`npm install -g pnpm@11` 成功后 `pnpm --version` 仍是 10.33——`C:\Program Files\nodejs\pnpm` 的 corepack shim 抢在 AppData 之前。**解法：`corepack prepare pnpm@11.24.0 --activate`**。另外 pnpm 11 首次 install 会在 pnpm-workspace.yaml 写入 `allowBuilds` 待确认块，要手动把 esbuild 设 true 再装。

### Vite 会把小文件内联成 data URL，扩展 CSP 拒绝（2026-08-26）
AudioWorklet 的 `?url` 导入因文件 <4KB 被内联成 data:，`audioWorklet.addModule` 在 MV3 扩展页会被 CSP 拦。**解法：wxt.config.ts 里 vite `build.assetsInlineLimit: 0`**。症状隐蔽（构建全绿，运行才炸），语音链改动时留意。

### pnpm audit 在 npmmirror 源下直接报错（2026-08-26）
本机 registry 是 npmmirror，没有 audit 端点。**解法：`pnpm audit --registry=https://registry.npmjs.org`**。

## 风险
- **封控红线**：任何人往代码里加"自动发送/模拟按键/抓联系人"类功能都会被 policy-scan 拦（分发流程必跑）。这不是可商量的优化项，是产品定位。
- 扩展"读取选中/输入框"依赖 activeTab：用户没点过工具栏图标的页面会拿不到授权，报错文案已引导。不要为了省这一步去加 `<all_urls>`——违反需求硬门。
- WhatsApp 等平台改版对本产品影响极小（无 DOM 选择器），但 contenteditable 的 execCommand insertText 在个别富文本编辑器可能失效——fallback 永远是"复制→手动粘贴"。

## 规避策略
- 动语音链后必须人工过一遍：开始→暂停→停止→再开始 + 关标签页/关侧边栏自动停（验收清单 🔎 项）。
- 新增 Provider：白名单 → registry → optional_host_permissions → 错误映射单测，四步缺一不可（docs/Provider接口文档.md 有清单）。
- 测试基线：改任何包先 `pnpm test`，发版前 `pnpm test && pnpm e2e && pnpm policy-scan && pnpm package`。
