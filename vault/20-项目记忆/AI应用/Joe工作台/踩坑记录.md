# Joe工作台 · 踩坑记录

## 已确认问题
- **规格表式风格卡片打动不了 Joe**（2026-10-12）：Oil UI Pro 风格卡片只有色块、字体名和平板按钮，Joe 评价"没有标新立异、按钮普通、不舒服"。给 Joe 定风格要直接出整屏真实效果图。
- **Impeccable 工作界面模式会把布局压回常规后台**（2026-10-12）：它规定工作类界面只许换配色、字体和一处特色，5 张方向图都是"左侧栏 + 卡片"换皮，Joe 仍说不好看。Joe 要强风格化时，不走这条规则。
- **Impeccable 选择页在应用内浏览器面板收起时会判成"页面关闭"**（2026-10-12）：`serve-question --wait` 退出码 4，没拿到选择。退路：图片直接发在聊天里，用提问工具让 Joe 选。

## 失败方案
- 用形容词或规格卡问 Joe 要什么风格：问不出来。先出多张差异很大的整屏试样，让他指。
- 只换材质、颜色不换骨架的「干净版」被 Joe 嫌大众（2026-10-12，85、86–89）。他要的风格化包括排版、按钮、顶部导航、侧边导航和标志写法。几个方向之间，骨架、导航方式、对象样子、标志写法都要拉开，不能都用「左上角标志、顶部标签、左侧栏、表格、右侧详情」这一套。
- 风格阶段 Joe 说「做成××」「要带交互」，直接做了可交互原型（2026-10-12），Joe 说太快了，他只要预览图。风格没点头前，一律先出整屏预览图放进总览页；交互画成图里的状态（悬停、选中、弹窗）。他看过图点头后，才做可交互原型。

## 风险
- 两套账本：工作台若另存一份进度，会和记忆库对不上，又回到"忘了做到哪"。
- 文件架核心若引用工作台层或记忆库的代码，将来拆不出来单卖。
- 游戏风试样里出现过别家角色（茶杯头、避难所小子、小骑士）和商标（IE、Windows 标志）：正式版不能用；要卖时素材、字体都得自有或开源可商用。

## 规避策略
- 出图提示词要列全所有真实项目名和类目，否则 gpt-image 会自己编项目、编标签、编摘要（2026-10-12 多张试样出现过）。提示词里写「and more / 还有更多」必出假项目（90、93 第一版编了十几个），要写「exactly these N and no others」再列全。
- APIMart 出图脚本 `design\tools\apimart-image.mjs`：密钥只读环境变量 `APIMART_KEY`；两台电脑上 Node 都能直连 APIMart（2026-10-12 实测）；查余额接口没有 `data` 外层；Windows 上 fetch 之后调 `process.exit` 触发过 libuv 断言（当时开着 `NODE_USE_ENV_PROXY=1`），脚本改成自然结束就好了。
- gpt-image-2.5-flare，3:2、2k、high：每张约 0.045 美元，24～39 秒，中文渲染清楚（2026-10-12 实测 40 余张）。
- 游戏风提示词只写游戏类型、不写作品名，并注明 original designs only：第 9 批 8 张里没有别家角色（2026-10-12，只验过这一次）。
- 更新总览页：Artifact read 带 `path` 取回的 index.html 带着发布外壳（doctype、head、body），去掉外壳再发布；配图路径写长路径 `C:\Users\Moonl1ght7\...`，短路径 `MOONL1~1` 会被读取权限规则拦下（2026-10-12）。
- 按记忆提交算项目活跃度时，排除一次改 7 个以上项目的批量提交（10-12「卡片摘要上线」改了 23 个项目，07-07 记忆系统 2.0 改了 22 和 29 个）。不排除的话，97 天没动的项目也会显示「今天有更新」。普通提交只涉及 1–4 个项目（2026-10-12 统计近 120 天）。
- 公司机的 Codex 命令行不在 PATH（2026-10-15 M5 实测更新）：顶层 `%LOCALAPPDATA%\OpenAI\Codex\bin\codex.exe` 是 5 月的旧版 0.129，找不到商店版桌面版（现在叫「ChatGPT」，AppID `OpenAI.Codex_2p2nqsd0c76g0!App`），`codex app` 会转去开安装页，退出码却是 0。桌面版自己用的新版在 `bin\<子文件夹>\codex.exe`（0.162，和安装包里 `app\resources\codex.exe` 是同一个文件），`codex app <路径>` 打印「Opening workspace … in the Desktop app...」、退出 0，但桌面版 26.1007.9446.0 不跳到文件夹，藏在托盘时窗口也不出来。Claude Code 是 npm 全局装的，在 PATH 上（10-12 核实）。Codex 参数以本机 `codex --help` 为准（官方文档网页抓取超时）。
- 看抖音视频（2026-10-12）：agent-reach 没有抖音通道，用应用内浏览器开公开视频页 `douyin.com/video/<id>`。面板收起时页面不可见，一直停在「视频数据加载中」，截图也超时，要请 Joe 把浏览器面板打开。打开后先从页面里读「章节要点」（带时间点的分段摘要），再点「网页全屏」（快捷键 Y），用脚本暂停并跳到各时间点逐帧截图。10-13 补充：面板收起时，用脚本把 `document.visibilityState` 改成 visible 能让页面加载，但视频帧只在面板显示时才稳定解码。截得最清楚的做法：视口设成 768×1366，跳到目标前 0.6 秒、静音播 0.65 秒再暂停，把视频画到一块铺满视口的画布上再截图（盖住视频时浏览器会停止解码，所以每次跳转前先藏起画布）。仍有部分帧不刷新，用章节要点的文字兜底。
- 跨会话更新深紫原型（2026-10-13）：Artifact 要求先用 Read 逐行读完线上版本（约 700KB、4500 行）才允许覆盖，否则拒绝发布。这次派子代理读完再发布，子代理用了约 74 万 token。同一会话里用同一文件路径重发不受这个限制；子代理在本会话发布过之后，主会话也能直接带网址重发（10-13 第 4 版实测）。给数据瘦身（文档摘录占大头）也能降成本。
- Windows「动画效果」关着时，浏览器会报告「减少动画」（2026-10-13 公司机实测）。深紫原型原来跟随这个设置，默认进「减弱」档，阻尼、放大等动效全看不到；10-13 已改成默认「完整」、不跟随系统。存设置时别把默认值一起存进去，否则以后改默认值对老用户不生效（这次用 motionPicked 区分是不是用户亲手选的）。
- 本地预览深紫原型（2026-10-13）：浏览器面板打不开本地文件，用本机 `.claude/launch.json` 里的 prototype-preview（python http.server 服务 `.preview/`；这两样只写进 `.git/info/exclude`，不进仓库）。生成页开头要补 doctype、`<meta charset="utf-8">` 和移动端 viewport，否则中文乱码、手机模拟按 980px 排版；线上发布外壳会自动补这些。浏览器面板收起时预览里的动画会被拖慢（360ms 的动画约 1 秒才结束），CSS 过渡和 requestAnimationFrame 干脆不走；要测，就在页面里把 requestAnimationFrame 换成 setTimeout、临时关掉相关过渡，滚动后手动派发 scroll 事件。10-13 补充：面板收起时 WAAPI 动画也可能完全停住（currentTime 不走），onfinish 一直不触发，把预览标签切到前台也没用；测法是先 finish() 跳到结尾，再手动调一次 onfinish，调之前先把 onfinish 清掉，否则面板一出帧真事件补发，收尾会再跑一次（这次因此清掉了正在进行的拖动，差点误判成代码问题）。
- 吸顶条（2026-10-13 深紫原型实测）：滚动容器有内边距时，`position: sticky` 的 top 从内边距内侧算起，写 top:0 只吸到内边距下沿，上面那条缝还能看到滚动内容；要贴顶边得写 top: -内边距。吸顶条要用实心底，半透明加模糊会让下面的字糊成一团；原标题要在吸顶条出现前淡出，否则同一行字会出现两遍。
- 深紫原型的点击是全局事件委托，按 `[data-proj]`、`[data-act]`、`[data-sel]` 这类属性分派（2026-10-13）。新控件别复用这些属性名做别的用途：待办的勾选框和表单用了 data-proj，一点就被当成面包屑，悄悄跳去了浏览视图。改成 data-pid 解决。
- 记忆库提交的时区和本机不同（2026-10-14 查实）：公司机系统时区是太平洋时间（-07:00），记忆库近 120 天的提交大多是 +08:00。家用机系统时区也是太平洋时间（2026-10-14 `tzutil /g` = Pacific Standard Time，最近的记忆库提交是 -0700），之前写的「两台电脑时区不同」不对。`git log --date=format:` 按每个提交自己的时区输出，按本机时间解析后，16 个项目的最后活动时间差 14–15 小时。读提交时间一律用 `--date=format-local:`，让 git 统一换成本机时间；原型快照脚本已同步改。读 git 路径还要带 `-c core.quotepath=false`，否则中文路径被转义，一个提交都对不上。
- 记忆库是 Obsidian 库（2026-10-14）：`vault/.obsidian/workspace.json` 在 Obsidian 开着时一直在变。监听记忆库要排除 `vault/` 下以点开头的路径（`.obsidian`、`.trash`、编辑器的临时文件），否则会频繁重读。
- notify 8.2 在 Windows 上有两种静默失效（2026-10-14 实测）：缓冲区溢出时事件直接丢掉；被监听的文件夹删掉重建后监听停止。两种都不报错、也不发重扫信号，只能靠定时重读加重新监听兜底（计划 Task 4.2）。
- 会话中途装的 Rust 不在已开 shell 的 PATH 里（2026-10-14）：Claude 进程的环境早于安装，cargo、tauri 命令前要先把 `~\.cargo\bin` 加进 PATH；重启 Claude 后应该就好了（未验证）。
- 家用机上环境变量 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` 在 `tauri dev` 下没生效（2026-10-14 实测），当时以为是 wry 总是自己传 AdditionalBrowserArguments。2026-10-17 公司机：直接启动 exe（包括经开始菜单快捷方式启动）时生效，追加在 wry 参数后面；测装好的正式版就靠它，见计划「依据和约定」第 5 步。开发版照旧用下面的 devcfg.json。改用 `npm run tauri dev -- --config <scratch>\devcfg.json`：devcfg.json 是 `tauri.conf.json` 里主窗口那一整段，加 `"additionalBrowserArgs": "--remote-debugging-port=9222 --disable-features=msWebOOUI,msPdfOOUI,msSmartScreenProtection --autoplay-policy=no-user-gesture-required"`（写了这项 wry 就不补默认参数，后两项要自己带）。写法见实施计划「依据和约定」第 3 步。
- scratch 路径很长，克隆沙盒记忆库报 Filename too long（2026-10-14 家用机）：两次 clone 都加 `-c core.longpaths=true`，克隆完在两个仓里 `git config core.longpaths true`。
- CSS 里引用 `public\` 下的图片要写根路径 `url(/skins/…)`（2026-10-14 Task 2.1）：相对写法 Vite 打包时不处理、原样保留，装好后按 `/assets/` 下去找，背景图会丢。
- 深紫原型 `design\prototype-violet\joe-violet.html` 约 156 KB，整份读一次约花 15 万上下文 token（2026-10-14 M2）。照实施计划给的行号，只读任务要用的行段。
- Ctrl+Alt+Space 在公司机被 Claude 桌面版的快速输入占着（2026-10-15 实测，注册报 `HotKey already registered`，按下弹出的是 Claude 的快速输入窗）。工作台照常启动，设置页显示占用。10-15 Joe 定改用 Ctrl+Alt+N，公司机注册成功；家用机未查。
- Tauri 里启动时就建好、先藏着的辅助窗口（记想法小窗）要写 `"focus": false`（2026-10-15 审查实测）：否则它启动时抢走焦点，按键落进看不见的卡片，回车就记下并推送一条垃圾想法。叫出来时先 `unminimize()`，否则最小化后快捷键叫不回来。
- WebView2 里窗口最小化时 `document.visibilityState` 仍是 `visible`，也不发 `visibilitychange`（2026-10-15 实测）。要判断主窗口有没有被看到，用窗口焦点。但从后台启动、没被激活过的开发版窗口，前台是别的程序时 `document.hasFocus()` 也报 true（10-15 M5 实测，不经 Playwright 直接读也一样），所以要靠窗口的 blur / focus 事件。窗口藏起（hide）时 wry 也不通知 WebView2，页面照样渲染，连线光点让藏在托盘的进程占 CPU 约 2.5%；M6 起藏托盘时同时调 `Webview::hide/show`，降到 0。最小化到任务栏仍在渲染（约 3%，2026-10-16 实测）。
- 原生下拉框（`<select>`）收起且有焦点时，按字母或方向键会直接改值并触发 change（2026-10-15 WebView2 实测）。change 会触发写入的下拉要拦掉这些键，只放行 Tab、Esc、空格、Enter、F4 和 Alt 组合；展开后按 ↓ 再 Esc 也算选定，原生下拉分不出，用撤销兜底。
- git 推送的低速超时（`http.lowSpeedLimit/Time`）管不到连接和 TLS 握手，实测卡满 300 秒（2026-10-15 审查）；要给整个 git 进程加硬超时（现在 60 秒，M4 的 fetch 照用 `run_timed`）。
- 公司机上开着 Codex 电脑操控和 OpenCLI 操控 Chrome（2026-10-15）：真窗口测试中多次被抢前台、混进别的输入，有一次让记下的想法丢了开头几个字。测试结果反常先重跑确认，再怀疑代码。
- 系统级按键（keybd_event、SendKeys）打进的是当时的前台窗口（2026-10-15 公司机）：两次工具调用之间，前台被换成了 Claude 桌面版，测试用的「1015 2030」加回车被打进了 Claude 窗口；之后又被 Chrome 里的抖音页抢走。做法：按快捷键、确认前台、打字放在同一次调用里，前台不是目标窗口就放弃；能用 CDP 发键的地方用 CDP；Joe 在用电脑时不发系统级按键。
- Windows PowerShell 5.1 把不带 BOM 的 .ps1 按本地编码读（2026-10-15）：脚本里的中文字面量会乱，和窗口标题比较永远不相等。用字符编码拼（`-join [char[]](0x8BB0, …)`）或存成带 BOM 的 UTF-8。`Get-Content` 读不带 BOM 的 UTF-8 文件也一样，要加 `-Encoding UTF8`（2026-10-16 M6：读 devcfg.json 设 `TAURI_CONFIG`，中文窗口标题坏掉，构建报 JSON 解析错）。
- PATH 里的 `D:\Git\cmd\git.exe` 只是启动器（2026-10-15 M4 审查实测）：超时只杀它，真正的 git 照跑、照拿锁，fetch 被「杀」后 14 秒照样做完。要杀整棵进程树（现在用 `taskkill /F /T /PID`）。
- git 会半途而废，失败后一定要核对仓库实况，不能只信退出码（2026-10-15 M4 审查实测）：
  - `rebase --abort` 是硬重置，变基期间别人写进工作区的改动和在游离 HEAD 上的提交都会丢；
  - 拿不到 `HEAD.lock` 时，变基已把文件换成远程的树，HEAD 却没动；下一轮「补提交」会把本机没推的想法删掉；
  - 拿不到分支锁时 `rebase --abort` 退出 0，HEAD 却留在游离状态。
  工作台的做法见实施计划执行记录 M4（merge-tree 预判、按实况复原、只退回自己的变基）。
- 判断 git 的输出要按行首匹配（2026-10-15 M4）：git 会把卡住那条提交的标题原样打出来，记忆库的提交标题常带 git 英文报错原句，整段找子串会误判。进度和报错之间用 `\r` 粘在一起，`\r` 也要当换行。
- `git merge-tree --write-tree` 读的是工作区的 `.gitattributes`（2026-10-15 M4）：属性随这次拉取才到的克隆，会被误判成冲突；要加 `git --attr-source=<上游提交>`。
- 对真记忆库只跑带 `--no-optional-locks` 的只读 git（2026-10-15）：普通 `git status` 会刷新并改写 `.git/index`。M4 审查员在真库跑过一次 `git status`，只刷新了时间戳缓存，内容没变。
- `tauri dev` 一见 Rust 文件改动就重编译重启（2026-10-15 M4）：一个子代理开着开发版做真窗口测试时，另一个要改 Rust 就放到独立 git worktree 里改（复制一份 `dist`，编译目录另设 `CARGO_TARGET_DIR`），测完再摘回。
- 开发版开着时 `cargo test` 会因 `target\debug\app.exe` 被占用报 os error 5（2026-10-15 M5），跑测试也另设 `CARGO_TARGET_DIR`。
- ShellExecuteEx 打开文件夹路径时，旁边有同名的 .bat / .exe 就会**运行它**、不开文件夹（2026-10-15 M5 真窗口实测：`C:\x\probe` 旁有 `probe.bat`）：shell 先试 PATHEXT 扩展名。路径补一个结尾 `\` 就只开文件夹。也别用 `explorer.exe <路径>`：explorer 按逗号切参数。
- `claude --desktop`（2026-10-15 读 2.1.299 的实现并实测）：输入或输出不是控制台就拒绝，从程序里起子进程、输出接管道时必失败；还要求命令行用 Claude 账号登录，公司机的命令行没登录，桌面版的登录和它无关。检查过后它只做一件事：`reg query HKCR\claude`，再打开 `claude://code/new?folder=<encodeURIComponent(目录)>`。程序里要开 Claude 桌面版到某文件夹，直接打开这个链接；没信任过的文件夹会先弹「Trust this workspace?」。
