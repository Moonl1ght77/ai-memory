# Joe工作台 · 项目地图

## 项目定位
Joe 自用的 Windows 桌面工作台，解决三个痛点：项目多、做到哪容易忘；想法来不及存；AI 交付的文档事后找不到。
其中「文件架」（按项目聚合文件引用，原文件不动）做成独立核心：自用跑顺后，可单独拆出来上架售卖，对标 Mac 应用 WhereIs。

## 技术栈
Tauri 2 + React + TypeScript（2026-10-12 Joe 确认做成桌面软件）：界面走网页技术，开发时可在浏览器里调和验；Rust 底层与 Tauri 官方插件负责文件、git、托盘、全局快捷键、开机自启。界面风格 2026-10-12 定为深紫干净版（见当前进度），要做皮肤层，以后加游戏皮肤。
- 开发环境（10-13 公司机核实）：Rust（rustup，MSVC 工具链）、VS 生成工具（C++）、WebView2（Win11 自带）、Node。Claude 桌面版自带一份 Claude Code（`%APPDATA%\Claude\claude-code\<版本>\claude.exe`），和 PATH 里 npm 装的命令行是两份，版本各自升级；开工（M5 起）不经命令行，直接打开深链接，见下面「桌面版接入」。
- 开发和检查（10-14 实测）：在项目根目录运行 `npm run tauri dev`（PATH 里要有 `~\.cargo\bin`；Rust 包名是 `app`，开发版程序是 `src-tauri\target\debug\app.exe`）。测试命令：前端 `npm test`，Rust 在 `src-tauri` 下 `cargo test`。环境变量 `VITE_VAULT` 可以让开发版读沙盒记忆库（M2 起是开发版的默认记忆库位置）。要操作真窗口，用 `npm run tauri dev -- --config <scratch>\devcfg.json` 启动：devcfg.json 在主窗口配置里加 `additionalBrowserArgs`，打开 `--remote-debugging-port=9222`，再用 playwright-core 的 `connectOverCDP` 操作真窗口、读页面、截图。环境变量 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` 在家用机不生效（10-14 实测），不再用。devcfg.json 的写法和重建步骤见实施计划的「依据和约定」。M6 起调试构建运行时用开发身份（identifier `com.joe.workbench.dev`、名字 `JoeWorkbenchDev`、标题带「（开发）」），和正式版分开单实例、自启项、窗口状态和 WebView2 数据；验 CSP 要用 custom-protocol 构建（「依据和约定」第 4 步）。
- 打包和安装（2026-10-17 M7）：
  - `npm run tauri build` 出 `src-tauri\target\release\bundle\nsis\JoeWorkbench_<版本>_x64-setup.exe`（0.1.0 约 25 MB）。第一次打包要从 GitHub 下载 NSIS。
  - 装到当前用户 `%LOCALAPPDATA%\JoeWorkbench\JoeWorkbench.exe`，不要管理员，开始菜单和桌面有快捷方式。
  - 正式身份 `com.joe.workbench`：WebView2 数据在 `%LOCALAPPDATA%\com.joe.workbench`，窗口状态在 `%APPDATA%\com.joe.workbench`，开机自启是 HKCU Run 里的 `JoeWorkbench … --hidden`。
  - 构建、升级、卸载见项目仓 README。在 Claude 会话里装，要到容器外装（见踩坑记录）。
  - 公司机 10-17 已装 0.1.0；家用机还没装。
- 记忆库的 git（10-13 核实）：分支 `master`，跟踪 `origin/master`，`pull.rebase=false`；提交信息格式「项目名：……」，工作台写收件箱的提交用「想法收件箱：……」。
- 收件箱的合并方式（10-15 Joe 定，M4）：仓库根目录的 `.gitattributes` 让 `vault/想法收件箱.md` 用 union 合并。两台电脑或 AI 会话各记一条，拉取时不再冲突，两行都留。代价：同一条两边都改了归属会出现两行；一边删、一边改，删掉的那条会回来。出现重复或删了又回来的想法，就是这个原因。别的文件照常冲突，软件遇到冲突就放弃拉取，提示手动处理。
- AI 接入（2026-10-12 核实可做，期次待定）：工作台起一个本地 MCP 服务，Claude Code 和 Codex 共用，两边都支持 stdio。MCP 用官方 Rust 库 rmcp（Apache-2.0，旧贡献仍是 MIT）；内嵌终端用 xterm.js（MIT）+ portable-pty（MIT，Windows 走 ConPTY）；都不是 GPL。只给单次会话挂工作台 MCP、不改用户全局配置：Claude Code 用 `--mcp-config`（加 `--strict-mcp-config` 则只用它），Codex 用 `-c mcp_servers.<名>.command=...`；起手提示词两边都是位置参数，Codex 工作目录用 `-C <目录>`。`--mcp-config` 能接多个值，后面紧跟提示词可能被当成配置，实现时实测参数顺序（未验证）。登录和额度走用户自己的 Claude / Codex 账号，软件不存密钥。来源：Claude Code 官方文档 code.claude.com/docs/en/mcp 与 cli-reference；Codex 为公司机本地 `codex --help`（0.129.0-alpha.15）；许可证读各仓 LICENSE 与 Cargo.toml。
- AI 钩子（二期用，2026-10-18 读官方文档并核公司机；设计和用法见二期设计 5.9、6.5）：
  - Claude Code：钩子写在 `~/.claude/settings.json` 的 `hooks`（公司机原来没有这一项；插件的钩子在各插件自己的 `hooks/hooks.json`，各处合并）；桌面版读同样的设置文件。写文件前后是 PreToolUse / PostToolUse，Write、Edit 的路径在 `tool_input.file_path`，NotebookEdit 是 `notebook_path`，MultiEdit 文档没列。Windows 默认用 Git Bash 跑，写成 exec 形式（`command` 是 exe，`args` 是参数）就不经 shell；`"async": true` 后台跑、不阻塞会话。来源 code.claude.com/docs/en/hooks、desktop。
  - Codex：钩子 0.124（2026-04）起稳定、默认开；公司机命令行 0.162.0-alpha.17.2 在 `bin\9614f1d9b40d9c4f\`（`bin\` 里最新的子文件夹 `77fbd4d52e601e0a` 只有 rg.exe，一期按「有 codex.exe 的最新子文件夹」找，不受影响）。写在 `~/.codex/hooks.json`；补丁工具 apply_patch 不带路径字段，要从补丁文本的 `*** Add File:`、`*** Update File:`、`*** Delete File:`、`*** Move to:` 行取；钩子要在 Codex 里审信任，改了要再审。`config.toml` 的 `notify` 被 Codex 自带的电脑操控占着，桌面版也会改写 config.toml，别往里加东西。来源 developers.openai.com/codex/hooks、github.com/openai/codex 发布说明。
- 桌面版接入（Joe 主要用桌面版，2026-10-12 核实）：Claude 桌面版的 Code 标签和命令行共用 `~/.claude.json`、`.mcp.json` 里的 MCP，另外还读 `claude_desktop_config.json`（聊天侧和 Code 标签都用，命令行不读）。桌面版没有只挂单次会话的办法，只能长期登记，所以工具要少。Codex 桌面版读 `~/.codex/config.toml`（推断：它自己在里面登记了 node_repl）。打开桌面版到指定文件夹（10-15 M5 实测后的做法）：Claude 直接打开 `claude://code/new?folder=<路径>`（`claude --desktop` 检查完做的就是这一步，它本身要命令行登录和真终端）；Codex 用 `%LOCALAPPDATA%\OpenAI\Codex\bin\<子文件夹>\codex.exe` 里最新的一份跑 `codex app <路径>`，再用 `shell:AppsFolder\OpenAI.Codex_2p2nqsd0c76g0!App` 把窗口叫到前台；公司机桌面版 26.1007.9446.0 不跳到文件夹。`claude://code/new?q=` 能预填提示词，但文档只写了 SSH 文件夹，本地文件夹未验证。两个桌面版都是 MSIX 包。来源：code.claude.com/docs/en/desktop、deep-links、cli-reference；Codex 为本机 `codex app --help`。

## 长期原则
- 文件架核心独立：存引用、跟踪改名移动、搜索、同步、截止日期、待办、MCP 都放核心；核心不依赖记忆库和工作台层，依赖只能单向（工作台 → 文件架）。
- 游戏风只做工作台皮肤（2026-10-12 Joe 确认）：项目墙、随手记可以整屏游戏风；文件架界面用普通结构（列表、搜索框、拖放区），颜色、字体、边框走主题变量，在工作台里套游戏皮肤，单卖时默认干净皮肤。照具体游戏做的仿作品素材只能自用，要卖的皮肤素材必须原创或可商用。
- 记忆库是项目进度的唯一账本：工作台只读进度、写想法收件箱，不另存进度。待办和截止日期以软件为准，记忆库只记叙述性进度和决定，AI 收工时两边对齐。
- 不抄 WhereIs 的名字、界面、文案、图标；仓库建仓即私有，不放竞品任何原件（见 `40-知识库\AI协作打法.md`）。
- 不引入 GPL 代码（DeskBox、Constellation 都是 GPL），保留将来闭源售卖的可能。
- 分阶段加关口：自用两三周后再定卖不卖、卖哪块；自用期很少打开就停在自用版。

## 同类调研（2026-10-12）
- WhereIs（whereis.work）：只有 Mac 版（macOS 26+、Apple 芯片）；Pro $39.99/年、买断 $79.99（美区 App Store 价）。
- WhereIs 1.1 功能（2026-10-13 读官网核实）：核心是「文件架」，按事件整理，只存引用不动原文件，一个文件可上多个架；架内有虚拟文件夹、7 色高亮、置顶、多种排序、最多 5 个标签和说明、归档；改名移动靠 macOS 书签跟踪。系统「共享」可把文件送进「未分配」架；也能从 Finder 拖入；搜索按文件名和架名。Pro 功能：每个架的待办（清单、截止日、标记）、截止时间加提醒和渐变倒计时条、整架复制或打包。AI 也在 Pro 里：内置 MCP（工具数没写），能搜索、整理、读 PDF 和 Word、改待办；AI 写的文件靠钩子自动上架并标出是哪个 AI 写的；权限分三级，可预演、可撤销；每个架生成一个工作文件夹，拖到 Dock 里的 Claude、Codex 打开。网页演示里那个 Claude Code / Codex 面板是模拟的，正式版没有内嵌面板。同步走 iCloud，免费版也有；界面有英文、简体中文。免费版限 3 个架、每架 20 项；Pro 每季 $14.99、每年 $39.99、买断 $79.99，试用 14 天。官网没提 Windows。
- GitHub 无现成可用：Stash、Bucket、Edge-Drop、Holdem 等是免费的临时拖放架，没有项目概念、不接 AI；Constellation（Tauri + Rust，用 NTFS 日志跟踪改名移动）最接近，但 3 星、2026-02 后停更、GPL；仓鼠症大结局（hamster-archiver）带 MCP，但做的是媒体归档。
- DeskBox（Joe 在用，`E:\DeskBox`，装的 v1.3.5，最新 v1.5.0）：桌面收纳工具，格子背后是真文件夹（拖入即搬走或复制），一个格子只能映射一个文件夹，不接项目和 AI，解决不了找文档。
