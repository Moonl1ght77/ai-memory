# AI员工自动化总控 · 项目地图

## 项目定位

独立的上层"总控"项目，来自《AI员工自动化.pdf》基础版结构。一名总管（主会话）+ 三名基础员工（研究员 / 执行员 / 验收员），默认串行，总管是唯一任务入口。

它**不是**印花工作台里的一个 agent，也不实现任何业务功能（不生图、不扫描印花、不导出 PSD/TIFF）。它交付的是一套规则和流程：任务卡、交接卡、状态记录、验收契约。

## 技术栈

纯 Markdown + JSON + TOML 配置，无代码、无依赖、无构建。

- Claude Code 入口 `CLAUDE.md`，角色 `.claude/agents/*.md`，命令 `.claude/commands/{bootstrap,handoff,interview}.md`
- Codex 入口 `AGENTS.md`，角色 `.codex/agents/*.toml`
- 契约 `config/project-contract.json`（岗位名、串行、需 Joe 确认的操作清单）
- 下游绑定 `config/child-project-binding.json`
- 进化策略 `config/evolution-policy.json`（扩展前必须访谈）
- 验收 `powershell -NoProfile -File .\scripts\validate-ai-employee-project.ps1 -Root .` → 期望 `AI_EMPLOYEE_CONFIG_VALID`

## 长期原则

- 四个任务名固定，改了验收脚本第 4 关直接 fail：`AI员工自动化总控｜总管｜任务调度` / `｜研究员｜资料与方案` / `｜执行员｜制作与落地` / `｜验收员｜检查与交付`
- 基础版边界：不跨项目自动调度、不共享凭据、不自动装插件、不建隐藏员工或并行员工
- 要加岗位 / 跨项目能力 / 长期记忆 / 改验收规则，先走 `/interview` 写 `docs/interviews/` 草案（保持 `[T] pending`），Joe 确认后才写 `docs/decisions/` ADR 和正式规则
- 发布、发送、付费、删除、覆盖、权限变更、账号登录、生产操作，一律要 Joe 明确批准
- 研究员和验收员只读；执行员只动任务卡授权的文件；同一文件同一时刻只允许一个岗位改
- 模板目录是"母版"，改进先落在项目目录，需要回流母版时手动同步，不要反向覆盖
