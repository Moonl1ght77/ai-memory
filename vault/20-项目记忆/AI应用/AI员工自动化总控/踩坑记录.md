# AI员工自动化总控 · 踩坑记录

## 已确认问题

**验收脚本在本机跑不了（2026-08-29 确认并修复）**
`README.md` 原写 `pwsh -NoProfile -File ...`，但本机没装 PowerShell 7，只有 Windows PowerShell 5.1。5.1 读无 BOM 的 UTF-8 `.ps1` 会按 GBK 解码，中文全变乱码 → 直接 ParserError。
加 UTF-8 BOM 后能解析，但接着报 `INVALID_JSON=config/project-contract.json` —— 脚本里 `Get-Content -Raw` 没指定编码，同样按 GBK 读 UTF-8 的 JSON，中文尾字节被吞成 `?`，把字符串的收尾引号一起吃掉。
修法两步都要：① `.ps1` 加 UTF-8 BOM；② 所有 `Get-Content -Raw` 改成 `Get-Content -Raw -Encoding UTF8`（4 处）。修完输出 `AI_EMPLOYEE_CONFIG_VALID`。

**模板里的相对路径搬家后失效**
`config/child-project-binding.json` 的 `child_project_config_source` 原值是 `..\`，那是模板待在 `矢量绘图平台\docs\claude-config-template\` 里时的相对位置。复制到 `E:\Projects\AI员工自动化总控` 后指向错误目录。复制类模板落地时要通查一遍相对路径。

## 失败方案

- 直接跑 `python` 改文件：本机 `python` / `python3` 是 Windows Store 的占位 stub，一跑就退出码 49。改文件走 sed / heredoc。
- `python`/`python3` 是 Store 占位 stub（退出码 49），**用 `py -3`** 才是真 Python 3.12.10
- `awk -v` 传含反斜杠的 Windows 路径：`-v` 会解释转义，`E:\Projects` 变成 `E:Projects`，反斜杠被吃。含路径的整行替换别用 `awk -v`，改用 `sed` 按行号替换（**2026-08-30 复犯一次**：往 INDEX 路由表插带路径的行时又用了 `awk -v`。凡是插含 Windows 路径的行，先想起这条）。

## 风险

- 客户端能力不能假装：不支持项目栏/任务栏就如实报「仅创建配置」，验收脚本也不检查 UI，别把脚本 PASS 当成任务已创建。
- 模板目录是母版，别把项目目录的改动反向覆盖回去，也别在模板目录里直接干活。

## 规避策略

- 本机 Git Bash 里 sed 替换反斜杠要写 4 个 `\\` 才出 1 个 `\`（这层环境多吃一层转义）。改完必须 `grep` 回读确认。
- 新写给本机跑的 `.ps1`：一律带 UTF-8 BOM，读文件一律显式 `-Encoding UTF8`。

- **Bash 工具里长 heredoc 会 parse 失败**（2026-09-03）：~230 行含 f-string 引号的 Python heredoc 报 `unexpected EOF while looking for matching`，整条命令不执行（文件未动）。规矩：超过 ~100 行或含复杂引号的内容先用 Write 工具写到 scratchpad，再 `cat scratch >> 目标`；小改动用 `py -3 - <<'EOF'` 读文件做 `assert old in s` 精确替换。
- 本机控制台是 GBK：`py -3` 打印中文会乱码，跑脚本前 `export PYTHONIOENCODING=utf-8`。
- **Joe 会把 API Key 直接贴进聊天**（2026-09-03 发生一次）：不能用、不能写进任何文件；回复里提醒该 Key 已暴露需重生成，让他用 `setx APIMART_KEY` 自己设，重开会话后 Bash 才能继承。铁律 4「Key 只走环境变量」是双向的：AI 不写 Key，也不接 Key。
- **Joe 用刘小排 R1–R4 需求评审台本**（2026-09-05）：R2 粘贴块里「1.【问题一】→ 按 A 做…」三行是台本自带示例，Joe 的真答复在块上面；块尾「更新方案 + 继续找决策点 + 不写代码」是固定指令直到 R4。我连挑三轮「模板是空的」，错。规矩：只读 Joe 填的编号答复；决策点变琐碎就收敛，等 R4。


## 工作流撞会话额度：部分完成，续跑别重跑（2026-09-05，两次实测）

- 症状：Workflow 里多个并行 agent 跑到一半报「You've hit your session limit」，工作流以 completed 结束但 failures 列表里有 agent；已完成 agent 的成果（文件）已在仓库里，失败 agent 可能写了一半（第一次后端基础段 70 个文件已落盘且能编译，只是没交报告）。
- 规矩：额度恢复后**先读 `<transcriptDir>/journal.jsonl` 的 result 行 + 失败 agent 的 jsonl 末尾 + `git status`/编译/测试**，判断每段做到哪，只给没完成的段开新工作流；把已完成段的报告原文喂给接力 agent。第二次直接从「修复」段单独起一个工作流，前面的联调/评审结果没重跑。
- 顺带：跨时段的后台工作流各段都要求 agent 用完按 PID 停服务（8080/8100/5173），否则下一段起服务撞端口；起引擎一律 `APIMART_KEY=` 清空，本机用户级变量里有真 Key。

- **Bash 工具的 heredoc 也吃一层反斜杠**（2026-09-05 写 launch.json 时坐实，与上面 sed 四个反斜杠同根）：`cat > f <<'EOF'` 里写 `E:\\Projects` 落盘成 `E:\Projects`，JSON 直接无效。含 Windows 路径的整文件一律用 Write 工具写，或 Python 里用 `chr(92)` 拼；写完必 `json.load` / `grep` 回读。
- **Claude Code 预览面板起 cmd 不查当前目录**：launch.json 里 `cd /d 目录 && mvnw.cmd` 报「不是内部或外部命令」，要写 `.\mvnw.cmd`。
- **桌面端「访问网页」类工具会弹权限确认，Joe 不在或额度用完时整轮卡死**（2026-09-05 三次）：WebFetch / Artifact 读写被驳回后我必须停等，界面就一直转。读公开文档改用 Bash `curl`（Mintlify 类文档站加 `Accept: text/markdown` 直接出正文），Artifact 更新只在 Joe 在场时发。

## Workflow 续跑与并行文档（2026-09-05 晚，实测）

- **撞额度后续跑用 `resumeFromRunId` + 改脚本**：已完成员工走缓存（提示词不变即命中），失败段现跑；在失败段的提示词里加「总管已拍板」块，可把上一轮评审结论直接喂进修复段，不必重跑评审。缓存键是提示词内容，改了拍板文字的那一段自然重跑。
- **文档员工与修复员工并行 → 文档写的是修复前的代码**：文档员按 `git diff` 如实写「没有互斥锁」，而修复员同时在加锁，收尾时四份文档都过时。规矩：文档段放在修复段之后串行，或总管收尾 grep 关键词（「无锁」「下周开放」）复核；这次总管手工改了 6 处。
- **验收标准草案只在聊天里 = 换机就丢**：公司机拟的 8 条草案没进 git，家用机收 R4 时拿不到，只能按方案 §14 重拟。规矩：草案写进任务卡文件再给 Joe 看。
- **评审段的三个镜头值回票价**：钱/钥匙镜头抓到「Java 超时自动重发 = 付费接口双扣」这类联调全绿也看不见的坑；正确性镜头抓到指纹含盘态字段。凡涉及花钱或发号的改动，评审至少两路。


## 验证与工具的三个坑（2026-09-07 凌晨实测）

- **`cmd | tail` 会吃掉退出码**：`py -3 tests/x.py 2>&1 | tail -40` 的 `$?` 是 `tail` 的，永远 0。一次把 AssertionError 的失败读成了「exit 0 通过」。规矩：跑测试一律 `cmd > log 2>&1; echo "EXIT=$?"`，再 `tail` 日志。
- **Python traceback 显示的源码行是「打印那一刻」从磁盘重读的**，不是执行时的代码。测试跑着的时候改了源文件，traceback 会显示新代码却报旧代码的错，看起来像见鬼。判断失败原因要看断言的**值**，别信 traceback 里那一行文字。
- **改了引擎行为必须重跑引擎契约测试**：`c1ed65b` 把 `upscale_item` 改成直接返回 `skipped`，`test_ai_item_chain` 还在断言旧的 `dry_run`/`upscaled`，那轮只报「Java 37/37」就收工了，坏测试留到下一轮才被发现。Java 单测绿 ≠ 引擎契约没塌。

## 「主交付」这类口径改动的两条经验（2026-09-07）

- **口径不能无条件翻**：把矢量 PDF 定为主交付时，LEO-000001 的描摹件恰好过不了矢量门禁（`bad_px_ratio=0.0305>0.03`）。无条件排第一 = 把不合格件标成主交付，正好违背「要高质量」的初衷。正确做法是让主交付**跟质检结果走**，不过闸就退回位图并在说明里写明别送厂。
- **空字典落进 else 会写出吓人的文案**：`_vector_note` 里 `gate.get("passed")` 对原生矢量件（无 `vector_gate` 字段）返回 None，说明.txt 就打印成「门禁：未通过（）」。凡是给商家看的文案，「没有这项检查」和「这项检查没过」必须分开写。

## apimart 与 LLM 接入（2026-09-07 实测）

- **同一把 `APIMART_KEY` 就有 LLM 与 embedding**：`GET /v1/models` 返 357 个模型（claude-haiku-4-5 / gemini / glm / deepseek / text-embedding-3-small 都在）。卡了两天的「LLM Key 走哪家」根本不用换供应商 —— **先探 `/models` 再问人**。
- **`/v1/chat/completions` 不写 `stream` 也回 SSE 流**（`data: {...}` 分块），`json.load` 必炸空 body。用 `/v1/messages`（Anthropic 原生形状）回干净 JSON 带 usage。
- `gemini-2.5-flash` 在这家上游的 safety_settings 配错，直接 400，绕开。

## LLM 当筛选器的两条（2026-09-07）

- **过度筛选 = 商家眼里的「找不到」**：模型把「日系小清新」挑成 48 选 1 的色板还叠上疏密，返回 0 条。修法不是再调提示词，是**用代码去库里验一遍再逐条放宽**（能用代码解决就别用模型）。放宽了什么必须如实告诉商家。
- **枚举白名单必须有**：模型会编 `palette=不存在的色板` 这种值。凡是模型产出要落进查询/写库的，一律先按真实枚举过一遍，编的丢掉。

## 词表类改动的两条（2026-09-07 风格库扩容）

- **历史矩阵按下标取词表，扩容只能追加不能插队**：`STYLES_V4 = [STYLES[0], STYLES[2]]`，往 `STYLES` 中间插一条，已入库款的提示词就对不上了。做法是老表冻结、另开 `STYLES_ALL = STYLES + 新的`，并在自检里断言老三样仍在表头。
- **通用模板会跟具体风格打架**：FLO 模板锁死「至少 70% 留白」（商家判太密），但莫里斯藤蔓的招牌就是密不透风的缠枝，强按留白出来的不是那个风格。加了一个 `DENSE_STYLES` 集合走原模板。**凡是"给所有情况定一条硬规矩"的地方，扩品类/扩风格时都要回头看它会不会把新东西压死。**
