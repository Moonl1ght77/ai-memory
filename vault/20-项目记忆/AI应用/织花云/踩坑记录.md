- **换底色边缘感知不能按最近簇投影**（2026-09-17 家用机，合成图测试 + 四张仓库示例花型对比实测，`f16ca92`）：09-16 接手块写的「每像素投影到最近非底色簇」有两个洞。一是六簇 k-means 常把一个簇中心落在毛边混合色上（毛边像素多到自成一簇），投影到它 t≈1，毛边原样留下；二是浅粉这种「米底 + 红」混合色的真实图元，按颜色和边缘过渡像素分不开，会被当成边缘改掉。颜色本身分不出「边缘」和「浅色图元」，只有空间能分。做法：只处理底色掩膜边界 2 px 内的像素（`EDGE_RADIUS`），参考图元色取 4 px 内「非边界带、非底色」像素的均值（`REFERENCE_RADIUS`），簇中心只给细线兜底；混合公式用 (1−t)·新底色 + t·原像素 + t(1−t)·(图元参考色 − 旧底色)，最后一项把图元份额里藏的旧底色去掉 —— 接手块写的 (1−t)·新底 + t·原像素 在浅底换深底时中点仍留 25% 旧底、比图元还亮，过不了它自己定的测试 ③。t 之外剩下的明度差按 `replacePalette` 的 1.6 倍 tint / shade 规则当纹理。产品里 `replacePalette` 要迁这套时照此做，别照接手块原稿。

## 规避策略
- 开工三步：`git status --short` + 分支 + HEAD → 读任务模块与测试 → 记基线 commit 后在 `claude/<短任务名>` 分支改。
- 未提交文件要覆盖前先复制到 `data/backups/<任务>/`（被 git 忽略）。
- 交付前 `git diff --check` + 相关测试 + `npm run build`；没跑的写 `not-run`，不写通过。
- **作品库分页 + bootstrap 100 条并存时，新作品会把第 100 张「挤丢」**（2026-09-18 评审代理抓到，我第一版就有）：前端把 bootstrap 的 100 条和翻页拿到的 `older` 合并显示，上传 / 工具生成新作品后 `refresh()` 重拉 bootstrap，原第 100 张既不在新 100 里也不在 `older` 里，游标又从 `older` 末尾起，它直到整页重载都看不见——正是 Joe 抱怨的「被消掉」换个形式重现。修法：记上一份 `patterns`，掉出去且比新一页最旧项更早、且不是本页删的，并进 `older`（比新页最旧项新的是别处删的，不复活）；游标取合并后 (createdAt, id) 最小项，不取数组末尾；恢复的作品只在「已到底或不早于已载入最旧项」才并入。教训：**分页 + 全局刷新并存，边界项归属要显式处理**，靠「追加」必丢。
- **每张作品卡片一次色板请求走 read 限流桶（240/分钟）**：改动前一页 100 张永远碰不到，分页后翻两页就 429，此后一分钟刷新 / 翻页 / 回收站全失败。每卡一次的读取（媒体、色板）都该进 media 桶（1200/分钟）；`app.mjs` 限流分桶按 `req.path` 判，路径不带 `/api` 前缀。
- **对象存储镜像标记必须绑定桶配置**（2026-09-18 评审抓到）：标记只按 key 落盘时，测试桶跑通再换正式桶，所有作品照样 302 到新桶里不存在的对象，整站图全断且 302 被缓存一天；服务端永远察觉不到（4xx 发生在浏览器和桶之间）。修法：标记目录按 `sha256(endpoint|bucket|prefix)` 分层，换配置自动视为未镜像；`--verify` 用 HEAD 找桶里丢的重传；前端桶链接失败退回本站路由重签。同类教训：**任何「本地记着远端有」的状态都要绑远端身份**。
- **签名 URL 进 SPA 就是长期持有**：列表带签名链接省一跳，但标签页开一天链接就过期，`<img>` 只会报错不会重签。要么前端有回退（本次做法），要么别把签名链接放进长期状态。
- **跨域下载别带 `credentials: 'include'`**：同源首跳默认就带 cookie；302 到桶后带凭据的 CORS 请求要求桶精确回显 Origin + Allow-Credentials，常见 `*` 规则直接失败，而探针脚本看 `*` 还以为通过。
- **子代理评审不给 Bash 就不挂**：第三轮两镜 + 12 反驳者 16 个代理 12 分钟全部返回，提示里写死「不要调用 Bash，只用 Read/Grep/Glob，先读 scratchpad 里导出的 diff 文件」。以后本机跑评审工作流都这么写。
- **ultracode 工作流的子代理在家用机跑 Bash 会随机挂死**（2026-09-18，两轮评审各有代理卡在一条本该秒回的 `cat`/`grep` 上 20 分钟不动，最后一条记录都是 tool_use 没有 tool_result）：主线程 Bash 正常。用法上把评审拆短（每镜只读 diff + 少量文件、命令 30 秒内返回），拿到已完成镜的结果就 `TaskStop`，别等全部；关键核实自己在主线程做。原因未查（怀疑子代理里的 Bash 权限 / hook 交互），NEEDS_CONFIRMATION。
- **本仓库工作区是 CRLF，Git Bash 的 `sed -i` 会把整个文件改成 LF**（2026-09-21 公司机实测，`core.autocrlf=true`，检出后 `src/*.jsx` `src/*.css` 全是 CRLF）：改完 `git diff --check` 报「LF will be replaced by CRLF」、`file` 不再显示 CRLF。提交内容不受影响（autocrlf 入库时统一），但工作区和检出态不一致。做法：文本改动用 node 脚本（读时 split CRLF、写回 join CRLF），或改完用 node 把 `\r?\n` 统一回 `\r\n`；本机没有 Python（`python` 是商店占位，退出码 49）。**09-23 家用机又中一次**：`sed -i` 只改 `tests/garment-prompts.test.mjs` 一处，整份 221 行变 LF，Git 报「LF will be replaced by CRLF」才发现，用 node 统一回 CRLF；同批 `JSON.stringify` 新建的 `scripts/briefs/*.json` 也是 LF，要一起转。另：Claude Code 的 Bash 工具会把命令里的 `\\` 收成 `\`（连 `<<'EOF'` 引号 heredoc 里也一样，`\"` 和 `\n` 不动，2026-09-21 实测），heredoc 写 node 脚本时反斜杠序列用 `String.fromCharCode(92)` 拼，别直接写。
- **仓库的 `@playwright/test` 1.63 要 `chromium_headless_shell-1243`，本机只装了 1228 / 1234**（2026-09-21 公司机）：`chromium.launch()` 直接报 Executable doesn't exist。不必 `npx playwright install`（下载几百 MB），`chromium.launch({ channel: "msedge" })` 用系统 Edge 就能跑，1920 宽截图 + 断点循环 + aria / 焦点检查一个脚本搞定（放 scratchpad，不进仓库）。脚本要从项目根解析包：`createRequire(process.cwd() + "/package.json")("@playwright/test")`，直接 `import` 在 TEMP 目录找不到 node_modules。
- **桌面版内置浏览器看不清 1920 宽的页面**（2026-09-21）：面板只有约 800 px 宽，`resize_window` 到 1920 后截图缩到 0.42 倍、文字糊成一团，`zoom` 报「region crop not yet supported」。要看桌面宽度的视觉效果用上条的 Playwright 截图，内置浏览器只用来给 Joe 现场点着看和跑 `javascript_tool` 量尺寸（`getComputedStyle(...).gridTemplateColumns` 这类）。
