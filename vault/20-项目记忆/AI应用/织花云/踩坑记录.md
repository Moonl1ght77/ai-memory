- **换底色边缘感知不能按最近簇投影**（2026-09-17 家用机，合成图测试 + 四张仓库示例花型对比实测，`f16ca92`）：09-16 接手块写的「每像素投影到最近非底色簇」有两个洞。一是六簇 k-means 常把一个簇中心落在毛边混合色上（毛边像素多到自成一簇），投影到它 t≈1，毛边原样留下；二是浅粉这种「米底 + 红」混合色的真实图元，按颜色和边缘过渡像素分不开，会被当成边缘改掉。颜色本身分不出「边缘」和「浅色图元」，只有空间能分。做法：只处理底色掩膜边界 2 px 内的像素（`EDGE_RADIUS`），参考图元色取 4 px 内「非边界带、非底色」像素的均值（`REFERENCE_RADIUS`），簇中心只给细线兜底；混合公式用 (1−t)·新底色 + t·原像素 + t(1−t)·(图元参考色 − 旧底色)，最后一项把图元份额里藏的旧底色去掉 —— 接手块写的 (1−t)·新底 + t·原像素 在浅底换深底时中点仍留 25% 旧底、比图元还亮，过不了它自己定的测试 ③。t 之外剩下的明度差按 `replacePalette` 的 1.6 倍 tint / shade 规则当纹理。产品里 `replacePalette` 要迁这套时照此做，别照接手块原稿。
- **边缘处理会放大底色误判的小斑点**（2026-09-17 家用机 tropical-herbarium 实测，放大 3 倍）：浅色叶子里的高光和排线颜色接近底色，被判成底色 —— 旧算法只把它们涂成藏青小点（已知限制），加了边缘带后小点周围 2 px 也按边缘混色，撑成 2–4 px 的藏青楔块和涂抹，比旧的更难看。做法：4 连通底色块小于 64 px（`MIN_GROUND_AREA`）不算底色，归最近图元簇、保持原样、不生边缘带；真正的毛边紧挨大块底色，不受影响。代价：≤ 2 px 宽的独立底色细缝也不换色（示例花型里没见到）。没解决的：大片浅色图元整片被判成底色（tropical-herbarium 中右大叶、orchid-ink 灰洗染）仍会整片换成块状，属「图元与底色同色」的老限制，水墨 / 渐变本来就不在目标里。

- **Windows Git Bash 里用 sed / heredoc 写多行代码会出两种怪事**（2026-09-17 上午实测）：① 带中文或 `→` 的 `cat <<'EOF'` 直接报 `unexpected EOF while looking for matching`，文件没动；② sed 替换串里写 `\r` 只得到一个 CR 不换行，两行被粘成一行（`cat -A` 看不到 `^M`，`file` 却报 CRLF/LF 混合）。做法：多行代码用 Write 写到临时文件再 `cat >>` 追加或 `sed 'Nr 文件'` 插入；行内替换只用 `\n`；改完对每个文件跑 `sed -i 's/\r$//; s/$/\r/'` 统一成 CRLF（仓库 autocrlf=true，索引是 LF，工作区 CRLF），再 `git diff --check`。
- **发布脚本的参数是包名不带 `.tgz`，传错会静默退出、日志空白**（2026-09-17 上午家用机实测）：`publish-release.sh` 第 9 行用正则 `^zhihuayun-[0-9]{8}t[0-9]{6}$` 校验参数，不匹配直接 `exit 2`，不打一个字；我传了 `zhihuayun-20260917t021528.tgz`，轮询两分钟日志一直空、current 不变、脚本进程不在。规避：启动后 3 秒就看日志有没有 docker build 输出，空的先 `ps aux | grep publish-release` 和检查参数，别干等；正确写法记在当前进度「家用机接手」的发布流程里。这次退出在任何改动之前（锁已释放、未建快照），直接重跑即可。

- **NewAPI 站 `/models` 有名字 ≠ 有通道**（2026-09-17 家用机实测）：`gpt-image-2` 列在名单里，调用回 503 `No available channel for model gpt-image-2 under group 🌏️ OpenAI 官转`，`code: model_not_found`。良率脚本的名单检查只挡「没名字」，挡不住「有名无通道」。规避：新模型先用 1 次最便宜的真实调用探路（失败不计费），别按名单排一整批；开通道找供应商（许锦泽）。
- **`createProvider` 不传 `imageModel` 就生成不了**（2026-09-17，两个临时脚本各踩一次）：`provider.generate` 校验 `selectedModel === config.imageModel`，不一致抛「未配置此图像模型」`unsupported_image_model`，且在发请求之前，所以不花钱但一批全空跑。规避：临时脚本按目标模型给 `imageModel`；产品脚本 `validate-*-live.mjs` 都已传。
- **天亿马 `/images/edits` 无视 `mask`，错位重绘接缝是假修**（2026-09-17 晚，Joe 从 2×2 TIFF 看出；4 次探针带 / 不带 mask、sunburst / flare 都整图重画，mask 外像素改动 48–65/255）：整图重画后外边天然连续、原来的硬切边跑到图心，`seamMetrics` 只量外边就打高分。规矩：判接缝一律同时量原图和错位半格版（取小值），并看 4×4 平铺；代理看图也要看四分之一线不只看中心十字；别信「修好」的分数。
- **`bypassPermissions` 写在项目 `.claude/settings.json` 不生效**（2026-09-17 官方文档 code.claude.com/docs/en/permission-modes「Which mode a session starts in」原文：`auto` 与 `bypassPermissions` 在 `.claude/settings.json` / `.claude/settings.local.json` 里 doesn't take effect，终端会话退到 Manual，桌面端回内置默认 Auto）：Joe 09-17 上午改了项目级那行，新会话照样 Auto。规避：只能写用户级 `~/.claude/settings.json` 的 `permissions.defaultMode`；桌面端选择器选的模式按文件夹记忆且优先于 defaultMode；首次以 bypass 启动弹一次风险确认；deny 规则在 bypass 下照拦。
- **gpt-image 出的四方连续图在画框边硬切图元，不会跨边延续**（2026-09-17 78 张多样题材代理逐张看，41 张接缝明显）：大图元、有方向的排布（斜条 / 人字 / 横条 / 大螺旋 / 浪头）几乎必断，纹理型（豹纹 / 迷彩 / 大理石）和小碎点稳，同一配方两轮会翻转。规避：生成后跑一次错位重绘（`validate-seam-inpaint-live.mjs` 那套，¥0.43），`seamMetrics` < 94 的才修；严格网格别用重绘（分数高但带内变形），走周期检测。产品现有 `repairSeams` 边缘融合修不了这种。
- **客户端超时不等于不扣钱**（2026-09-17 两次实测）：provider 120 s `AbortSignal` 超时后，r6 geometric-linocut 那次没扣（47 × 38.16 分毫不差），dh-r5 playful-illustration 那次扣了（26 × 38.16）。上游做完就结算，客户端断开不退。规避：超时后别当免费重试；盈利模型里超时按「可能付费」算；同步方言想省钱只能把超时放宽，不能靠断开。
- **差值法计费要串行 + 等 60 s**（2026-09-17）：NewAPI `total_usage` 异步结算，队列刚结束就读会少 1–2 分并算进下一段；并行时段只能得阶段合计，单价探针必须单独串行跑。按次定价核对法：8 张 high 差值 305.30 分 = 8 × 38.16，对上就是按次；503 失败不扣。
- **gpt-image 出 grid 排布的几何花型不接缝**（2026-09-17，40 张高画质 + 48 张工作室档全部复现，接缝分 77–91，其余风格 94–99）：模型不会让网格周期整除画布，2×2 平铺中线整行图元被切；产品 `repairSeams` 是边缘融合，对错位网格只会糊出一条带，不是修法。排布对照 n=3：grid 86.7 / brick 91.3 / half_drop 92.7 / tossed 95.7。规避：gpt-image 路径的 geometric 配方别用 grid，或做周期检测裁切；MJ 的 `--tile` 是另一条路，没在这轮测。
- **机器初判的「边界」带太宽，不能直接当良率报**（2026-09-17）：`VERDICT.near` seam ±1.5、误差 ±1 让 240 张高画质里 73 张落进「边界」，代理逐张看 144 张，vintage 23 张全可售、描摹 0 张 broken，机器却判 0% 可用。规避：报两个界（边界算可用 / 算不可用），阈值等 Joe 盲判 30 张后定；机器量的是「能否描成矢量」，不叫「可交付」。
- **模型给的色板常超 6 色，`validatePrintAnalysis` 直接拒**（2026-09-17，36 次里 3 次，三个模型都出过）：提示词只写了 `colors:["#RRGGBB"]` 没写上限，验证器要求 1–6。规避：`GARMENT_VISION_SYSTEM` 加「最多 6 色」；线上遇到这错先想到这个，不是模型坏。
- **Git Bash 里 `cat > 文件` 后面没接 heredoc 会挂在 stdin**（2026-09-17，白等 120 s）：命令被工具移到后台也不会结束。规避：写多行文件用 Write 工具；shell 里只用 `cat <<'EOF' > 文件`。
- **散点花型「不贴边」写进提示词，gpt-image 不听**（2026-09-17 晚，16 题材 × 2 轮 32 张 ¥12）：边框 4 px 带非底色像素 24.9% → 19.5%，0 张 ≤ 2%；模型的反应是把图元画小画密，边上照样切。接缝要靠本地后处理，不靠提示词。用例 `scripts/briefs/scattered-margin.json`。
- **补种算法第一版把图元拆成零件、缝带塞满小件**（2026-09-17 深夜 v1 → v10 十版）：① 4 px 分组半径把相邻图元连成一团（擦除占 99%），要先洞填充再小半径膨胀；② 从边带找空位塞任何能放下的图元，结果全是最小件排成一列，要按被擦图元的大小 + 颜色签名挑候选、原位替换；③ 只查同一源图元的间距不查同款另一源，顶带底带各塞一个太阳环绕后叠在一起（v10 仍是主要 patched 原因）；④ 硬颜色阈值擦软边淡彩留鬼影（蜡笔 / 铅笔 / 写实 / 工笔）；⑤ 大主图元擦后无等价替换只剩小件（仙鹤 / 吉他）。评判只能靠代理逐对看 2×2 平铺，seamMetrics 分对这些一律 97+ 看不出。
- **1024 px 花型 300 dpi 只有 8.7 cm 花回**（2026-09-18 调研，`PRINT_END_USE_GUIDE.md`）：够衬衫小花 / 童装 / 内衣 / 拼底，连衣裙 / 床品 / 窗帘 30–64 cm 花回要 2048–2880 出图或平铺策略；别拿 1024 原图直接报「可印大花回」。

## 风险
- `deploy/cutover.sh`、`backup-legacy.sh`、`rollback-legacy.sh` 是 2026-09 首次替换旧 JoeAI 入口的脚本，引用旧站容器；拿它们升级当前版本会出事。日常只用 `publish-release.sh` / `rollback-release.sh`。
- `npm start` 会加载 `.env`；本机没有 `.env` 时先从 `.env.example` 复制，别把生产 key 拷进来调试。
- 服务启动接管（`a9f7edc`，09-15 已上线 release `zhihuayun-20260915t075527`）只续查带任务 ID 的 MJ 任务；gpt-image 遗留任务仍标失败退分且远端不取消。已有 provider task ID 先查状态再决定，别因客户端超时重发付费生成（`ARCHITECTURE.md`）。

## 规避策略
- 开工三步：`git status --short` + 分支 + HEAD → 读任务模块与测试 → 记基线 commit 后在 `claude/<短任务名>` 分支改。
- 未提交文件要覆盖前先复制到 `data/backups/<任务>/`（被 git 忽略）。
- 交付前 `git diff --check` + 相关测试 + `npm run build`；没跑的写 `not-run`，不写通过。
