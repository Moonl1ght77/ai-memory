## 架构地图（2026-09-14 只读体检，HEAD `d9c417e`；可分享报告页链接见当前进度）
- 拓扑：浏览器 SPA → Nginx :80（Host 固定服务器 IP，无 TLS）→ 单个 Node 进程 `127.0.0.1:4320` → SQLite WAL（`node:sqlite` 同步调用，`BEGIN IMMEDIATE`）+ `data/media` `data/exports/<id>` `data/icc`。外连 APIMart：MJ 每 4 s 轮询上限 12 分钟，gpt-image 每 3 s 上限 8 分钟，结果图只从白名单域名 HTTPS 下载且 DNS 不得解析到内网。无队列、无多副本，限流是进程内 Map。
- 服务端分层：HTTP 38 条路由 = `app.mjs` 24 + `auth` 3 + `garment-service` 6 + `export-service` 5。插件签名 `install*(app, store, requireUser[, requireAdmin], config)`，auth / garment / export 三个现成样板，**新功能照此落点**。编排全在内存：生成 = 进程内 Promise 集合；导出 = 串行队列 + Worker 线程（180 s / 768 MB 堆）；描摹 = Worker ≤2 并发（45 s）。领域层纯函数：`prompts` / `mj-prompts` / `garment-prompts` 编译，`image-tools` / `advanced-tools` / `recolor` / `seam-*` 图像，`print-*` / `spot-*` / `vector-*` 编码，`learning` 状态机。`catalog.mjs` 是全员共享的叶子模块（plans / styles / `generationCreditCost` / `apiError` / 视图函数）。导出流水线是分层最干净的子系统。
- 数据：15 张表，DDL 分散在 4 个文件（store 11、garment 2、export 1、icc 1），无迁移版本表，唯一一次列变更（`unlimited_generation`）靠 `PRAGMA table_info` 探测。`store.db` 直接暴露，store 之外 41 处直写 SQL（garment 12 / export 11 / app 7 / icc 6 / auth 5），归属校验 `user_id=?` 散落在各处 SQL 里。
- 账本流（MJ 一次生成）：`POST /api/generate` → `reserveJob`（同账户 ≥2 进行中拒 429，余额 <10 拒 402，扣分 + `ledger reserve:<job>`，幂等键按账户唯一）→ provider 拿 `task_id` 立即写回 `params.providerTaskId` → 结果必须 1–4 张互异单图（四宫格不算）→ `completeJobCandidates` 一个事务写 N 条 patterns + `pattern_group_members(group_id=job.id, index 1..N)` → 失败 `failJob` 退分一次（`ledger refund:<job>` 唯一键防二次退）。**重启：进行中任务全部判失败退分，远端任务不取消不恢复。**
