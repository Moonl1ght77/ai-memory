# TVC首页视频 · 踩坑记录

## 已确认问题

### Codex 额度消耗过快
- 问题：每轮对话都消耗额度，图片审查消耗大量 token
- 原因：全程使用 Codex，没有分工
- 规避：用 Scream Code 处理重复性工作（提示词生成、审查），只在关键步骤用 Codex

### 素材图质量不稳定
- 问题：AI 生图「抽卡」性质，需要多次尝试
- 原因：提示词不够精确，模型随机性
- 规避：批量生成 → 批量审查 → 只重做需要改的

### 工作流中转太多
- 问题：AI 给提示词 → 网页生图 → 发回 AI → 循环
- 原因：没有自动化生图
- 规避：批量处理模式，一次生成多个提示词，一次审查多张图

## 云皱棉 Hero Frame 概念视频踩坑（2026-06-19 验证，2026-07-07 从"工作室整理总控"归位至此）

失败方案：
- 初始设计过于简单（单纯草坪）
- 色彩质感太数码感，不符合胶片风格要求
- 静帧误展示了漂浮状态（应为视频起始状态）
- 构图问题：草坪出屏幕、人物没有被完全托住
- 视频提示词写成分段而不是一镜到底
- 用了英文提示词（应为中文）
- 动态不足（草没有风吹效果）
- 人物漂浮时立起来（应保持躺姿）
- 人物 AI 感过重

验证有效：
- 参考图引用机制（面料参考图 + 人脸参考图）
- 调整草坪尺寸和位置参数
- 增强全元素动态描述
- 添加真实感描述和负面提示词
- 使用中文提示词格式

## 风险
- 素材图版权问题（AI 生成图的商用授权）
- 视频风格与小程序整体风格不匹配
- 过度追求完美导致项目拖延

## 验证过的经验
- 批量处理比逐个处理效率高 3-5 倍
- Scream Code 适合处理重复性工作
- 素材图先筛选再精修，不要每张都重做
