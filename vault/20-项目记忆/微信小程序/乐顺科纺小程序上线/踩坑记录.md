## 2026-08-03 线上图片全白 + 开发者工具崩（两件独立事故，同日爆发）

### 事故一【根因：腾讯云账户欠费 0.04 元】
**现象**：线上正式版 + 开发者工具里，面料图全白；文字、分类数量、视频**全正常**。
**排查中被排除的**：云开发套餐没到期（交到 2027-06-05）；月配额全没超（容量 877MB/3GB、调用 1万/20万次、CDN 流量 3GB/10GB）；云存储文件都在。
**根因**：腾讯云账户可用余额 **-0.04 元**。图片 URL 尾巴上的 `imageMogr2` 实时缩图属于**数据万象**，是腾讯云**按量计费**产品，从账户余额扣钱；云开发 ¥19.9/月 套餐是**预付费**，两套计费**互不相通**。余额一变负数，数据万象立刻停服 → 所有带 `imageMogr2` 参数的请求挂掉；而视频走原始地址不带该参数，普通文件下载不受影响 → 视频照常播。
**定位诀窍（下次直接用）**：**「文字正常 + 视频能播 + 图片全白」= 查腾讯云账户余额，不是查云开发配额。** 图片和视频走同一存储同一 CDN，唯一差别就是 `appendImageProcess` 拼的那串参数（`domain/media-rules.js:64`）。
**验证法（不依赖开发者工具）**：云开发控制台→存储→复制任一图片下载地址，浏览器开两次，一次原地址、一次尾巴加 `?imageMogr2/thumbnail/720x/format/jpg/interlace/1/quality/82`；原地址能开、加参数报错 = 实锤。
**修复**：商家充值即恢复，**不用改代码、不用发版**，解冻延迟约 5-15 分钟。
**长期风险**：`imageMogr2` 每次图片加载都在按量扣商家的钱，是**持续运营成本**，余额见底就会重演。已建议商家充 200 + 开自动充值 + 设余额预警。

### 事故二【根因：开发者工具 2026-08-02 升级后启用了 summer-compiler】
**现象**：模拟器启动失败 `[summer-compiler] Couldn't found the '/components/loading-mask/loading-mask.json' file relative to 'pages/splash/splash'`；云开发面板也打不开（连带症状，面板挂在模拟器上下文里）。
**排查中被排除的**：组件 4 个文件磁盘上全在；`app.json:60` 引用路径正确；`miniprogramRoot` 配置正常；工作区干净无未提交改动。
**根因**：`project.config.json` 里早就存在的 `"useCompilerModule": true`，**旧版工具忽略该字段，升级后的新版认了**，切到新一代编译器 summer-compiler，而它解析不了 `app.json` 全局 `usingComponents` 里 `/components/...` 这种**绝对路径**写法。
**判定编译是否真的成功过（有用）**：看 `%LOCALAPPDATA%\微信开发者工具\User Data\<hash>\` 下的 `Weappdest`、`WeappMiniCode`、`WeappPureSimulatorCache` —— **空目录 = 编译从没成功过**（不是缓存脏，别浪费时间清缓存）。另：工具升级会**新建一个 hash 目录**，目录创建时间可反查升级时间点。
**修复（`2a8ecec`）**：`useCompilerModule` 改 `false` 退回旧编译器，`project.config.json` 和 `project.private.config.json` 两处都写（前者进 Git，后者防工具覆写）。**必须完全退出工具重启才生效**，点「重新编译」无效。不动一行业务代码。
**2026-08-13 复发（`26bc8e6` 治根）**：同样报错再现，但排查发现两处配置仍是 `false`、工作区干净、User Data 未新建 hash 目录——**工具原地小更新后不再认 `useCompilerModule` 开关，强制 summer-compiler**，开关式修复失效。治根改法=把 `usingComponents` 里全部 8 处 `/components/...` 绝对路径改相对路径：`app.json` 全局 2 处改 `./components/...`，6 个页面 json 的 nav-bar 改 `../../components/...`。相对路径新旧编译器都认，向后兼容，77 单测全绿。**教训：微信在逐步废弃旧编译器，任何靠"退回旧编译器"的修复都是缓兵计，代码写法必须兼容 summer-compiler。**

## 规避策略
- 先只读检查。
- 先确认上线主线。
- 高风险动作前先备份或建立 Git 基线。
- 客户资产单独整理，不和源码仓库混放。
- 每次开工先同步记忆仓库，再同步小程序仓库；遇到未提交修改时先查明来源，不自动覆盖、合并或清理。
- 图片故障要同时追踪“数据库字段 → 页面视图模型 → WXML src → 后台写回”四段；读侧兼容修好后还要验证写侧不会再次破坏旧数据。
- 对历史色卡用完整对象深比较回归测试，不能只断言图片数量或 URL，否则色号、色名和色值被改写也会假通过。
