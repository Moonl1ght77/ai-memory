## 技术栈
- 一期全用 GitHub 免费功能：组织 + 仓库 + Projects 看板 + 官方 GitHub MCP，费用 0（按 2026-11-18 查到的官方文档）。
- 仓库划分：`core`（核心仓，只有 Joe 和老板）、每个员工一个 `task-eN`（任务卡 + 交付）、`task-e2` 先当测试用假仓。

- 宣发执行层候选：xAI Grok Bot（带云电脑的 agent，可多 Bot 协作、主 Bot 汇总，支持定时任务、MCP、API；docs.x.ai 2026-11-18 读过）。是否就用它，待 Joe 确认。

## 长期原则
- 权限墙靠 GitHub 账号权限，不靠提示词；员工账号和令牌看不到核心区。
- 信息分三级：核心（记忆库及其 git 历史、Joe 全局规则和方法论、询价订单客户、监事结论与金丝雀答案、预算报价、复盘、发布账号）原件摘要都不出；内部（检测报告、货号表原件、传播简报、选题表等）原件不出，总控可摘片段写进卡；员工可见的才能进任务卡。
- 岗位分派规则：输入只要有一项是核心、又摘不出员工可见版，这个岗就不分派。11 岗里 7 个留核心（R01 总控、R02 档案、R04 传播策划、R08 质检终审、R09 发布互动、R10 效果分析、R11 监事），4 个可分派（R03 线上研究、R05 单条文案、R06 图库、R07 制作；图库和制作给同一人）。
- 员工之间不直接传东西：成果先进 core，再由总控作为下一张卡的附件发出。员工写的一切都当不可信输入：交稿过三道关（脚本查路径 / 文件类型 / 密钥 → 隔离会话里 AI 辅审，读不到核心 → 人看差异），评论和标签由人在网页上看，不交给有核心权限的 AI 读。
- R11 监事独立：每轮指定一人当监事，R03 简报由另一人保管，监事盲审写完再给。
- 宣发硬约束（V4）：R09 一律 Bot 起草、人工发布（据媒体报道小红书封禁 AI 托管代发账号，二手来源）；AI 生成文本和图片发布时要主动声明（《人工智能生成合成内容标识办法》第 3、10 条，原文已读）；自有账号推销自家产品按商业广告审，功能宣称要有可验证依据（推论）。
