### 2026-08-06 家用机对齐时踩实的三条

- **`npx skills add` 装不上时，报错里会列出仓库现有的全部技能**，`No matching skills found for: X` 后面跟着完整清单。这是判断「技能改名了」还是「名字打错了」的唯一线索。**用 `tail` 看输出会把它切掉**，要用 `head` 或看全量。`writing-great-skills` 就是这样查出已被改名成 `writing-for-agents` 的。
- **winget 碰到注册表里的旧条目，会把包修回原来那个路径，不是装到标准位置**。家用机 Python 因此被补回 `%APPDATA%\Accio\pre-install\<哈希>\python\`。好处是 `py` 立刻恢复正常，坏处是 Python 继续寄生在别的软件目录下。**不要以为 winget 装完就在 `%LOCALAPPDATA%\Programs\Python`，装完要实际去找。**
- **删一批技能前，先看它的数据目录存不存在**——`~\.dbs` 不存在就能证明 28 个 dbs 从没产生过任何诊断数据，删除决定有事实依据，不靠印象。这个办法对任何「装了但不确定用没用过」的工具都适用。

### 2026-08-09 云端 Routines 首次打通踩实的三条

- **GitHub「授权」≠「安装」，克劳德 App 可能只走完一半**。claude.ai 的 onboarding 流程走完后，克劳德可能只出现在 GitHub「已授权的 GitHub 应用」标签（只给身份，不给仓库），routine 照样克隆不了仓库。必须确认「**已安装的** GitHub 应用」标签里有克劳德且勾了目标仓库。修复入口：https://github.com/apps/claude/installations/new （私有仓库不是原因，App 机制本来就支持私有库）。
- **云端 routine 沙箱只有 WebSearch 能联网**（2026-08-09 实测）：WebFetch 报 `EGRESS_BLOCKED`，Bash curl 报 `curl: (56) CONNECT tunnel failed, response 403`。写 routine 提示词时明说「只用 WebSearch，别试 WebFetch/curl」，省得云端 agent 白撞墙。
- **Routine 的几条硬规则**：cron 最短间隔 1 小时且用 UTC（北京时间减 8）；`run_once_at` 跑完自动失效；执行时间有几分钟随机抖动（定 22:00 实跑 22:03）；**API 删不了 routine**，只能去 https://claude.ai/code/routines 网页删；云端跑在隔离沙箱，碰不到本地电脑任何东西。

### 2026-09-06 Claude Code 新版 Ultracode 档位烧 token 踩实的五条

（起因：一次 InWELL 视频排查自动开了 26 个 agent、烧掉 2.6M token，Joe 没主动要过多 agent。证据全部出自本机 `~\.claude\cache\changelog.md`，装的是 2.1.207）

- **`/effort` 档位顺序是 low → medium → high → xhigh → max → ultracode**，changelog 原话 `Added xhigh effort level for Opus 4.7, sitting between high and max`。**`max` 才是最高的「纯思考」档，`xhigh` 只是倒数第三**。想要最强推理又不要多 agent，选 **Max**，别选 Ultracode。
- **Ultracode 不是「更聪明」，是「max 级推理 + 强制每个实质任务开 Workflow 多 agent」**。它底下跑的推理强度就是 xhigh/max（changelog：`ultracode is no longer offered on models that do not support it`），多出来的只有编排层。开着它，AI 会按系统指令对每个非闲聊任务自动 fan out 几十个 agent。
- **2.1.160 起，prompt 里出现「ultracode」这个词本身就会当场触发多 agent**，跟档位无关。原话 `Renamed the dynamic-workflow trigger keyword from workflow to ultracode`——旧触发词 `workflow` 已失效，新词是 `ultracode`，在输入框里会**紫色高亮**。看到高亮按 `alt+w` 或紧接着按退格可撤销这次触发。讨论这个功能时提到这个词，会把它本身触发一次。
- **两个吞掉刹车的设置**：`~\.claude\settings.json` 里 `"skipWorkflowUsageWarning": true` 会让 workflow 启动前不再弹用量确认框；`/config` 里的 "Workflow keyword trigger" 才是关键词触发的总开关（**桌面版 Code 标签页开不了 `/config` 面板，要在终端跑 `claude` 才有**）。另外用滑块改档位默认**只对本会话生效**，`settings.json` 的 `effortLevel` 不会自动跟着变，要新会话也生效得单独确认持久化或直接改这行。
- **后台任务按会话隔离，跨会话停不了**：在 A 会话里对 B 会话跑着的 workflow 调 `TaskStop` 返回 `No task found with ID`。必须回到发起它的那个窗口，在 Background tasks 面板点那一行的 ⊡ 按钮。已跑完的 agent 结果会保留，不算白烧。

## 风险
- **Codex 配置、全局规则、第三方切换工具需分开核验（2026-10-07 家用机）**：配置存在不代表 AGENTS.md 非空；Codexx Network 的本地代理端口与旧配置地址一致，工具备份中的 AGENTS.md 曾为 0 字节，不能仅凭备份断言谁清空了它。回到官方线路时，要同时核对服务商与接口覆盖，并保留原配置备份；实际 app-server 的严格配置检查及 config/read、account/read 用于验证线路与登录类型，debug prompt-input 用于验证规则是否进入提示词。工作规则母版必须真实存在，本机完整规则需与母版核对；第三方工具连接独立于模型服务商，来源未确认时单独报告。
- 直接删除旧目录会影响旧线程查证和路径兼容。
- 直接清理小程序总工作区可能误删有效源码、客户资产或笔记。
- 多个 AI 工具会持续生成 `.claude`、`.agents`、`.windsurf`、`.vscode` 等目录，需要边界规则。
