### 2026-08-06 家用机对齐时踩实的三条

- **`npx skills add` 装不上时，报错里会列出仓库现有的全部技能**，`No matching skills found for: X` 后面跟着完整清单。这是判断「技能改名了」还是「名字打错了」的唯一线索。**用 `tail` 看输出会把它切掉**，要用 `head` 或看全量。`writing-great-skills` 就是这样查出已被改名成 `writing-for-agents` 的。
- **winget 碰到注册表里的旧条目，会把包修回原来那个路径，不是装到标准位置**。家用机 Python 因此被补回 `%APPDATA%\Accio\pre-install\<哈希>\python\`。好处是 `py` 立刻恢复正常，坏处是 Python 继续寄生在别的软件目录下。**不要以为 winget 装完就在 `%LOCALAPPDATA%\Programs\Python`，装完要实际去找。**
- **删一批技能前，先看它的数据目录存不存在**——`~\.dbs` 不存在就能证明 28 个 dbs 从没产生过任何诊断数据，删除决定有事实依据，不靠印象。这个办法对任何「装了但不确定用没用过」的工具都适用。

### 2026-08-09 云端 Routines 首次打通踩实的三条

- **GitHub「授权」≠「安装」，克劳德 App 可能只走完一半**。claude.ai 的 onboarding 流程走完后，克劳德可能只出现在 GitHub「已授权的 GitHub 应用」标签（只给身份，不给仓库），routine 照样克隆不了仓库。必须确认「**已安装的** GitHub 应用」标签里有克劳德且勾了目标仓库。修复入口：https://github.com/apps/claude/installations/new （私有仓库不是原因，App 机制本来就支持私有库）。
- **云端 routine 沙箱只有 WebSearch 能联网**（2026-08-09 实测）：WebFetch 报 `EGRESS_BLOCKED`，Bash curl 报 `curl: (56) CONNECT tunnel failed, response 403`。写 routine 提示词时明说「只用 WebSearch，别试 WebFetch/curl」，省得云端 agent 白撞墙。
- **Routine 的几条硬规则**：cron 最短间隔 1 小时且用 UTC（北京时间减 8）；`run_once_at` 跑完自动失效；执行时间有几分钟随机抖动（定 22:00 实跑 22:03）；**API 删不了 routine**，只能去 https://claude.ai/code/routines 网页删；云端跑在隔离沙箱，碰不到本地电脑任何东西。

## 风险
- 直接删除旧目录会影响旧线程查证和路径兼容。
- 直接清理小程序总工作区可能误删有效源码、客户资产或笔记。
- 多个 AI 工具会持续生成 `.claude`、`.agents`、`.windsurf`、`.vscode` 等目录，需要边界规则。

## 规避策略
- 只读盘点优先。
- 正式项目放进 `E:\Projects`。
- 记忆和索引放进 `E:\AI-Memory\vault`。
- 删除动作放最后，且只删确认可重建的缓存。
