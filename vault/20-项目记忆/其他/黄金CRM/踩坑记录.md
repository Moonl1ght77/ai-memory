# 黄金CRM · 踩坑记录

## 已确认问题
2026-10-09 公司机收工核验：Project Graph 的 `.prg` 是 ZIP 文件，保存后 Git 的二进制差异不一定代表业务内容变化。两份 v0.3 本轮只有 thumbnail.png 改变，其余条目逐项一致；比较时分开核对缩略图、正文与连接数据。交付 ZIP 需同时核对各条目的当前内容；跨 Windows 检出还会遇到 Markdown 的 LF／CRLF 差异，判断文字改动先规范换行，不能因此误认业务说明已改。

2026-10-09：Project Graph 4.2.4 的画布注释绘制在节点下方，不参与节点碰撞框，也不会自动推开其它节点。初版业务图把详情同时放在叶标题注释与独立正文里，正文自重复注释也存在；仅检查正文框无重叠不能证明展开注释可读。修复前检查复现 144 处注释与正文重叠。

## 失败方案
只验证正文碰撞框、忽略展开注释区域的验收方法漏掉了此问题；不能沿用为完整可读性证明。

## 风险
本机核实注释默认字号 18、最多 4 行、宽度设置 200；超出行数会截断。修改全局字体、注释长度或节点间距后，需重新检查展开区域；软件不会替图稿自动排开。

## 规避策略
完整业务说明保留在正文，画布注释只留简短补充核对要点；清理正文自重复注释，为保留注释预留空间。验收同时核对正文框、注释包络、行数限制及原生展开显示。当前 v0.3 已按 105 个注释区域进行此项检查，字体和行数条件见当前进度。
