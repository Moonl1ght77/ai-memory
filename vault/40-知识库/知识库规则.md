# 知识库规则（防水桶机制）

知识库和项目记忆是两回事：
- **项目记忆**（20-项目记忆）：单个项目的状态和踩坑，允许琐碎，因为它只服务那个项目。
- **类目知识库**（40-知识库）：跨项目复用的打法，必须极度克制。

## 晋升制：知识不是"写进来"的，是"晋升进来"的

一条经验要进知识库，必须同时满足四条（比三问更严）：

1. **真实验证过**：在至少一个真实项目里用过并成功，不是理论、不是猜测。
2. **第二次被用到**：在第二个项目或第二个客户单里再次用上它，才有资格晋升。第一次成功只留在项目踩坑记录里。
3. **写成"做法"而不是"记录"**：格式是"什么场景 → 怎么做 → 为什么"，不是流水账。
4. **注明出处**：哪个项目、什么时间验证的。查不到出处的条目在体检时删除。

唯一例外：Joe 明确说"这条晋升到知识库"，可跳过第 2 条。

## 条目格式（每条不超过 10 行）

```markdown
### 【场景】一句话说清什么情况下用
- 做法：具体怎么做
- 原因：为什么这样做（可选）
- 验证：项目名 + 日期（至少两处，除非 Joe 特批）
```

## 修剪机制（每次"记忆体检"必做）

- 逐条检查类目知识库：出处失效的、被新做法取代的、一年没用过的 → 报给 Joe 确认后删除。
- 单个类目文件超过 50 条时，必须先合并同类项再新增。
- 删除不心疼：git 里都有历史，真要找回随时能找回。

## 和项目内知识库的分工

有的项目自己带知识库（如 `E:\元提示词agent\知识库` 存提示词规则）。分工原则：
- **工具怎么用、提示词怎么写** → 项目自己的知识库
- **跨项目的打法、流程、选择判断** → 这里的类目知识库
- 同一条知识只存一处，另一处只放指路链接。
