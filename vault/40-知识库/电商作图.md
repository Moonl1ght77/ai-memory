## 已晋升条目

### 【场景】LLM 节点一次收多张图做判断（质检/比对）
- 做法：禁止按输入顺序认图；两步内容认图——先按视觉特征分参考图/成品图，再按构图特征匹配方案；匹配缺失/重复本身就是失败项；提示词加"发现自己在按顺序编号立即作废重来"自检条款。
- 原因：并发生成导致喂图顺序随机，按序号认图会产生成批误报。
- 验证：agent全自动生图 V9.1，2026-07-08（Joe 特批晋升，待二验）

### 【场景】要求 N 张图同场景，但场景参考是弱锚（影棚素背景/无特征图）
- 做法：分析节点输出"场景类型 + 一句可逐字复用的场景描述句"，编译节点把这句话一字不差地写进全部 N 组提示词；风格条款按场景类型双模式切换（影棚净图风/真实直拍风），禁止写死单一模式。
- 原因：无特征背景锚不住场景，各组自由改写场景描述必然漂移；实锤：同一次运行 G1 画成真实房间、G5 画成影棚。
- 验证：agent全自动生图 V9.2 首跑诊断，2026-07-08（Joe 特批晋升，待二验）

### 【场景】多图跨图一致性条款起草（同人同衣同场景类工作流）
- 做法：枚举画面里所有可见部位逐一立一致性条款（含鞋、袜、发型这类"没人提供参考"的部位）；无参考的部位用"选定一个中性描述并在 N 组提示词里逐字重复"兜底。
- 原因：没写进条款的可见部位，模型每张自由发明；实锤：8张图鞋子款式各不相同。
- 验证：agent全自动生图 V9.2 首跑诊断，2026-07-08（Joe 特批晋升，待二验）

### 【场景】用户需求卡文字与输入参考图矛盾（如身材写"强壮"但模特图是瘦子头像）
- 做法：开工前做输入自洽检查：需求文字只能强化图片事实，不能对抗图片；身材锚必须是全身/半身带体型的模特图，头像三视图不合格；矛盾时停下让用户二选一（换图或改文字）。
- 原因：文字与图对抗时模型每张自己猜，N 张结果各画各的。
- 验证：agent全自动生图 V9.2 首跑诊断，2026-07-08（Joe 特批晋升，待二验）

### 【场景】蓝图（唯一真源）更新后发布到运行平台
- 做法：四步闭环缺一不可——①重建交付文件 ②核验脚本零漂移 ③发布到平台（content-only 热更新已有项目 / 结构变动新建项目）④回读平台数据再核验一次。用户编辑过的卡（需求卡）永不覆盖，改动建议以文字交给用户自己贴。
- 原因：画布与蓝图不同步 = 旧版本继续运行 = 版本串味；已修问题会"复活"。
- 验证：agent全自动生图 V9.2.1，2026-07-08（Joe 特批晋升，待二验）

### 【场景】修复一个出图质量问题（防止版本升级后回归）
- 做法：每个修复必须三点落地——①提示词/规则条款 ②QA 检查项+硬失败条款 ③运行前检查清单项；并登记进项目的"回归防线登记表"（问题→修复版本→三处护栏位置），升级改提示词前先对照登记表确认护栏未被挤掉。
- 原因：只改提示词的修复会在下次迭代中被无声覆盖，旧问题复活是商用致命伤。
- 验证：agent全自动生图 V9.2.1 回归防线机制，2026-07-08（Joe 特批晋升，待二验）
